# PANO Phase 1：正式应用架构与书库管理

- 项目：PANO（Page Annotation and Note Organizer）
- 仓库及可执行程序：`pano-reader`
- 阶段：Phase 1 — Application Foundation and Library Management
- 日期：2026-11-27
- 参考基线：Phase 0 / 0.1 Demo（此前核查的提交 `1dbeae5`，实施时以工作区实际状态为准）

## 1. 开发背景与目标

Phase 0 与 Phase 0.1 已初步验证 Qt PDF 页面渲染、自主阅读控件、页面 point 坐标、文字选取、图形及画笔标注、混合绘制、精准定位、撤销重做和独立 JSON 存储等技术路线。经用户实际使用，主要坐标、旋转、显示及定位问题已基本解决，Demo 技术验证阶段结束。高 DPI、复杂文字排版、PDF 固有旋转及大型文档性能仍属于后续常规验证事项，不再阻塞正式开发。

本阶段的重点是建立正式应用，而非继续扩展 Demo。完成后，用户应能够初始化或加载书库、导入和管理 PDF、组织多级书架、收藏及恢复删除的书籍、同时打开多本书进行阅读与标注，并在重启程序后恢复阅读成果。应用应具备稳定的数据契约、保存机制、独立的本机配置和可热切换的基础主题。

### 1.1 基本约束

- 使用 C++20、Qt 6 Widgets / Qt PDF、xmake，正式程序目标名 `pano-reader`，命名空间 `pano`，项目自有代码采用 MIT 许可证。优先保持 Windows 和 Linux 可构建，第三方依赖遵守各自许可。
- 本地优先，不要求账号、服务器、联网或自研同步服务。
- 原始 PDF 与阅读成果严格分离。映射的外部 PDF 和拷贝进书库的 PDF 均为只读文档；正常阅读、标注和保存不得修改它们。
- 数据采用 UTF-8 JSON、Markdown 字符串及独立图片资源；使用稳定 ID，不以显示名称、数组索引、书架路径或本机绝对路径作为对象身份。
- 不以支持 Demo 旧数据格式为目标；允许重新设计正式内部实现。不得删除用户已经产生的 Demo 数据，旧数据不静默转换或覆盖。
- 以清晰、简单、可维护的实现为主，不引入插件框架、复杂服务体系、数据库或没有实际需求的抽象层。

### 2.2 正式代码的继承原则

**Demo 只作为参考，不作为正式程序直接扩展的代码基底。** 正式 `src/` 应根据本阶段确定的职责边界、数据格式和应用生命周期重新建立。

可以参考已经验证的数学关系、Qt API 使用、绘制算法和已知问题的修复经验。对于独立且职责明确的少量实现，例如页面坐标变换、局部荧光笔合成、文字选择适配等，允许经过审查后有选择地重新实现或移植；不得批量复制旧 `src/`、沿用整个 Demo 主窗口、存储类或交互状态机再逐步打补丁。正式工程不得依赖 `demo/` 源码、头文件或运行时资源。无需为了避免复用而刻意改变已经验证正确的算法，也不要求重新发明 Qt 已有能力。

归档 Demo 的具体目录安排和新工程模块划分允许按实际情况小幅调整，但必须维持两者构建与代码依赖的独立性。在本阶段结果记录中简要说明参考或移植了哪些技术内容、为何保留，以及哪些部分重新设计。

## 3. 正式应用架构（M01）

### 3.1 模块划分

```text
src/
├── main.cpp
├── app/             # 应用启动、主窗口、工作区、全局 QAction
├── library/         # 书库、书架、导入及书库界面模型
├── document/        # 文档会话、阅读状态、保存生命周期
├── pdf/             # Qt PDF 适配、页面渲染与缓存
├── reader/          # 页面布局、统一坐标、阅读及标注交互
├── annotation/      # 标注对象、样式、绘制及编辑命令
├── note/            # 笔记编辑、预览及资源处理
├── storage/         # JSON、路径、文件校验和持久化
└── settings/        # 本机设置、主题及配置管理
```

以上为职责划分，不要求每个目录编译为独立库，也不强制所有建议类名。主要对象如下：

| 对象 | 职责 |
|---|---|
| `MainWindow` | 统一主窗口、工作区标签、菜单及工具栏协调，不负责文件序列化 |
| `LibraryManager` | 书库业务操作、书籍及书架管理、导入、收藏、回收站 |
| `LibraryView` | 书库三栏视图、选择、筛选、拖拽，使用共享模型 |
| `DocumentSession` | 单本已打开书籍的 PDF、标注模型、笔记、撤销栈、存储绑定、渲染资源及保存状态 |
| `ReaderWorkspace` | 单个阅读标签页，组织 PdfView、导航和笔记/属性面板 |
| `PdfView` | 页面布局、显示、鼠标交互、视图状态，不决定文件存储方式 |
| `Storage` | 格式校验、路径解析、原子写入、资源文件管理 |
| `SettingsManager` | 本机配置的加载、保存及变更通知 |
| `ThemeManager` | 统一主题、调色板、样式和自绘控件颜色 |

DocumentSession 按书籍 ID 唯一管理，阅读控件及面板使用会话提供的数据而不重复持有独立标注模型。生命周期和 QObject 所有权须明确；关闭会话后取消或隔离迟到的渲染结果、定时器和信号。不同会话的标注、编辑缓冲、撤销历史及保存状态不得相互污染。页面布局与当前缩放属于视图状态。主窗口的操作根据活动工作区路由到对应模型或会话，切换时重新绑定并更新 QAction 状态。

不强制预先支持同一本书的多个视图、多窗口或后台任务框架。首版同一书籍 ID 只创建一个阅读会话。

## 4. 书库、本机配置与启动（M02、M03）

### 4.1 书库数据目录

用户选择的书库目录是长期阅读数据的根目录。建议结构：

```text
PANO Library/
├── library.json
├── books/
│   ├── Dynamics of Structures/
│   │   ├── document.json
│   │   ├── annotations.json
│   │   ├── cover.png
│   │   ├── assets/
│   │   └── Dynamics of Structures.pdf  # 仅拷贝模式
│   └── Another Book/
├── bookshelf/
│   └── shelves.json
└── state/
    ├── reading.json
    └── history.json
```

实际书籍目录采用导入文件名去扩展名作为可读基础名称；清理非法字符、保留名称、路径穿越及不同文件系统的名称冲突，必要时追加编号或短 ID。书籍标题重命名不自动重命名物理目录。普通书架、收藏和回收站都不是物理目录。书库索引仅使用安全的根目录相对路径。目录由程序管理，但不得误删其中无法确认归属的用户文件。

不在书库中保存本机配置、页面缓存、临时渲染文件或日志。不提前创建未来独立笔记系统的空目录。

### 4.2 本机配置

通过 `QStandardPaths` 获取标准应用配置、缓存和本地数据目录；Windows 与 Linux 的实际路径由系统决定。默认书库推荐 `Documents/PANO`，首次启动可修改。配置目录建议使用以下逻辑文件，也可按职责适当合并：

```text
<application-config>/
├── general.json       # 当前书库路径、默认导入模式、保存设置
├── appearance.json    # 主题、字体、语言偏好
├── reader.json        # 阅读默认设置
├── tools.json         # 标注工具预设
├── shortcuts.json     # 快捷键偏好（未实现时不创建）
├── workspace.json     # 窗口、布局、标签页、书库视图
└── sources.json       # 本机源文件路径映射
```

阅读页码、页内锚点、上次阅读时间属于书库数据；窗口尺寸、面板宽度、当前标签页、书库路径、设备缓存、外部源路径覆盖属于本机数据。阅读布局、缩放模式可以作为书籍阅读状态同步，恢复时按当前窗口重新计算适应比例，不直接恢复设备像素滚动条数值。

未来若提供配置导出，仅导出主题、字体偏好、快捷键、工具预设等可移植设置；默认不导出书库路径、本机源映射、窗口位置或当前标签页。此阶段不实现配置导入导出。

### 4.3 首次启动与切换书库

首次启动显示简洁的书库选择对话框，提供默认路径和浏览按钮。选择不存在或空的目录时经确认初始化；选择有效的已有书库时直接加载。非空且非 PANO 目录、损坏索引、不支持的格式版本、无权限目录等必须明确提示，不可静默覆盖或将其视为新书库。用户取消时不创建书库。

再次启动使用本机记录的书库路径。若路径失效，提示重新定位或切换，不自动创建替代书库。设置界面允许安全切换书库：先校验目标及取得其锁，再提交当前笔记、保存全部脏会话，成功后关闭旧会话、释放旧书库锁并切换。失败则保留原书库及未保存数据。切换不等于迁移，不自动搬运 PDF 或删除旧库。标签恢复按书库 ID 隔离；首版可以提供恢复上次标签的设置，至少实现上次阅读位置恢复。

## 5. 正式数据格式与契约（M02）

正式文件采用 UTF-8 JSON、统一缩进和稳定的序列化规则。业务数据文件均包含 `format` 与 `schema_version`。初始正式 schema 取 1，与 Demo 格式通过不同的正式 `format` 标识、结构及校验明确区分。程序版本独立维护。以下字段作为本阶段格式基线；实施中如确有必要调整字段名，需同步更新规范文档，不得出现多个权威字段。

### 5.1 书库索引 `library.json`

```json
{
  "format": "pano-library",
  "schema_version": 1,
  "id": "library-uuid",
  "books": [
    {
      "id": "book-uuid",
      "directory": "books/Dynamics of Structures",
      "favorite": true,
      "deleted_at": null
    }
  ]
}
```

书库索引是书籍登记、目录关联、收藏和删除状态的权威来源。`deleted_at` 为 UTC ISO 8601 时间或 null。所有书籍（含回收站）均保留登记，直到永久删除。书籍 ID 全库唯一。

### 5.2 书籍信息 `document.json`

```json
{
  "format": "pano-document",
  "schema_version": 1,
  "id": "book-uuid",
  "title": "Dynamics of Structures",
  "author": "Anil K. Chopra",
  "imported_at": "2026-11-27T06:00:00Z",
  "source": {
    "mode": "copy",
    "path": "Dynamics of Structures.pdf",
    "sha256": "<64 hexadecimal characters>",
    "size_bytes": 123456
  }
}
```

- `copy`：路径相对于单本书籍目录，必须位于书籍管理目录内；不记录或依赖导入前外部路径。
- `reference`：路径可为原始绝对路径；若支持库内相对引用，必须显式定义其路径基准（建议额外 `path_kind: library_relative`，普通绝对路径为 `absolute`），不允许根据工作目录猜测。第一阶段只支持绝对路径也可。
- SHA-256 标识 PDF 内容而非阅读项目 ID；标题、作者可修改。PDF 元数据不存在时标题回退至文件名，作者可为空。实际页数由 PDF 引擎获取，可缓存用于书库展示，但不作为标注校验的唯一依据。
- 书籍 ID 与索引一致。来源解析成功后，阅读器只获得有效的只读 PDF 路径和文档对象。

### 5.3 书架 `bookshelf/shelves.json`

```json
{
  "format": "pano-bookshelves",
  "schema_version": 1,
  "shelves": [
    {"id": "shelf-a", "name": "土木工程", "parent_id": null, "book_ids": []},
    {"id": "shelf-b", "name": "结构动力学", "parent_id": "shelf-a", "book_ids": ["book-uuid"]}
  ]
}
```

父级为 null 表示顶层。每个书架只有一个父级，禁止自身或后代作为父级，禁止循环及悬空父级。同级名称建议唯一；名称排序采用一致规则。一本书可属于多个书架，书架内同一书籍 ID 不重复。成员关系以本文件为准，不在书籍元信息中重复记录。删除书架只删除分类及其子书架，书籍仍保留在书库中。

### 5.4 标注 `annotations.json`

```json
{
  "format": "pano-annotations",
  "schema_version": 1,
  "book_id": "book-uuid",
  "annotations": [
    {
      "id": "annotation-uuid",
      "page_index": 12,
      "type": "rectangle",
      "geometry": {"x": 120.0, "y": 200.0, "width": 240.0, "height": 60.0},
      "style": {
        "stroke_color": "#FF0000",
        "stroke_width_pt": 1.5,
        "fill_color": null,
        "opacity": 1.0,
        "blend_mode": "normal"
      },
      "note": {"title": "运动方程", "markdown": "体系采用线性弹性模型。"},
      "created_at": "2026-11-27T06:00:00Z",
      "modified_at": "2026-11-27T06:00:00Z",
      "z_order": 0
    }
  ],
  "note_tree": []
}
```

标注公共字段包括稳定 ID、实际页索引、类型、几何、样式、可选附属笔记、创建及修改时间和绘制顺序。没有笔记时 `note` 为 null（或者采用规范明确的统一省略规则）。数组按创建顺序追加，不因界面排序改变。`z_order` 在页内解释，冲突时以创建顺序稳定决胜。笔记显示顺序默认按笔记创建顺序（已有标注之后添加笔记时，可记录 note 自己的创建时间），不等同于绘制顺序。

| `type` 建议值 | `geometry` 的权威字段 |
|---|---|
| `text_highlight` / `underline` / `strikeout` | `polygons`（点序列数组）、`text_start`、`text_end`、`text` |
| `line` | `start`、`end` 两个点 |
| `rectangle` / `ellipse` | `x`、`y`、`width`、`height` |
| `pencil` / `highlighter` | `points` 点序列 |
| `note_point` | `point` 单个点 |

点统一使用 `[x, y]`。标注页索引从 0 开始，界面默认从 1 开始，可后续显示 PDF 原有页码标签；不将 PDF 目录结构保存进标注。坐标为 Qt PDF 基准可见页（已考虑文档自身固有旋转/裁剪、未施加用户视图旋转）的 point 单位，左上原点、X 向右、Y 向下。文字索引采用 Qt PDF 对应版本的索引定义，在格式说明中明确范围约定；几何多边形为长期显示的权威数据，索引用于文字范围恢复，不以索引变化静默重算旧标注。

建议 C++ 使用公共对象与类型特有数据（如 `std::variant`），避免同时保存重复的矩形、端点、路径字段。包围盒、命中范围等派生数据按需计算。样式只暴露类型适用的属性；颜色用 `#RRGGBB`，透明度统一由 opacity 表达，混合模式为 `normal` 或 `multiply`。类型无关的字段不得造成无法理解的默认几何或歧义。

笔记正文采用 Markdown 字符串，不单独建立每条笔记的 MD 文件。自由笔记通过 `note_point` 锚定原文。`note_tree` 为后续组织关系保留，可定义分组节点和引用标注 ID 的笔记节点；本阶段不实现完整笔记树编辑器，不强制每次创建标注同步维护未使用的树。后续树关系一旦写入，必须校验引用、无循环及无重复节点；空树时由当前笔记列表按创建顺序展示。图片、截图路径相对于书籍目录，限制在 `assets/`，禁止资源路径穿越。

### 5.5 阅读状态与历史

`state/reading.json`：`format: pano-reading-state`，以书籍 ID 为键，保存实际页索引、页内 point 锚点、缩放模式/固定比例、旋转（视图角度）、布局（仅已实现的布局值）及更新时间。恢复时处理页码超界、无效缩放和不同窗口尺寸。

`state/history.json`：`format: pano-reading-history`，以书籍 ID 记录最近打开时间等基本阅读历史，首版不统计精确阅读时长或详细轨迹。状态文件不重复存储笔记或书籍元信息；永久删除时清除对应状态记录。

### 5.6 校验与版本维护

在 `docs/specification/` 中记录书库、书架、书籍、标注、阅读状态及本机路径映射的正式格式（单位、类型、必填字段、默认值、关联规则、版本策略）。不要求额外引入 JSON Schema 框架。

加载时检查格式、版本、唯一 ID、父级关系、文件归属、有限数值、页索引、几何与类型匹配、样式范围、资源路径等。对缺失 PDF 的书籍保留标注和元信息，实际页数校验待源文档可用。未知高版本、未知对象类型、损坏 JSON 或关键关联不一致不得静默降级并重新写入；明确拒绝写入或提供安全只读状态。未来升级通过显式迁移并备份旧文件完成。Demo 数据不自动迁移。

## 6. 书籍导入、文件保护与跨设备使用（M04、M05）

### 6.1 导入流程

支持文件对话框多选 PDF 和从文件管理器拖入 PDF。导入时可选择映射或拷贝，初始值来自本机设置；可按批次统一选择。若在普通书架中导入，成功后加入该书架；在全部书籍中导入不强制分类。回收站不允许导入。

1. 检查文件可读性、PDF 能否打开及基本元数据，计算 SHA-256；对加密、损坏或不支持的文档明确提示，不留下无效的书籍登记。
2. 检查是否存在相同内容的书籍。默认提示打开已有书籍或加入当前书架；可明确选择创建新的独立阅读项目。若匹配项在回收站中，提供恢复选项，不静默恢复或覆盖。
3. 分配稳定书籍 ID 及独立目录，初始化文档信息和空标注文件。拷贝模式将 PDF 复制到书籍目录并核对内容哈希；映射模式不复制原文。
4. 渲染第一页生成 `cover.png`，维持原始宽高比，限制合理分辨率。封面生成失败时使用占位封面，允许后续重建，不因封面失败丢失可用书籍。
5. 完成文件写入并校验后登记书库索引，再处理目标书架成员关系。某一步失败时报告具体原因，清理本次产生且确认归属的临时文件，或保留可识别的待恢复数据，不能形成指向不存在目录的有效索引。批量导入逐项报告成功、失败、跳过情况。

封面和元信息加载不应导致书库每次打开时逐本解析完整 PDF；大量文件导入、哈希及封面生成应避免长时间阻塞界面，可采用简单后台任务和进度反馈，不必建立通用任务框架。

### 6.2 路径解析与源文件重定位

本机 `sources.json` 按书库 ID 和书籍 ID 保存映射覆盖，例如：

```json
{
  "schema_version": 1,
  "libraries": {
    "library-uuid": {
      "source_overrides": {
        "book-uuid": "/mnt/document/Books/Structural Dynamics.pdf"
      }
    }
  }
}
```

映射模式优先解析本机覆盖路径，再解析共享文档中的原始路径；路径有效且内容一致方可使用。两者均不可用或哈希不同则提示重新定位。用户选择新 PDF 后核对原 SHA-256，匹配才保存到本机覆盖字段，不自动改写其他设备使用的共享路径。若文件大小、时间戳等快速检查表明可能变更，应重新计算哈希；不能仅凭文件名接受新源。建议在打开会话时进行内容一致性验证并在会话内复用结果，避免每次保存标注重新计算 PDF 哈希。

拷贝模式只解析书籍目录内的相对路径，不使用本机覆盖、不回退到旧导入位置。文件缺失时提示从备份恢复；不把其他文件悄悄当作原 PDF。源文件不可用时，书库中仍保留封面、元信息、标注及笔记，不连带删除数据。第一阶段不要求为缺失源的书籍构建完整独立笔记阅读界面，但必须能识别、定位源文件并保留数据。

### 6.3 源文件保护与备份边界

- PDF 引擎使用只读方式打开文档。标注、笔记、旋转和阅读状态只能改变独立数据，不允许覆盖源文件或书库中的 PDF 副本。
- 今后带标注 PDF 导出只能创建独立输出，禁止目标指向任一受保护源（包括路径别名、符号链接和可检测的硬链接）。此阶段不实现 PDF 导出，但不引入违反此约束的写入接口。
- 普通书库目录复制、Git 管理或网盘同步保留映射关系，不自动拷贝外部 PDF。本机路径覆盖默认不随书库备份。拷贝模式书籍随书库整体迁移后应直接可用。
- 将来可实现完整书库导出：将可访问的映射 PDF 复制至新的导出库，仅导出副本转换为拷贝模式；缺失源时明确报告不完整。本阶段不实现该功能，也不开发目录级批量映射、自动同步和冲突合并。

## 7. 多级书架、收藏及回收站（M06、M07）

### 7.1 组织原则与操作语义

书库（Library）包含全部导入书籍；书架（Bookshelf）是多级逻辑分类。书架树采用单父级结构，书籍支持多书架归属。收藏（Favorites）及回收站（Trash）是基于状态生成的特殊视图，不属于普通书架树，不保存独立成员列表。

| 操作 | 语义 |
|---|---|
| 全部书籍 | 显示所有未进入回收站的书籍，包含未分类书籍；不视为实际父级书架 |
| 新建、重命名、移动书架 | 修改书架定义，禁止循环、同级冲突及非法目标 |
| 删除书架 | 经提示删除分类及子分类，不删除任何书籍或笔记 |
| 添加到书架 | 新增书籍与目标书架关系，保留已有其他关系 |
| 从当前书架移除 | 仅删除当前关系，书籍仍存在于书库 |
| 移动到书架 | 从实际来源书架解除归属并加入目标，保留其他归属；没有实际来源书架时只增加关系 |
| 收藏/取消收藏 | 修改书籍收藏属性，与书架归属无关 |
| 删除书籍 | 移入回收站，不立即清理目录 |
| 恢复书籍 | 取消软删除，恢复尚存在的书架关联、收藏和阅读状态 |
| 永久删除/清空回收站 | 经明确确认清理程序管理的数据和关联，不删除映射源文件 |

第一版不自动清空回收站。普通视图隐藏软删除书籍，原有书架关系保留；删除书架时其关系自然移除。恢复后若无任何有效归属，则在全部书籍中可见。

### 7.2 删除安全与失败恢复

软删除前若书籍已打开，提交编辑缓冲、保存并关闭会话；失败则取消删除。回收站书籍不得进入可编辑阅读会话，可查看元信息及执行恢复/永久删除。

永久删除之前验证目标目录确属该书籍，位于书库 `books/` 下、与索引及 manifest 一致，不跟随符号链接到库外，不删除书库根目录或外部源。若目录内存在其他受保护映射源或不能确认归属的文件，拒绝直接递归删除并提示处理。建议先将目录在同一文件系统内移动到受控的待清理位置，再更新索引、书架及状态，最后清理待删除目录；具体实现可采用等效的简洁可恢复流程。失败或中断须能够识别未完成操作并重试/恢复，不能将部分成功伪装为永久删除成功。清空回收站逐项执行并报告结果。

## 8. 书库界面（M08）

### 8.1 总体布局

使用经典 Qt Widgets 桌面应用结构：菜单栏、工作区标签栏、上下文工具栏、主要内容及状态栏。书库固定为第一个标签页，不可关闭；阅读标签页可关闭。默认书库界面三栏，中间区域自动扩展，两侧使用可调整的分割器并支持隐藏。尺寸采用合理最小值，不使用固定像素布局强行适配所有屏幕。

```text
┌─────────────────────────────────────────────────────────────┐
│ 菜单栏：文件 / 编辑 / 视图 / 书库 / 工具 / 帮助            │
│ [书库] [Dynamics of Structures ×] [Structural Dynamics ×]   │
│ 导入 | 新建书架 | 分类操作 | 排序 | 视图       搜索书籍      │
├─────────────┬─────────────────────────────┬─────────────────┤
│ 全部书籍    │ 土木工程 / 结构动力学        │ 书籍封面        │
│ 收藏        │                             │ 标题、作者      │
│ 我的书架    │ [子书架] [子书架]            │ 收藏、导入方式  │
│  └ 土木工程 │                             │ 文件状态        │
│    ├ 结构…  │ [书籍封面] [书籍封面]        │ 上次阅读位置    │

├─────────────┴─────────────────────────────┴─────────────────┤
│ 状态栏：书库状态、书籍数量、操作反馈                         │
└─────────────────────────────────────────────────────────────┘
```

此图为布局说明，不要求精确还原字符图或采用特定像素比例。初始左右面板可参考约 1:3:1.4 的比例。建议使用 Qt Model/View、统一业务模型及代理/筛选模型，避免树、列表和封面模式各维护一份业务数据。

### 8.2 左侧导航

显示全部书籍、收藏、多级普通书架及回收站；树形导航不展开具体书籍。普通书架支持创建、重命名、移动、删除及展开状态恢复。回收站与普通书架视觉区分。可以在根分类或当前书架建立子书架。

### 8.3 中间内容

普通书架显示直接子书架及直接归属书籍，子书架以文件夹样式显示，书籍以封面或列表显示；不默认递归汇总所有子级书籍。全部书籍、收藏、回收站为平铺书籍视图。路径导航可点击返回上级书架，双击文件夹进入，双击正常书籍打开或切换到现有阅读标签。

支持封面/列表切换、单选及合理的多选、搜索标题/作者、名称/作者/导入时间/最近阅读时间/阅读位置/文件大小排序、升降序切换，书架优先排列。搜索默认在当前视图内进行，可通过全部书籍完成全库搜索。缺失字段采用稳定的排序规则。阅读位置比例不等于真实阅读完成率，应使用准确表述。封面尺寸、列表列宽及排序偏好在本机恢复。

### 8.4 右侧信息

选中一本书时显示封面、标题、作者、收藏状态、文件来源与可用状态、导入时间、文件大小、上次阅读位置、最近阅读时间、标注和笔记数量、所属书架等已有信息；支持编辑标题/作者、打开文件位置、重新定位源文件、继续阅读。选择书架时显示名称及基本统计，多选时显示数量及可用批量操作，不误显示单书籍属性。

标注/笔记统计可按需从书籍数据获取或使用可重建缓存，不为书库展示引入独立权威计数字段；不要求逐本打开 PDF。历史首版只显示基础最近阅读信息，不开发行为统计系统。

### 8.5 操作入口与拖拽

菜单、工具栏、右键菜单和快捷键复用 QAction 或共享业务命令，避免相同行为产生不同结果。书库与阅读界面使用上下文工具栏。

| 拖拽来源 | 目标 | 行为 |
|---|---|---|
| 外部 PDF | 全部书籍/普通书架 | 导入，普通书架中同时分类 |
| 书籍 | 普通书架 | 默认移动当前来源关系，Ctrl 拖拽为添加分类 |
| 书籍（来自全部书籍或收藏） | 普通书架 | 增加分类，不取消收藏 |
| 书籍 | 收藏 | 添加收藏 |
| 书籍 | 回收站 | 软删除 |
| 普通书架 | 另一个普通书架/书架根节点 | 调整父级，禁止非法循环 |

回收站内书籍只能通过明确恢复、永久删除等入口操作，不将拖拽到普通书架默认为永久删除或隐式复制。拖拽目标需要视觉反馈；不支持的目标拒绝操作。分类移动保留其他书架关系。

## 9. 文档会话、多标签页与 Demo 功能基线（M09、M10、M15）

### 9.1 生命周期

打开书籍时解析并校验源 PDF、加载标注、建立 DocumentSession、初始化阅读控件与面板、恢复阅读状态。每个书籍 ID 同时仅有一个会话；再次打开切换至已有标签。不同 ID 即使 PDF 内容相同也可以分别阅读，其笔记完全独立。

切换标签页之前先提交离开会话的笔记编辑并保存必要数据。关闭标签时处理未保存状态，成功后释放 PDF、渲染器、缓存及编辑历史；保存失败保留会话。退出程序或切换书库时处理全部脏会话。菜单、工具栏、撤销重做、保存与状态栏始终针对活动工作区；快捷键焦点在笔记文本编辑器时遵循文本编辑语义，不意外撤销其他书籍标注。

### 9.2 正式阅读界面基础

延续三栏设计：左侧导航（本阶段最低限度提供页码跳转，可用目录和缩略图留待 Phase 2），中间自主 PDF 阅读控件，右侧标注/笔记列表及属性和笔记编辑面板。提供必要的阅读、缩放、旋转、标注、编辑及笔记工具，使用分组和分隔线；正式阅读器的详细交互布局后续独立完善，不要求本阶段完成所有设计稿。

### 9.3 必须重新建立的技术基线

正式工程不能以旧 Demo 作为运行依赖，但下列已验证的能力必须恢复，不因重建工程而出现明显退化：

- PDF 加载、连续单页阅读、页码跳转、固定比例缩放、适应宽度/页面和 0/90/180/270 度视图旋转。
- 一套共享页面 point 坐标及 Page→Content→View 变换。Qt QTransform 的组合约定应明确；页面图像、标注、临时对象、文字选区、鼠标逆映射、命中检测及原文定位均使用统一变换。图像按基准页尺寸渲染，不把旋转后宽高直接用于拉伸。
- 异步页面渲染、有限 LRU 缓存、旧请求隔离。只缓存原始页面图像，标注独立合成。多会话下有合理的总资源限制或非活动会话回收策略，不要求复杂全局调度器。
- 文字高亮、下划线、删除线；直线、矩形、椭圆；铅笔、荧光笔、对象橡皮擦；定位笔记。已有自由画笔 Shift 直线及轴向吸附、实时预览、对象选择与类型适用的移动/尺寸调整。
- 标注颜色、线宽、填充、透明度和普通/正片叠底模式；荧光笔局部蒙版一次性合成，避免同一笔画内部重复叠色。创建新对象按实际工具预设，不硬编码覆盖用户样式。
- 标注精准定位（包括同页不同位置）、关联笔记、Markdown 基础预览、图片资源与区域截图、撤销重做、带笔记标注删除保护和保存恢复。

对旧 Demo 尚未实现的功能不要求在本阶段补齐，例如连续橡皮擦、复杂笔记树及新增内容型标注。优先保证正式应用生命周期及数据可靠性，不将本阶段扩大为完整阅读器重写优化项目。保留现有公式显示代表性能力即可；成熟 Markdown/公式库在笔记阶段统一选型（见第 12 节）。

## 10. 保存与数据可靠性（M11、M14）

### 10.1 保存策略

| 触发 | 行为 |
|---|---|
| 标注提交、属性改变、撤销/重做 | 标记脏状态，延迟自动保存 |
| Markdown 编辑 | 停止输入后保存，确保编辑缓冲提交 |
| 书架、收藏、软删除等业务操作 | 操作完成后立即持久化 |
| 切换书籍或回到书库 | 提交并保存离开的书籍 |
| 关闭书籍、退出程序、切换书库 | 保存所有涉及的脏数据，失败时阻止丢失数据的操作 |
| Ctrl+S / 保存菜单 | 立即提交并保存当前书籍；书库模式可保存待保存的书库状态 |

建议默认延迟 2 秒，连续编辑最长等待 30 秒（可按实际使用调整）。本机设置可启停延迟自动保存并调整间隔；关闭延迟自动保存不关闭切换、关闭及手动保存。鼠标移动中的临时对象不触发文件写入，完成操作才记录一次命令。

状态栏显示已保存、未保存、正在保存、保存失败。保存失败不能清除脏标记；保留内存修改和错误信息，允许重试或取消关闭等操作。即使采用后台保存，也不得将旧快照的写入成功标记为更新版本已保存；每会话写入串行化或使用等效机制。

### 10.2 原子写入、锁与外部修改

- 使用 `QSaveFile` 或等效原子替换写入 JSON，禁止静默退化为覆盖写。资源文件先安全写入再提交引用；失败时保留旧数据，不因撤销/取消而误删仍被引用的资源。
- 使用 `QLockFile` 或等效方式对书库根目录进行本机写入互斥。不能取得锁时提示占用，不强行清理有效锁；异常退出后按安全规则处理失效锁。该锁不是跨设备同步协议。
- 加载时记录文件版本或内容摘要，保存前检测已知外部修改，防止 Git 切换、手动修改或网盘同步导致静默覆盖。冲突时提示、保留本机修改，不自动进行合并。
- 对多文件业务操作明确写入顺序、失败回滚或恢复策略；单个 JSON 原子写入不代表多文件事务。优先使用简单可恢复的顺序和少量操作记录，不引入数据库事务系统。
- 检测孤立目录、缺失索引项、未知格式时给出诊断，不无提示重建或删除用户数据。备份不是自动覆盖冲突的替代品。

第一版只支持单设备写入同一个书库，使用外部同步工具时建议先关闭 PANO、等待同步完成，再在另一台设备打开。不得宣称已支持并发编辑、跨设备锁或冲突合并。

## 11. 独立设置与主题（M12、M13）

### 11.1 设置窗口

使用独立设置对话框或窗口，按标签页组织。首版优先实现实际可用设置，未开发的条目不显示为可操作功能。

| 标签 | 本阶段内容 | 后续扩展 |
|---|---|---|
| 界面 | 主题、字体大小、恢复默认界面设置 | 语言切换、更多外观选项 |
| 数据与存储 | 当前书库、打开目录/安全切换、默认导入方式、自动保存开关及延迟 | 完整备份、配置导入导出 |
| 阅读 | 已支持的默认缩放方式、阅读状态恢复相关设置 | 更多布局、缓存细化、阅读背景 |
| 标注 | 已支持工具的基本样式设置或工具栏预设记忆 | 多预设编辑、吸附及橡皮擦选项 |
| 快捷键 | 基本快捷键说明（按需） | 自定义及冲突检查 |

主题及字体即时更新并持久化；如对话框提供取消/应用语义，应明确实时预览的回滚行为。导入默认值作用于后续导入，不更改已导入书籍的模式。书库切换必须执行第 4.3 节的业务流程，不能简单修改路径字符串。语言首版只需保证界面文字使用 `tr()` 等可翻译方式组织，不要求完整翻译文件或语言切换。

### 11.2 主题管理

提供现代浅色（默认）、经典桌面、暖色阅读、现代深色四种内置预设，可在设置界面实时切换。主题通过统一 ThemeManager 管理 QPalette、必要的集中式 QSS 及自绘控件语义颜色（窗口、面板、背景、边框、强调、选中、文字等）。图标适配明暗背景；避免各模块硬编码冲突样式、重复设置字体或在切换时重建整个主窗口。无需用户自定义主题编辑器。

PDF 原文颜色、标注真实颜色及图片资源不随界面主题变化；深色主题只修改界面和阅读画布背景。阅读纸张变色/反色是未来独立功能。主题、字体、窗口布局三者独立保存和更新。

主题热切换保持打开的书籍、当前页内位置、缩放、选择、编辑内容、撤销历史和面板布局；新窗口及对话框遵循当前主题，重启恢复最后设置。切换主题不能要求重新加载 PDF。字体大小变化可能引起正常布局调整，但不得丢失阅读状态或覆盖用户偏好。

## 12. Markdown 与公式渲染的阶段边界

正式项目不以自研完整 Markdown/TeX 解析器为长期目标。候选路线为 Qt 原生 Markdown 或 MD4C（支持数学语法识别）配合 QTextDocument，以及独立数学排版库（优先评估 JKQTMathText，备选 MathJax SVG 或 WebEngine + KaTeX）。Markdown 数学语法识别不等于公式排版能力；候选库须实际验证字体、行内基线、矩阵/分段函数、离线部署、许可证与跨平台构建后才能冻结。

本阶段不强制引入任何上述额外依赖，不继续扩展自研复杂语法。正式笔记接口保持 Markdown 原文与显示实现独立；可采用 Qt 原生 Markdown 能力及少量经过审查的临时公式适配，或有选择地移植已有的独立显示算法，以保留代表性公式、图片、基本 Markdown 预览功能。不得直接引用 Demo 源文件或借此批量复用 Demo。若临时渲染存在不支持的公式，应安全显示源码或提示，不丢失笔记原文，并在结果记录中列明差异。正式笔记阶段再统一替换为成熟方案。

## 14. 验收与验证计划

### 14.1 构建与最少必要的自动检查

至少在当前可用开发环境中构建正式主程序及归档 Demo，记录 Qt SDK、编译器、构建命令与结果。Windows/Linux 两个平台均为目标；无某平台环境时记录未验证，不声称双平台均通过。少量针对性的非视觉检查建议覆盖：

1. 正式 JSON 格式往返、书籍/书架稳定 ID、循环书架和非法路径拒绝、未知版本不覆盖。
2. 映射/拷贝导入、哈希匹配与拒绝、复制后原路径不再依赖、PDF 原文哈希不变、永久删除不触及外部源。
3. 书架关系、收藏、软删除/恢复及永久删除的状态一致性，保存失败或外部修改时数据保护。
4. 页面统一坐标变换：多个缩放、非零滚动、四种旋转，验证独立预期点和实际显示边界，不只检查正逆往返或序列化数据不变。

允许复用 Demo 探针中的思路，但正式检查不依赖 Demo 实现。无需编写大量控件级测试或全套自动 GUI 脚本。使用临时目录及测试 PDF；禁止使用实际书库做破坏性测试。

### 14.2 运行与人工/视觉检查

本项目已获用户许可进行运行、截图和视觉检查。开发者应实际启动正式应用，尽量在当前可用真实桌面环境执行下表中的主要操作；对于 offscreen、无窗口系统、无法模拟交互或无法测试另一平台的情况明确说明。截图仅作为辅助，需实际检查显示内容，不以成功生成截图文件等同于界面验收。

| ID | 验收场景 | 预期结果 |
|---|---|---|
| V01 | 首次启动、取消、创建新书库、重新启动 | 初始化提示正确，取消不创建，重启加载原库 |
| V02 | 加载已有库、切换库、无权限/无效库 | 数据不覆盖，切换安全，错误提示明确 |
