## 1. 开发目标与范围

本阶段开始正式的专业笔记系统开发。将现有依附于标注的笔记改为独立对象，在每本书内建立标注、笔记及笔记组织结构三个独立数据集合；通过可选关联实现原文定位和界面联动。笔记树采用类似文件目录的简单层级结构，允许在书籍根节点及任意分组下创建笔记或子分组。初版重点是点击式管理、数据一致性和可使用的完整流程，不追求复杂编辑器或拖拽体验。

本轮还需要首先统一 xmake 工程入口。根目录是整个仓库唯一正式构建入口；子项目可以保留局部 xmake.lua，但由根工程按配置包含，不再作为独立项目配置和编译。默认构建不包含 Demo，Markdown Demo 的第三方依赖不得影响主程序。

## 3. N01、N02：独立模型与关联管理

### 3.1 对象职责

现有 `src/annotation/Annotation.h` 中的 `AnnotationNote` 包含 `title`、`markdown`，作为 Annotation 成员存在；`PdfView::setAnnotationNote()` 与 `ReaderWorkspace` 的笔记定时提交均依赖这一结构。本轮应移除这种正文嵌入关系，而不是再额外复制一份笔记集合。

- `Annotation`：保留现有几何、样式、文字、页索引、ID、时间等字段，仍以未旋转页面 pt 坐标为准。保留 `NotePoint` 定位标注类型。
- `Note`：独立的笔记对象，可有或无原文关联，不包含页码、坐标及标注样式的副本。
- `NoteTree`：只负责分组、层级及笔记 ID 引用，不持有笔记正文或标注数据。
- `DocumentSession`：负责一本书内模型的生命周期、关联事务、撤销和持久化协调。标注和笔记模块不得互相持有对方的完整业务模型。

概念接口（名称可随现有代码风格调整）：

```cpp
struct Note {
    QString id;
    QString title;
    QString markdown;
    QString annotationId;  // 空表示无原文关联
    QString createdAt;
    QString modifiedAt;
};
```

独立 UUID 使用现有 Qt QUuid 机制生成，创建后稳定，不基于页码、坐标、正文或时间推导。分组同样具有独立 UUID；书籍根节点直接使用 book ID，不另建虚拟持久化对象。允许正文为空，标题应具有有效显示值（例如“未命名笔记”）；空正文绝不等于不存在笔记。时间字段沿用项目现有 ISO 8601 约定，笔记创建时间和标注创建时间相互独立。

### 3.2 可选一对一关联

每项标注最多关联一条笔记，每条笔记最多关联一项标注；两者均可独立存在，只允许同一本书内关联。保留定位笔记的工作方式：点击 PDF 创建 NotePoint，并与独立 Note 关联。

延续此前讨论的单一权威关系设计：只在持久化 Note 中保存 `annotation_id`，Annotation 不再保存笔记正文，也不额外保存第二份持久化 `note_id`；内存中通过 ID 索引提供双向查询。可在 Annotation 内存模型中暴露只读派生状态，但不能成为另一份可独立修改的真值。

建议由会话层提供 `noteForAnnotation`、`annotationForNote`、`hasLinkedNote`、`linkNote`、`unlinkNote` 等统一入口。NoteModel 独立管理笔记集合并按 ID 查找，不需要遍历标注获取笔记列表。关联建立/解除时更新反向索引和相关界面；普通几何和样式修改不需要修改笔记。标注绘制、笔记提示图标、仅有笔记筛选及删除保护等使用关联查询，不直接读取正文。

建立关联前校验两对象存在、属于同一会话、没有冲突。已有关联时默认拒绝隐式覆盖；如果用户明确选择重新关联，显示将解除的旧关联，作为一次操作执行。初版可通过“关联已有标注”对话框列出当前书籍中未关联的标注（页码、类型、原文摘要），或使用阅读区当前选中标注；不开发复杂关系图。NotePoint 不作为可长期存在的无关联普通标注，专用定位点与笔记创建、解除关联或删除一并处理。

## 4. N03：数据协议与持久化

### 4.1 同文件独立集合

本轮不拆成多个物理文件，以保留单次原子写入能力。继续使用每本书的 `annotations.json`，但数据协议升级到新的版本（建议 `schema_version: 2`，以仓库实际规范为准）。仅修改该阅读数据协议，不无关提升书库、书签、阅读状态或工具预设的版本。

示例仅表达结构，UUID、时间和标注几何在正式实现中使用完整有效值：

```json
{
  "format": "pano-annotations",
  "schema_version": 2,
  "book_id": "book-001",
  "annotations": [
    {"id": "a001", "type": "highlight", "page_index": 17, "text": "Equation of motion"}
  ],
  "notes": [
    {
      "id": "n001",
      "title": "运动方程",
      "markdown": "系统的基本运动方程为……",
      "annotation_id": "a001",
      "created_at": "2026-11-28T08:00:00Z",
      "modified_at": "2026-11-28T08:00:00Z"
    },
    {
      "id": "n002",
      "title": "阅读心得",
      "markdown": "",
      "annotation_id": null,
      "created_at": "2026-11-28T08:01:00Z",
      "modified_at": "2026-11-28T08:01:00Z"
    }
  ],
  "note_tree": [
    {
      "type": "group",
      "id": "g001",
      "title": "单自由度体系",
      "children": [{"type": "note", "note_id": "n001"}]
    },
    {"type": "note", "note_id": "n002"}
  ]
}
```

上例中的 `format`、标注类型名等沿用现有规范中的真实值，不借示例改变原有序列化字段。空关联统一输出 null（C++ 内部可以为空 QString）；根节点由书籍信息生成；数组顺序即同级组织顺序。Group 不具有 Markdown 正文；Note 是叶节点。附件继续保存在原有 `assets/`，正文通过相对路径引用。公式渲染产物不作为正式附件保存。

### 4.2 存储入口调整

当前 `LibraryStore::readAnnotations()` 只返回标注数组，`writeAnnotations()` 固定写入 schema 1 且将 `note_tree` 写为空数组；`DocumentSession::annotationsFingerprint()` 等持久化判断也围绕标注数据。必须一次性更新整个读写链路，包括新书导入时的初始化、会话加载/关闭、自动保存、外部修改校验、书库统计和各类探针。不能仅修改单个 JSON 字段或只在 UI 中维护笔记树。

建议引入一个书籍阅读数据聚合结构（例如 `BookReadingData` / `ReadingContent`，名称自定），包含 annotations、notes、note_tree 三个集合。序列化、反序列化和完整性校验走统一入口。不要在 NoteModel 和树模型之间复制标题、正文、关联等数据。模型的结构变化、笔记正文变化、树顺序及关联变化均触发会话 dirty 状态，计算完整快照指纹，使用现有 QSaveFile 与外部文件变动检查进行一次写入。写入失败不清除 dirty，不显示已保存，不覆盖外部变更；保持用户可恢复的内存数据。

必须保证：ID 唯一、关联目标存在且一对一、树节点引用有效、每条正式笔记在树中恰好出现一次、无重复分组 ID、无非法父子结构；NotePoint 与关联规则一致。校验先于提交或正式加载；对结构错误提供明确提示，不静默删除笔记、重排树或猜测关联。限制异常嵌套深度及不合理数据规模，避免递归崩溃；不要人为限制正常的多级组织。

### 4.3 旧数据策略：不兼容，不自动迁移

用户明确要求从新格式开始，现有测试笔记无须保留。因此只实现新版数据读写，不编写旧 `AnnotationNote` 迁移器，不维护新旧两套模型，不新增兼容字段或旧数据自动转换逻辑。

但不得静默覆盖旧书库。旧 schema 1 或未知版本应明确报错并保持文件不变；不允许加载失败后把空模型自动保存回原文件。建议使用新测试书库重新导入原 PDF；原书库可由用户自行备份和重新初始化。本轮不必开发专门的重置界面。不得修改、删除或复制覆盖原始 PDF，不得自动重建其他书籍的数据。旧程序应不能写入 v2（现有旧版读取入口已检查 schema 1，需验证相关行为）。更新数据规范，并明确新版不兼容的范围。

## 5. N04：目录式笔记树

### 5.1 节点与显示

采用“书籍 → 分组/笔记”的目录式结构；书籍根节点可直接包含任意笔记和分组，分组可以继续包含笔记及子分组，笔记本身为叶节点。分组用于主题或章节分类，不具有正文和原文锚点；若需章节总结，在分组内创建独立笔记。笔记有独立标题与 Markdown 正文，是否关联原文与树结构无关。

```text
结构动力学（书籍根）
├── 基本概念（分组）
│   └── 动力学假设（笔记）
├── 单自由度体系（分组）
│   ├── 运动方程（笔记，关联第18页）
│   └── 自由振动（分组）
│       ├── 无阻尼振动（笔记，关联第31页）
│       └── 章节总结（独立笔记）
└── 阅读心得（独立笔记）
```

初版使用普通 Qt 树形控件（QTreeWidget 或 QTreeView + 模型，选择维护成本较低的实现）。树控件只展示业务数据；持久化结构不能从临时控件文本反推。所有节点按创建顺序追加到所选父节点末尾，之后尊重用户手动调整的顺序。使用 Lucide 图标区分书籍、分组、笔记，关联笔记可显示页码或链接提示；无关联不显示虚假页码。展开/折叠为界面状态，不要求本轮新增持久化字段。

### 5.2 点击式操作

| 操作 | 行为 |
| --- | --- |
| 新建笔记 | 根或分组选中时在其下创建；选中笔记时在其父分组下添加同级笔记 |
| 新建分组 | 根或分组选中时创建子分组；选中笔记时在父分组下创建同级分组 |
| 重命名 | 修改分组名称或 Note 标题，不改变 ID |
| 移动到 | 简单分组选择对话框，支持根节点；移动整个分组时排除自身及其后代 |
| 上移/下移 | 仅调整当前同级数组顺序；首尾位置禁用对应动作 |
| 展开/折叠 | 控件标准操作，不改变数据结构 |
| 删除笔记 | 删除笔记和树引用，按第6节处理关联 |
| 删除分组 | 默认保留子项并提升到原分组所在的父级位置；删除整个子树需另行确认 |

根不可删除、移动、重命名（书名由书库管理）。无选择时使用根节点。创建入口较多时共用同一父分组决策，显式编辑窗口应记录创建时的目标父节点，不能因用户随后改变树选择而更改保存位置；若该分组被删除，提示重新选择或回到根，不静默写入不存在的节点。移动、删除后保证选中项与预览有效，避免全树无意义刷新导致展开状态丢失。初版关闭拖拽、多选和复杂批量操作；不实现实际思维导图视图。树结构应便于未来按深度优先顺序生成汇总 Markdown，但本轮不开发导出模块。

## 6. N05：对象生命周期与撤销

### 6.1 创建、关联、删除规则

| 操作 | 规则 |
| --- | --- |
| 普通标注 | 只创建 Annotation |
| 独立笔记 | 只创建 Note 及树节点，无 PDF 位置 |
| 为已有标注添加笔记 | 新建 Note、树节点和关联；已有笔记时打开该笔记而非重复创建 |
| 文字/区域选区创建笔记 | 复用已有选区、摘录和截图能力；新建必要标注及 Note、树节点和关联 |
| 页面点击创建定位笔记 | 新建 NotePoint + Note + 树节点，作为一次提交 |
| 删除普通标注（有关联） | 明确提示解除关联，默认保留 Note 与原树位置；可显式选择同时删除 |
| 删除笔记（普通关联标注） | 删除 Note 和树节点，保留标注 |
| 删除定位笔记 | 删除 Note 和专用 NotePoint，不能留下无用途定位点 |
| 解除关联 | 保留两对象（普通标注）；若为专用 NotePoint，删除该定位点并保留 Note |
| 连续橡皮擦 | 继续跳过附有关联笔记的标注，保持现有保护和提示 |
| 标注复制/粘贴/重复 | 新 ID，只复制几何及样式等既有范围；不复制笔记或关联 |

若选择同时删除笔记，使用既有明确确认方式，不能由普通擦除隐式触发。删除分组时默认提升子项并维持原相对顺序；若实现“删除整个子树”，显示受影响笔记/分组数量并要求确认，普通关联标注仍保留，专用 NotePoint 随其笔记删除。为避免误操作，第一版可以只提供提升子项的删除方式，将整树删除留待后续，不影响本阶段达标。

### 6.2 跨模型事务和撤销

当前 `PdfView` 持有 `AnnotationModel` 和 `QUndoStack`。可保留已有结构并由 `DocumentSession` 组织跨模型命令，或小范围调整共享撤销入口；不能形成标注、笔记、树三个相互不协调的历史栈。创建定位笔记、删除带笔记标注、删除笔记、重新关联、移动分组等应分别形成一个完整业务命令，undo/redo 恢复 ID、正文、关联、几何、树父节点与同级顺序。对话框的取消不是撤销已提交的操作。

提交前校验全部修改；中间状态不能被自动保存或被其他 UI 当作正式数据。修改失败时不留孤立笔记、定位点、树引用或半条关联。标注几何编辑命令继续使用现有实现，不能因删除嵌入式正文而丢失现有撤销能力。编辑器内 Ctrl+Z/Redo 归文本编辑器；主阅读器中使用书籍会话的撤销命令。若编辑窗口打开时关联对象或笔记被删除/撤销，按第7节冲突规则处理。

## 7. U01、U02、U03：基础界面与联动

### 7.1 阅读器右侧窗格

保留现有顶部工具栏、左侧导航及 PDF 阅读区，不调整已经稳定的整体界面。右侧继续保留“标注 / 笔记 / 详情”三个标签页，默认标注页不变。本轮只改变笔记相关职责及关联数据的使用方式。

- 标注页仍列出全部标注，保留类型、排序、颜色提示和“仅有笔记”筛选，笔记状态通过关联查询获得；独立笔记不出现在标注列表。
- 笔记页上部是目录式树，下部是选中笔记的只读预览，使用可调整高度的现有或简单 QSplitter；工具栏只需新建笔记、新建分组及必要操作入口，重命名、移动和删除可放右键菜单。选中根/分组时显示名称及简要说明，不实现整组汇总。选中笔记时显示标题、关联状态、可用原文页码、Markdown 预览以及编辑、定位入口。
- 详情页仍以标注信息为主，已有标注样式编辑方式不变；不在右侧加入复杂源码编辑器或自动展开的大型编辑区。
- 使用现有正式程序的 MarkdownPreview/Renderer/MathRenderer 进行暂时预览；不连接 `demo/markdown` 源文件或依赖。

示意：

```text
┌──────────────────────────┐
│ 标注 | 笔记 | 详情         │
│ + 笔记  + 分组   更多      │
├──────────────────────────┤
│ ▾ 结构动力学              │
│   ▾ 单自由度体系          │
│       运动方程       P18   │
│     ▾ 自由振动            │
│         无阻尼振动    P31  │
│   阅读心得                 │
├──────────────────────────┤
│ 运动方程      [编辑]      │
│ 关联原文：第18页 [定位]   │
│                          │
│ Markdown 只读预览         │
└──────────────────────────┘
```

### 7.2 最小独立编辑窗口

为了本阶段可直接实际使用，需要提供一个简单且可替换的编辑窗口，而不是保留无法使用的模型接口。建议非模态 Qt 窗口，允许一边查看 PDF 一边编辑；同一时刻全程序只允许一个编辑窗口，重复打开相同笔记时激活已有窗口，切换到其他目标时先处理未保存草稿。只需标题输入、Markdown 多行文本输入、书名和关联状态、保存/确定/取消；可调整大小，遵循现有主题与字体。无需新渲染引擎、语法高亮、实时双栏或完整格式工具栏；右侧只读预览在成功提交后更新。正式编辑器留到 Phase 3.2。

编辑窗口必须绑定 `book_id + note_id`（新建时使用临时 ID 和创建上下文），不能依据主窗口当前选中标注或当前标签页提交。使用独立 draft：

- 新建时准备临时笔记、目标分组以及必要的定位标注/选区、待写附件；确认前不加入正式数据。若需要为用户显示定位点，可显示临时预览但不持久化。
- 已有笔记编辑时复制标题和正文。Ctrl+S/保存提交并继续编辑；确定提交并关闭；取消丢弃上次成功提交之后的修改；关闭未保存窗口时提示保存/放弃/继续编辑。
- 成功提交后更新正式对象与树，再调用会话保存机制。需要反馈真实保存状态：若磁盘写入失败，保留草稿及明确的未保存状态，不关闭或显示成功；处理重试不得重复创建对象或撤销记录。可通过先校验并执行统一事务后同步保存，或采用明确的会话 dirty/重试状态实现，避免 UI 的“保存成功”与实际写入混淆。
- 用户关闭原书籍、切换书库或退出应用时，应先处理该窗口的待提交内容；普通切换阅读标签不改变编辑目标。目标笔记/分组/标注已被删除或在编辑期间被外部撤销时，检测并提示，不得静默覆盖、重建或关联到其他对象。可通过限制编辑目标相关的冲突操作并给出提示简化第一版。
- 新建取消不能留下空 NotePoint、普通标注、正式笔记节点或错误关联；原有标注不受影响。区域截图/图片附件如需落盘，应延后至提交或使用临时区，取消仅清理本次草稿产生且未被引用的资源；不自动删除已有附件。保留已有已提交图片引用，路径必须属于该书资源目录。

### 7.3 创建入口及联动

四个入口使用相同的新建/编辑机制：树中新建独立笔记；已有标注添加笔记；文字或区域选区创建摘录笔记；PDF 点击创建定位笔记。复用当前已有 `noteRequested`、右键、浮动工具栏等入口，调整其语义与连接，不建立两套旧/新笔记操作。已有文字摘录/区域截图能力不能因模型分离而意外消失。仅保留现有功能所需的摘录与图片处理，追加到正在编辑的笔记、更多格式工具及剪贴板增强留待后续。

| 操作 | 预期行为 |
| --- | --- |
| 单击笔记树节点 | 只预览笔记，不改变 PDF 位置 |
| 双击有关联的笔记或点击定位 | 使用现有统一导航入口精准定位并选中对应标注 |
| 双击无关联笔记 | 保持阅读位置；可保持预览，不另设复杂窗口行为 |
| 点击 PDF 标注 | 保持当前位置，更新标注列表及关联笔记信息；不强制切换右侧标签或打开编辑器 |
| 标注页点击关联笔记入口 | 切换到笔记页并选择对应笔记，可主动打开编辑窗口 |
| 编辑期间翻页或选择其他标注 | 编辑目标不变 |
| 删除/解除关联 | 更新标注图标、筛选、预览、树与定位按钮；不错误跳转 |

用单向事件传递或必要信号屏蔽避免标注选中 → 笔记选中 → PDF 跳转 → 标注选中的循环。树操作与编辑提交不改变阅读视口大小或当前缩放。原文定位沿用当前 `navigateTo` 机制，保留页内锚点及现有历史语义。
