# PANO — Phase 0.1 阅读器与标注系统修复

> 项目：`pano-reader`  
> 阶段：Phase 0.1 / Reader and Annotation Stabilization  
> 基线：`main`，提交 `3d23ec22f78b646eb277b62bc5df418380c1cff3`（2026-11-27）  
> 文档性质：Demo 修复、技术验证与人工验收任务

## 1. 背景与开发目标

Phase 0 已建立 C++20、Qt Widgets、Qt PDF、xmake 工程，实现自主 PDF 阅读控件、标注对象、基本编辑、Markdown 笔记、独立 JSON 存储及异步页面渲染。仓库的 `docs/development/log/phase0-results.md` 记录了构建及部分探针验证结果，但真实桌面交互、扫描件、高 DPI、大型 PDF 等尚未充分验收。

实际使用中发现以下主要问题：

1. 多种标注的显示位置与实际操作位置不一致，整体明显偏上。
2. 滚动及缩放过程中，标注可能异常消失或重新出现。
3. 从笔记跳转原文时仅能定位到页面，不能定位到具体标注所在位置。
4. 旋转 PDF 后只改变了页面的宽高，页面内容未真正旋转，出现压扁、拉伸现象。

本阶段继续定位为技术验证，不启动正式产品功能开发。重点修复统一坐标变换、页面渲染、标注绘制与精准导航机制，并处理与这些机制直接相关的交互缺陷。完成后由用户进行真实文档人工测试，据此判断 Phase 0 是否可以收尾。

## 2. 开发约束

- 保留 Qt PDF、`QAbstractScrollArea + QPainter`、现有标注对象及 JSON 内嵌 Markdown 的技术路线，除非修复过程中出现可明确证明的技术阻塞。
- 原始 PDF 始终只读；视图缩放、滚动、旋转不改变其内容，也不改变持久化标注几何。
- 页面索引从 0 开始，标注采用页面 pt 坐标，左上原点、X 向右、Y 向下。这里的页面基准方向指 PDF 引擎正常显示的方向（已处理文档固有旋转及可见页面范围），不包含用户额外施加的视图旋转。
- DPR 只参与图像像素分辨率及必要的绘制设备转换，不进入持久化标注几何，不与缩放或滚动重复计算。
- 保留现有 `.pano` 数据目录、哈希绑定及保存机制，不引入新的书架数据模型。不得通过统一偏移现有 JSON 坐标掩盖显示错误。已有 Demo 数据如确有不一致，应备份并说明，不能静默改写。
- 尽量复用现有模块与探针，不进行大范围重构，不增加大量测试；开发过程不自行启动自动视觉检查或桌面交互测试，用户负责最终人工体验。

## 5. 核心技术修复

### 5.1 R01 — 统一坐标转换

保留 `PageLayout` 负责页面尺寸、连续布局及页面到内容坐标变换的职责。由 `PdfView` 或轻量辅助组件统一提供页面到视图、视图到页面、页内矩形或多边形映射等接口。无需为此额外建立大型抽象层。

Qt `QTransform` 的 `A * B` 对点的作用顺序为先 A 再 B。因此统一的页面到视图变换应等价于：

```cpp
QTransform PdfView::pageToViewTransform(int pageIndex) const
{
    return m_layout.pageToContent(pageIndex)
         * QTransform::fromTranslate(-horizontalScrollBar()->value(),
                                    -verticalScrollBar()->value());
}
```

反向变换由同一矩阵求逆，并处理非法页码及不可逆矩阵；也可使用经证明等价的分步计算。页面显示范围应与变换后的原始页矩形一致。避免直接在各工具内部拼接滚动、缩放和旋转矩阵。

检查并统一以下调用路径：PDF 图像、所有持久化标注、文字选区、荧光笔蒙版、临时绘制、选择边框、控制点、鼠标命中、拖动及缩放、笔记定位、鼠标坐标诊断。检查跨页、视口尺寸变化、滚动条范围变化和页间空白处的行为。

验证重点不是仅检查正反变换往返，而是检查原始页面四角及已知内部点实际映射到预期的显示位置。未旋转时四角应对应显示矩形四角；90°、180°、270° 时四角按旋转方向对应。非零水平与纵向滚动、非 100% 缩放必须覆盖。

### 5.2 R02 — 修复标注绘制与裁剪

使用 R01 的统一变换绘制所有标注。页面裁剪矩形与标注所在坐标系必须一致，裁剪应限制于对应 PDF 页面及视口，不得以取消裁剪来掩盖错误。选择框、控制点及定位图钉应与真实标注位置重合。

在文字标注中保留 `QPdfSelection` 提供的多边形、文字索引及文本内容。核对 Qt PDF 的选择坐标与标准页内坐标是否一致；如需适配，应集中在后端边界完成，而非对某类标注额外加偏移。文字选取及恢复必须在旋转视图下检查。

标注在原始页面图像异步加载、更新及缓存淘汰过程中保持独立，不因页面图像未就绪而删除或修改标注数据。若修正坐标后仍有异常消失，再排查可见页判断、重绘通知、绘制顺序、临时编辑状态和缓存；记录实际复现条件，不预先认定全部问题都由一个原因造成。

### 5.3 R03 — 真实旋转 PDF 页面

#### 5.3.1 目标与方案

用户旋转是对显示画布整体施加 90° 步进旋转，而不是修改 PDF、交换图像的目标宽高或对内容进行非等比例拉伸。

本阶段采用一条统一的实现路线：Qt PDF 始终提供未施加用户视图旋转的页面图像，自主阅读器使用统一的 `pageToViewTransform()` 同时显示原始页面、文字选区及标注。不要再同时引入 PDF 后端额外旋转，以免重复旋转。文档本身的固有旋转和可见页面范围由后端正确处理，必要时适配后端坐标，不得与用户旋转混淆。

#### 5.3.2 渲染像素尺寸

修改 `PdfView::pagePixelSize()`：使用 `m_layout.pageSizePt(pageIndex)` 作为基准，而非旋转后的 `pageSizeView()`。按实际缩放 s 与设备像素比 DPR 计算像素尺寸：

```text
widthPx  = originalWidthPt  * s * DPR
heightPx = originalHeightPt * s * DPR
```

若受最大像素数量或单边长度限制，使用同一个比例同时降低宽高，再取整；不得分别截断导致图像宽高比改变。保留合理的渲染分辨率上限。适应宽度、适应整页等缩放计算仍应使用旋转后的布局尺寸，两类尺寸用途不可混用。

#### 5.3.3 页面绘制

修改 `PdfView::paintPage()`，去除 `Q_UNUSED(pageToView)`。页面背景、边框、阴影可在视图坐标绘制；页面图像必须在原始页面 pt 矩形内使用统一变换绘制。例如核心逻辑：

```cpp
painter.save();
// 先在正确的视图坐标下设置页面裁剪，再应用页面变换。
painter.setClipRect(pageRectInView, Qt::IntersectClip);
painter.setWorldTransform(pageToView);
const QRectF pageRect(QPointF(0, 0), m_layout.pageSizePt(pageIndex));
painter.drawImage(pageRect, image);
painter.restore();
```

示例不替代对 QPainter 当前状态、DPR、源图像尺寸及裁剪行为的实际检查。原图与标注应共享同一个变换，避免一个使用旋转后的坐标、另一个仍使用原始坐标。

对宽 W、高 H 的基准页面，未缩放且未考虑布局偏移时，顺时针旋转映射应分别为：

| 用户旋转 | 页内点 (x,y) 的旋转结果 | 布局宽高 |
| --- | --- | --- |
| 0° | (x,y) | W × H |
| 90° | (H-y,x) | H × W |
| 180° | (W-x,H-y) | W × H |
| 270° | (y,W-x) | H × W |

检查现有 `PageLayout::pageToContent()` 是否满足上述约定，再通过缩放、布局、滚动得到视图坐标。不要仅靠交换宽高实现旋转。

#### 5.3.4 缓存与旋转交互

缓存继续保存未施加用户旋转的原始页面图像。同一文档、同一页、同一渲染像素尺寸可跨旋转状态复用；如果旋转导致适应宽度/整页比例变化，允许请求新的分辨率。不要仅为了旋转而清空全部缓存。

旋转前记录当前阅读锚点的页码和页内坐标，旋转后重新映射并尽可能保持其可见；受滚动边界限制时允许调整。连续四次顺时针旋转后应恢复原始方向，标注几何及笔记内容均不变化。

验收时使用含可辨别方向文字、圆形或正方形的非正方形页面，确保 90°/270° 下文字方向确实改变、圆仍为圆、正方形仍为正方形；180° 不能仅凭页面宽高判断。旋转后新建、选取、移动标注并恢复到 0°，验证原文与标注一致。另准备文档固有旋转的页面，防止双重旋转。

### 5.4 R04 — 精准原文定位

保留 `goToPage(pageIndex)` 作为单纯的页码跳转。新增或等价实现 `goToPosition(pageIndex, pagePoint)` / `revealPageRegion(pageIndex, pageBounds)`，使原文导航可以利用页内几何。

`revealAnnotation(annotationId)` 应查找并选中标注，获得其有效页内锚点或包围范围，再根据统一页面变换计算目标内容/视图位置及滚动偏移。定位点直接使用点坐标（核对当前 `p1` 与 `rect.topLeft()` 的一致性）；文字标注使用实际多边形范围；线条、路径及其他图形使用其有效几何范围，不依赖可能为空或不准确的缓存矩形。

默认保持当前缩放和旋转。目标已完整可见时不强制滚动；目标不在可见范围内时同时调整必要的水平及纵向滚动，尽量将其置于窗口中部并保留上下文；目标大于视口时优先显示起始或主要区域。考虑首页、末页及滚动范围限制，定位点或可见的目标区域必须实际进入窗口。跳转后使用选中轮廓等已有机制提示目标，不新增长期标注数据。

笔记列表、标注列表统一调用该导航接口。避免列表刷新或选择信号引发循环跳转、意外改变阅读位置。验收包括同一页顶部/中部/底部的多个笔记、高倍缩放下左右位置及旋转后的定位。

## 6. 相关交互与渲染收尾

### 6.1 R05 — 实时绘制预览

统一新建图形、自由路径、已有对象拖动与尺寸调整的临时状态。`DrawShape`、`DrawPath` 状态必须使用相同的标注渲染器实时绘制 `m_draft`；文字选区仍由选择预览机制负责，避免重复绘制。编辑已有对象时应隐藏旧位置、显示临时位置。释放鼠标后提交一次撤销命令，Esc 取消并恢复原状，不留下临时对象。切换工具、关闭文档时清理状态。检查鼠标释放的最终位置及页边界处理。

### 6.2 R06 — 荧光笔合成

保留正片叠底（Multiply）与普通混合（SourceOver）两种模式。同一笔画内部应作为整体合成一次，避免由于轨迹重复采样而反复叠加透明度；不同标注之间按实际绘制顺序合成。

优先将整页蒙版替换为笔画实际影响范围内的局部蒙版，考虑线宽、圆端点、抗锯齿边界，并与页面/视口相交后控制分配尺寸。局部蒙版使用页面到视图再到蒙版局部的统一变换，例如 `pageToView * Translate(-maskOrigin)`；高 DPI 下注意蒙版逻辑尺寸、像素尺寸及绘制位置的对应关系。也允许采用等价的整体路径填充方案，但必须保留单笔一次混合的效果。

确保 Multiply 作用于包含实际 PDF 内容的绘制目标，而不是仅对独立透明层执行混合。验证扫描文字、灰度及彩色内容上的效果；不以完全不改变彩色图像为目标。无需在本阶段建立复杂的标注图层缓存。

### 6.3 R07 — 工具预设

区分工具默认预设与实际标注样式。文字高亮、荧光笔默认采用正片叠底，普通图形与铅笔默认采用普通混合。用户选择的适用颜色、线宽、透明度及混合模式应直接用于创建新标注，不再通过创建时硬编码重新缩放线宽、限制透明度或覆盖用户选择。必要的数值合法性限制应明确且一致。

仅处理现有工具，不建立完整个性化预设管理系统。Shift 直线与水平/竖直吸附维持易用性；当前 45° 吸附与最初设计存在差异，可简化为近水平/竖直吸附、其他方向自由直线，或记录待人工体验确定的行为，不单独扩展设置界面。

### 6.4 R08 — 删除及附属笔记保护

普通无笔记标注可直接对象级删除。对于包含用户笔记内容的标注，至少提供明确的删除确认，取消时保留全部数据。可选择实现转换为定位点以保留笔记，但不是本阶段必须项。Delete、列表删除及橡皮擦等入口必须共用保护逻辑，撤销时恢复完整对象和笔记。

橡皮擦以对象删除为基础，不实现局部笔画分割。本轮可完善连续擦除，并将一次拖动视为一个撤销操作；如仍保留点击式擦除，应明确记录为 Demo 限制。不得为了连续擦除而绕过笔记保护。

### 6.5 R09 — 异步渲染与缓存检查

在坐标问题修复后检查快速滚动、缩放与文档切换行为。核对 `PageRenderer` 请求标识、文档切换后旧结果隔离、缓存键与实际图像尺寸是否一致。当前缓存命中路径中 `cachedImage()` 仅取值，`requestPage()` 才更新 LRU；应检查实际绘制命中是否更新访问顺序，避免名义 LRU 与实际行为不一致。

保留有限内存缓存。避免过时缩放请求导致队列长期积压，优先当前可见页面。在可行范围内使用已有分辨率图像进行缩放过渡，再异步更新高清图像，不能因过渡图像使用不同宽高比或方向而破坏标注位置。渲染失败应有可理解的提示，不进入无休止重绘/请求循环。

不要求本阶段实现复杂的预取调度、分块渲染或完整性能基准系统。只有实际发现明显问题时才继续优化；记录未实测的性能项目。

## 7. 验证方案

### 7.1 样本

- 仓库自带 `examples/sample-paper.pdf`：基本文字选择、标注、笔记、保存恢复。必要时另用包含圆形、方向箭头及四角标识的简单 PDF 验证几何；不要求建立大型样本库。
- 用户已有的扫描版专业书籍：验证无文字层的图形绘制、荧光笔与原文定位。
- 数百页原生或扫描 PDF：验证跨页滚动、缩放、缓存、笔记跳转。
- 如有条件，使用混合页面尺寸、PDF 固有旋转及高 DPI 环境补充验证。

### 7.2 必要代码与构建检查

优先利用现有 `pano-flow-probe` 或一个小型坐标检查验证关键数学关系，不为每个工具编写独立测试。坐标检查必须具有独立的预期结果，而非单纯检查矩阵与自身逆矩阵的往返一致性。至少覆盖非零滚动、非单位缩放和四种旋转下的页角点，并检查页内锚点转换。

完成必要的构建检查和非视觉逻辑验证；如本地 SDK 或工具链阻塞，记录实际命令和错误。不自行安排自动截图、视觉对比或 GUI 交互验证。此前已有的探针如果默认生成截图，不应为了本阶段擅自运行其视觉部分，可复用其非视觉检查逻辑。Windows 构建及高 DPI 真机验证视环境与用户安排进行，不宣称未经执行的检查已通过。

### 7.3 用户人工验收清单

| ID | 验收场景 | 通过标准 |
| --- | --- | --- |
| V01 | 页面上、中、下及不同页面创建文字和图形标注 | 绘制位置与所选文字或鼠标轨迹一致，控制点与标注重合。 |
| V02 | 50%、100%、150%、200% 下反复滚动、横向移动、缩放及跨页 | 标注与原文相对位置不变；应可见的标注不异常消失；离开视口后正常裁剪。 |
| V03 | 原生/扫描 PDF 依次旋转 90°、180°、270°、0° | 页面内容方向真实变化，宽高比正确，无压扁、拉伸；圆和方形保持形状。 |
| V04 | 旋转状态下选择文字、绘制及移动图形，再恢复原方向 | 图像、标注、文字选区及命中位置一致；恢复后几何正确，不出现重复旋转。 |
| V05 | 同页不同位置及跨页笔记，尤其在高倍缩放或旋转下跳转 | 准确显示目标标注/定位点，不只跳到页首；保持缩放与旋转。 |
| V06 | 绘制、移动、调整图形及笔画，Esc 取消 | 实时预览与提交结果一致，取消不产生数据，撤销重做正确。 |
| V07 | 扫描文字上的直线和自由荧光笔、不同颜色及混合方式 | 正片叠底不明显遮挡黑色文字，同一笔画内部没有异常重复叠色，样式与设置一致。 |
| V08 | 删除带/不带笔记的标注及撤销 | 关联笔记不会被无提示删除，撤销可完整恢复对象。 |
| V09 | 保存、关闭并重新打开 | 几何、样式、笔记准确恢复；PDF 哈希不变；不会因旋转或缩放改写标注坐标。 |
| V10 | 大文档快速滚动、缩放、旋转及切换文档 | 无明显渲染错位、旧文档图像混入、持续内存增长或无法恢复的空白页；记录观察结果及环境。 |
| V11 | 非默认 DPI 或系统缩放（如 125%、150%、200%） | 页面、鼠标、标注及蒙版仍一致；无对应环境则注明未验证。 |

V01–V05 是本次修复的核心人工验收条件，V09 是必须保留的数据安全条件。V06–V08、V10–V11 用于相关交互及技术方案进一步收敛。人工验收未进行前，只能说明实现已修改、待验收，不能据此冻结坐标及渲染契约。

## 8. 本阶段不开展的工作

不开发完整书架、引用/拷贝导入总数据目录、多文档标签、完整笔记树、OCR、全文搜索、PDF 导出、正式主题、安装包或发布系统。不扩充标注类型，不大规模改造自研 Markdown/TeX 渲染器；仅处理影响本轮验证的回归。暂不安排完整双页布局或复杂页面截图方案，若现有截图受坐标修复影响则保证已有行为不退化。

## 9. 交付与阶段结论

- 提交修复后的代码，保留原有构建入口；提交信息采用简短的 `fix:` / `refactor:` / `docs:` 等前缀。
- 在 `docs/development/log/` 增加简洁的 Phase 0.1 修复记录（建议 `phase0.1-results.md`），列明 R01–R10 的实际完成状态、重要修改、构建/非视觉检查结果、尚未验证事项及已知限制。不要将旧阶段记录改写为已经完成真实桌面验收。
- 记录最终采用的页面变换、原始图像渲染与旋转、精确导航、荧光笔合成方案；如与本文建议不同，说明依据和取舍。
- 提供用户可直接进行人工验收的构建及启动说明，不额外生成大量报告和测试文件。

本阶段不以功能数量作为成果，也不要求提前冻结正式版本的数据格式。只有关键坐标、旋转、标注显示、定位及保存恢复经过实际验证后，才考虑进入正式阅读器开发。若仍存在明显问题，优先继续收敛相关基础设施。
