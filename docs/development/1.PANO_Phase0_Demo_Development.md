# PANO — Phase 0 技术验证与 Demo 开发文档

> Page Annotation and Note Organizer  
> 项目及程序：`pano-reader`  
> 阶段：Phase 0 / Proof of Concept（PoC）  
> 文档性质：开发任务与人工验收依据

## 1. 开发目标

PANO 是一款本地优先、数据开放的 PDF 阅读与笔记软件，重点在于专业书籍阅读、自由标注和结构化笔记。项目参考 BookxNote 的阅读与笔记交互、SoloPDF 的数据开放理念，以及 Xournal++ 的图形标注能力，但不直接复用这些项目的实现代码。

本阶段不以完成可正式发布的产品为目标，而是实现一个可操作的桌面 Demo，通过实际编码和人工体验验证目前尚不确定的技术方案。重点回答以下问题：

- Qt PDF 能否满足原生及扫描 PDF 的阅读、渲染和文字选择要求？自主阅读控件能否在连续滚动和缩放时保持合理的性能？
- 页面、图像、视图坐标之间能否准确转换，标注在滚动、缩放、旋转和高 DPI 环境下能否保持位置一致？
- 文字标注与图形标注能否统一管理，能否完成对象选择、编辑、撤销及恢复？
- 正片叠底能否实现不明显遮挡文字的荧光笔效果，能否避免同一笔画内部反复混合？
- JSON 内嵌 Markdown 能否满足笔记保存、恢复和定位需求？Markdown 与 TeX 数学公式有哪些合适的本地渲染方案？

完成后，根据实际结果确定正式版本的技术架构。允许调整、简化或替换 Demo 中的实现，不要求提前设计所有正式功能。

## 5. PDF 阅读、页面布局与渲染

### 5.1 PDF 后端及阅读控件

使用 `QPdfDocument` 加载文档，获取页数、`pagePointSize()`、渲染图像和文字信息；使用 `QPdfPageRenderer` 验证后台渲染能力。

优先实现 `QAbstractScrollArea + QPainter` 的自主阅读控件。允许先用极小的 `QPdfView` 示例作为对照，但不要求维护两个完整阅读器。避免修改 Qt 源码或依赖 Qt 私有 API。若现有组件不足，应记录具体限制、可替代方案及代价。

基础能力：打开/关闭及切换文件、连续单页布局、滚动、页码跳转、适应宽度、自定义缩放，以及 90° 步进的临时视图旋转验证。不同页面允许具有不同尺寸；视图旋转不修改 PDF。无需保存原始书籍目录，也无需依赖 PDF 目录结构定位标注。

### 5.2 坐标系统

每页 PDF 作为逻辑画布，而非持久化位图。持久化坐标采用 point（pt），以未施加用户视图旋转的可见页面左上角为原点，X 向右、Y 向下，内部页索引从 0 开始。界面显示实际页序号（从 1 开始），不依赖书籍印刷页码。

程序维护三套坐标：页面坐标、渲染图像像素坐标、视口逻辑像素坐标。统一通过 `QTransform` 或等价机制处理页面布局、缩放、滚动及旋转的正逆变换。设备像素比 DPR 单独处理，不进入持久化几何。

必须验证 Qt PDF 返回的文字多边形、页面大小、渲染图像坐标对固有旋转、CropBox 的实际约定；不要未经验证就假定 API 坐标与原始 PDF 内部坐标相同。对特殊页面的适配应集中于后端/坐标转换层。

绘制、命中检测、对象控制点、截图和笔记跳转都使用同一套页面变换。图形操作限制在起始页面内，跨页文字选择暂不支持或明确拆分为单页对象，禁止生成跨页几何对象。

### 5.3 渲染和缓存

首先完成正确的同步渲染，然后验证 `QPdfPageRenderer` 的后台模式。只渲染可见及附近页面，按实际图像占用管理有限缓存（例如初始预算 128 MiB，可配置，不作为性能硬指标）。缩放时可先使用缓存图像，停止操作后更新高清图像。

渲染请求需记录文档代次、页面、目标图像尺寸、渲染选项和请求 ID。切换文档或快速缩放时丢弃不再有效的结果；避免大量过时任务积压。不要自行在多个线程中无约束地调用同一文档对象；遵循 Qt 的对象生命周期与线程接口约定。

缓存只保存不含自定义标注的原始页面图像。编辑标注不触发原 PDF 重新渲染。合成图像可作为临时结果，内存统计也应考虑合成缓冲及在途渲染请求，不能仅统计缓存条目数量。

## 6. 标注系统验证

### 6.1 对象与工具

工具负责创建对象，对象负责几何、样式和持久化，二者不必一一对应。铅笔和荧光笔共享路径几何，主要区别是工具预设。可使用简单结构体和 `std::variant` 等方式表达类型数据，不强制复杂继承或插件机制。

| 工具组 | 工具 | 本阶段交互 |
| --- | --- | --- |
| 基础 | 选择、拖动 | 选择标注、移动视图或对象，模式明确 |
| 文字 | 高亮、下划线、删除线 | 选中文字后创建，另支持浮动菜单入口 |
| 图形 | 直线、矩形、椭圆 | 鼠标拖动创建，支持移动、调整端点/边界 |
| 画笔 | 铅笔、荧光笔 | 自由绘制；Shift 直线、接近水平或竖直时吸附 |
| 画笔 | 橡皮擦 | 对象级删除，适用于所有标注类型 |
| 笔记 | 定位笔记、区域截图 | 页面点锚、关联 Markdown、截图资源验证 |

矩形、椭圆可修改边框与填充，直线和路径可修改颜色及宽度。第一版允许通过边界缩放自由路径，不要求逐个控制点编辑。Shift 直线允许任意角度，建议吸附阈值初始设为 10°（所有水平、竖直方向），由实际体验调整。一次鼠标按下到释放构成一个笔画或图形。

对象选择使用实际绘制几何，并考虑线宽和以视口逻辑像素表示的选择容差。重叠对象默认按逆绘制顺序命中。无填充矩形和椭圆应主要命中边界，而非整个包围盒。擦除使用同一几何检测机制，拖动经过多个标注时避免重复删除同一 ID。对附属笔记不得静默删除：Demo 可直接保留定位点并允许撤销，或提供确认。

### 6.2 文字标注

通过 `QPdfDocument::getSelection()` 获取选区，读取 `QPdfSelection` 的文字、起止索引和多边形边界；通过 `getSelectionAtIndex()` 验证恢复选区。记录实际 Qt 版本对索引端点和长度的约定，不假定字符串长度与 PDF 文字索引完全一致。

文字对象持久化时同时保存页索引、多边形、文字索引范围及摘录原文。几何坐标是长期显示与定位依据；索引用于同一引擎下重新选取和编辑。文字标注不能任意拖离原文字位置；Demo 可采用“重新选取范围”的方式更新。重新选择时同步更新全部文字及几何信息。

文字高亮应按每个选区多边形绘制，不能用整个选区的外接矩形代替跨行选区。下划线与删除线应从相应文字区域推导，验证普通横排文字，对旋转或特殊排版记录局限。无文字选区时不创建空对象，也不触发 OCR，图形与画笔仍正常工作。

### 6.3 混合绘制

所有适用标注支持 `normal` 和 `multiply` 两种混合模式及独立不透明度（0–1）。普通图形/铅笔默认 normal，文字高亮和荧光笔默认 multiply。创建时复制工具预设到对象属性，修改预设不改变已有对象。

绘制顺序为页面底图、持久化标注（默认创建顺序）、交互辅助信息。对普通混合与正片叠底采用 `QPainter::CompositionMode_SourceOver` 与 `CompositionMode_Multiply`。优先在包含原页面像素的 QImage 目标上进行合成（ARGB32 Premultiplied 等适合的格式），不能只在透明覆盖层中正片叠底后以普通方式叠放。

同一个荧光笔笔画应先形成整体覆盖区域，再一次混合至目标；可使用统一路径描边或离屏遮罩验证。连续鼠标采样段、自交区域不应因重复合成产生额外深色；不同标注对象的交叠允许自然加深。临时绘制预览与保存后渲染应一致。

### 6.4 撤销重做

优先采用 `QUndoStack` / `QUndoCommand`。创建、删除、移动、调整大小、修改样式、重新选取文字及增删附属笔记均应能够恢复对象状态和关联。一次拖动、笔画或连续擦除作为一个命令，不按鼠标移动次数记录。Markdown 编辑可按焦点使用文本控件的撤销机制；提交笔记内容时保证模型一致。Demo 不需要持久化撤销历史。

## 7. 笔记与数据存储验证

### 7.1 文件组织与范围

正式方案将使用统一数据目录，支持原 PDF 引用和拷贝导入，同一本书的标注与笔记独立于 PDF。本阶段只验证单本文档及其伴随数据，不开发书架和导入管理界面。建议允许用户指定测试数据目录，采用引用模式：

```text
DemoData/Book/
├── document.json       # 原 PDF 路径、文档 ID、SHA-256 等
├── annotations.json    # 按创建顺序保存标注及附属笔记
└── assets/             # 截图及图片等资源
```

拷贝模式只需验证相对路径解析不会破坏读写，完整的导入、迁移流程留待正式阶段。书籍目录名称不作为唯一 ID；同名文件、路径变更等不允许导致数据覆盖。标注前后原 PDF 的 SHA-256 应完全一致。引用文件不存在时保留所有数据，内容不匹配时给出提示并停止自动应用标注，禁止静默绑定到不同版本 PDF。

### 7.2 候选数据格式

以下是示意格式，允许根据 Demo 实现调整字段，不作为冻结的数据契约：

```json
{
  "schema_version": 1,
  "document_id": "demo-book-id",
  "annotations": [
    {
      "id": "demo-annotation-id",
      "page_index": 0,
      "type": "rectangle",
      "geometry": {"x": 100, "y": 160, "width": 200, "height": 45},
      "style": {
        "stroke_color": "#D94F4F",
        "stroke_width_pt": 1.5,
        "fill_color": null,
        "opacity": 1.0,
        "blend_mode": "normal"
      },
      "created_at": "2026-11-26T10:00:00Z",
      "modified_at": "2026-11-26T10:00:00Z",
      "note": {
        "title": "运动方程",
        "markdown": "## 基本假设\n\n$m\\ddot{u}+ku=0$"
      }
    }
  ]
}
```

实际对象 ID 应稳定且唯一；每个对象只属于一页，附属笔记可为空。自由笔记由定位点对象承载。文字类型额外保存文字范围及多边形，路径对象保存点序列。JSON 按创建顺序追加，采用固定格式缩进，编辑对象不改变其位置及创建时间。绘制顺序默认与创建顺序一致，未来可以独立维护；笔记树的组织顺序也独立于对象数组，暂不实现完整树编辑。

使用 `QJsonDocument` 等工具保存 UTF-8 JSON，优先采用 `QSaveFile` 原子写入。加载前校验 schema、ID、页索引、几何数据及文档关联；异常文件给出可理解的提示，不自动覆盖原数据。图片使用相对于书籍数据目录的资源引用，不在 JSON 中存储 Base64 大图。若截图已生成但 JSON 保存失败，保留资源供恢复，不主动删除用户数据。

### 7.3 笔记编辑、预览及原文定位

右侧使用 Markdown 源码编辑器和预览面板。验证标题、段落、强调、列表、表格、代码块、图片，以及行内 `$...$` 和独立 `$$...$$` 数学公式。Markdown 原文作为权威数据，预览不会反向覆盖或重新序列化原文。

可先使用 `QTextDocument::setMarkdown()` / `QTextBrowser` 验证基本 Markdown。Qt 原生 Markdown 不应视为已有数学公式渲染支持；另行评估本地 KaTeX/MathJax 与 Qt WebEngine 的组合，或其他轻量开源公式渲染方案。只需完成一种代表性可运行验证或记录明确的阻塞、替代方案与依赖成本；不必把所有方案都集成。不依赖 CDN 或联网才能显示公式，预览不应执行任意笔记脚本。

区域截图以原页面坐标选区映射到合适分辨率的图像，默认截取不含自定义标注的 PDF 内容；截图后插入相对路径 Markdown 图片引用。定位点、文字和图形标注的附属笔记均能通过列表跳转到页面对应区域。笔记树与排序的完整实现暂缓。

## 8. 开发组织建议

保持单仓库、少量清晰职责，不提前建设复杂 Application 层、插件系统、CLI 或多库体系。

```text
pano-reader/
├── xmake.lua
├── LICENSE
├── README.md
├── src/
│   ├── app/          # 主窗口、工具栏、属性与笔记面板
│   ├── pdf/          # Qt PDF 访问、渲染请求
│   ├── reader/       # 页面布局、坐标、缓存及阅读控件
│   ├── annotation/   # 模型、绘制、交互、编辑命令
│   ├── note/         # Markdown 编辑及预览
│   └── storage/      # JSON、资源与文档关联
└── docs/
    └── development/  # 本文及验证结果
```

目录仅是建议，按实际代码规模调整。避免仅为抽象而创建大量文件或接口。可按以下顺序完成：

1. 建立工程并完成 PDF 页面显示与坐标诊断。
2. 完成连续页面、缩放、渲染缓存和异步请求验证。
3. 实现图形/画笔标注、混合绘制、对象编辑及撤销重做。
4. 实现文字选取、文字标注并与统一对象模型整合。
5. 完成 JSON、定位笔记、Markdown、图片和公式验证。
6. 整理人工操作说明和技术验证结果，形成下一阶段选型建议。

## 9. 人工验证与验收计划

以用户本地人工使用验证为主。开发时只做必要的构建检查和少量关键逻辑检查（如获得授权的坐标变换、序列化或命令一致性测试），不建立大规模自动化测试体系，不自行启动 GUI 视觉检查；未经明确授权不运行额外测试。由用户执行以下场景，开发者提供操作步骤与必要的诊断输出。

### 9.1 文档样本

- A：普通可选文字 PDF，含跨行正文、数学公式及图片，数十页即可。
- B：无文字层的扫描 PDF，含黑白文字和图表，建议数百页。
- C：含不同页面尺寸、固有旋转或裁剪页面的 PDF；必要时用小型自制样本覆盖边界情况。
- D：大型实际专业书籍（约 500–1000 页或用户现有大型文件），原生或扫描均可。

同一文件可覆盖多个类别。使用用户有权使用的本地资料，不将受版权保护的整本书提交到公共仓库。必要的自制小样本可公开。

### 9.2 验收清单

| ID | 验证操作 | 预期结果 |
| --- | --- | --- |
| V01 | 打开 A/B，滚动、跳页、缩放、适应宽度 | 页面清晰，基本交互连续；扫描件不要求 OCR |
| V02 | 在固定图形边缘画框，切换 75%/100%/200%，滚动及跳回 | 框与原内容保持一致，几何坐标不变 |

| V11 | 新建定位笔记、附属 Markdown、公式及截图，列表点击跳转 | 原文定位正确，源码保存无损；公式验证结果或局限明确 |
| V12 | 保存、关闭、重开并加载 JSON；编辑既有标注 | 恢复页索引、几何、样式、创建顺序、笔记及资源；原 PDF 哈希不变 |

以上不是必须新增 14 个自动化测试的要求，而是人工验证场景。Windows 与 Linux 均应列为目标，未具备的环境明确标记未验证，不宣称已通过跨平台验收。

### 9.3 性能观察

提供简单的诊断界面或日志：实际 Qt 版本、页数、当前缩放和 DPR、渲染请求及耗时、缓存字节数、命中次数、待处理请求数，以及当前页面坐标。对 D 记录首次可见页面时间、连续滚动感受、高清缩放恢复时间及内存峰值；可重复少量典型操作，不需要专业基准测试框架。

本阶段尚无实测基线，不预先承诺固定 FPS 或耗时。验收以按需渲染、内存有界、交互可用、无明显持续卡顿及正确性为主，实际记录用于下一阶段确定量化目标。

## 10. 交付内容与阶段收尾

本阶段交付：

- 可通过 xmake 构建的 `pano-reader` Demo 源码及 MIT 许可证；记录实际依赖、构建方式和已验证平台。
- 简洁 README，包括启动方式、打开 PDF、标注、笔记、保存/加载和诊断操作说明。
- 一个可恢复的 Demo 数据样例（或自制样本生成说明），不提交大型私人书籍及用户数据。

收尾时重点给出五项判断：Qt PDF 是否继续采用；自主控件架构是否合适；坐标及文字定位契约是否可冻结；混合与对象编辑方案是否可靠；Markdown/公式和 JSON 存储是否适合作为正式基线。若某项未通过，应保留可复现步骤和原因，不通过临时规避手段掩盖问题，也不将未验证方案描述为已经成熟。

本阶段不要求达到完整产品效果，也不要求所有 Demo 代码均被保留。后续在用户完成实际体验后，再决定正式架构、功能范围及版本规划。
