## 1. 开发目标与范围

本阶段在现有独立笔记模型基础上完成专业 Markdown 编辑器，使 PANO 能够稳定进行文字、公式、表格和图像混合笔记的创建、编辑与阅读。右侧面板承担标注、笔记树及只读预览的管理职责，编辑操作在独立非模态窗口中完成。

在此之前，首先整理项目的构建组织，按实际依赖划分内部静态库，将功能探针和性能诊断目标从主项目配置中分离。随后修复 Phase 3.1 遗留的关联交互、工具栏、树状态、编辑草稿和跨模型操作等问题。各里程碑应能够独立构建、验证和提交，避免将结构调整与新功能故障混在一起。

### 1.2 冻结的设计及范围限制

- 保持 Annotation、Note、NoteTree 独立模型，以及 `annotations.json` Schema 2 中的三个数据集合；不变更数据契约、不重新引入旧版迁移或嵌入式笔记格式。
- 保持每本书内可选一对一关联，以 `Note.annotationId` 为持久化权威关系；不增加双份 JSON 关联字段，不支持多对多及跨书籍关联。
- 保持目录式笔记树（书籍、分组、笔记），通过点击创建、移动、排序；不开发拖拽、多选批量操作和思维导图视图。
- 保持当前阅读器三栏结构、标注类型、页面坐标体系及书库功能；不改动与本轮无关的 PDF 布局、渲染及算法。
- 不将整个项目迁移至 CMake，不引入 WebEngine、网络渲染、插件系统或通用应用框架；不追求所有目录各自构建为库。
- 不开发所见即所得编辑、可视化公式编辑器、多标签笔记编辑器、完整草稿崩溃恢复、笔记全文检索、子树/整书汇总、正式导出及跨书籍知识库。后续阶段另行安排。

## 2. 里程碑 A：工程组织及构建体系整理（B01–B03）

### 2.1 现状及目标

基准版本根 `xmake.lua` 定义 11 个非 Demo 可执行目标，其中仅 `pano-reader` 是产品程序。多个功能探针及 `pano-open-timing` 重复列出几乎全部正式源文件和 Qt 依赖。当前根工程还全局应用 `qt.widgetapp`，不适于进一步区分静态库和控制台工具。

本次应使根配置只保留项目级设置、公共构建约定、选项和子配置包含关系；正式程序、测试、诊断工具及 Demo 各有清晰的目标定义位置。默认配置只构建正式应用及必要库，验证工具按需启用。相同配置下正式模块的编译结果可被多个可执行目标复用，不再在各探针中重复编译同一套正式源码。

### 2.2 建议目标与依赖划分（B02）

根据基准代码引用关系，建议七个内部静态库。库划分应按职责和实际依赖确定，不机械按目录拆分。

| 目标 | 负责的代码 | 内部依赖（建议） |
| --- | --- | --- |
| `pano-common` | 共享数据类型、通用 JSON、时间、UUID、文件/路径工具 | 无 |
| `pano-pdf` | `PdfDocument`、`PageRenderer` | 按实际需要使用 common |
| `pano-annotation` | Annotation、Model、Commands、Geometry、Renderer、TextSelectionGeometry | common |
| `pano-note` | Note、NoteModel、NoteTree、MarkdownPreview、MarkdownRenderer、MathRenderer（后续替换） | common |
| `pano-library` | LibraryManager、LibraryStore 等书库与持久化逻辑 | common、pdf |
| `pano-reader-view` | PdfView、PageLayout | common、pdf、annotation |
| `pano-app` | app、document、settings（包括 BookmarkStore、会话、主题、工具预设） | 上述实际需要的库 |
| `pano-reader` | `main.cpp`、应用资源 | app |

依赖表是目标架构，不是未经验证即可直接照抄的链接配置。开发时核查每个模块完整的头文件与符号引用，精确声明直接依赖，确保构建 DAG 无环。必要的局部调整可以接受，但不得通过重复编译同一正式源文件、强制链接顺序或全量依赖所有库来隐藏循环。

特别处理以下边界：

1. `DocumentSession` 创建 `ReaderWorkspace`，后者又调用会话接口，存在双向依赖。现阶段两者放在同一 `pano-app` 静态库中，不为了拆库改造对象生命周期或将会话改成纯无界面模型。
2. `Note.cpp` 仅因 `nowIsoUtc()` 引入 `Annotation.h`。将通用时间及 ID 生成能力下沉或复用 `JsonUtils` 已有的公共函数，消除无必要的 Note → Annotation 依赖。核查现有 UUID、时间戳输出规则，保持文件协议和既有 ID 不变。
3. `LibraryTypes` 被存储、书库、阅读器和设置共同使用；将共享定义及必要实现下沉至 common（可保留原名称），使 `LibraryStore` 不再从构建层面反向依赖书库管理实现。`JsonUtils` 中无业务依赖的函数也归入 common，必要时保留小范围转发头，避免无意义的大范围重命名。
4. `SettingsManager` 使用 PageLayout 的枚举转换，`ToolPresets` 使用 Annotation，当前统一归入 app 可避免不必要的新依赖环。暂不单独拆 settings 库。
5. 核对旧 `NotePanel` 在正式程序中是否已无使用，确认无引用且不承担其他职责后删除。旧 Markdown/Math 渲染器等到里程碑 C 完成替换后清理；归档 Demo 不受影响。

实现时验证 `add_deps()` 的依赖传递及 Qt 组件、公共头文件路径、必要编译定义和链接配置的传播。局部配置中的相对路径必须以对应脚本目录或明确的根目录为基准（例如 `os.scriptdir()`），不得依赖当前执行目录碰巧正确。Qt MOC 所需的 `Q_OBJECT` 头文件须由所属目标处理一次，避免未生成或重复生成 MOC 符号。

应用 `resources/resources.qrc` 由实际使用资源的最终可执行目标负责注册；若选择资源库方式，须显式保证静态链接时资源注册不会被裁剪。确认图标、主题、窗口和测试截图正常。统一 MSVC 运行库、Qt ABI、架构、编译模式；Linux 保留适当 rpath。内部静态库不意味着 Qt 或 LGPL 第三方库必须静态链接。

## 3. 里程碑 B：Phase 3.1 遗留问题修复（A01–A06）

### 3.1 A01：完整双向关联及对象选择

现状：`DocumentSession` 已提供 `noteForAnnotation`、`annotationForNote`、`hasLinkedNote`，但 `NoteModel::forAnnotation()` 仍遍历笔记；标注列表显示笔记符号及标题，笔记树仅附页码，关联操作主要依赖 PDF 当前选中标注。

保持 Schema 2 单侧持久化，建立或完善内存中的 annotation ID → note ID 反向索引，并保证加载、创建、删除、关联、解除关联、撤销及恢复后同步。笔记 ID → annotation ID 直接由 Note 获取。所有关系变更必须使用统一会话业务接口，不由控件直接改字段。

| 操作 | 标注侧 | 笔记侧 |
| --- | --- | --- |
| 显示关联 | 保留类型、页码、摘录，另显示关联笔记标题及链接图标 | 保留标题，显示链接图标及关联页码 |
| 新建关联对象 | 新建关联笔记 | 可通过定位笔记/现有定位工具建立关联，暂不另做复杂选择模式 |
| 关联已有对象 | 打开笔记树选择对话框 | 打开标注列表选择对话框 |
| 查看关联对象 | 切换笔记标签、选中并展开对应节点 | 切换标注标签、选中对应项 |
| 解除关联 | 支持 | 支持 |
| 定位原文 | 支持 | 存在有效关联时支持 |

选择对话框使用真实对象 ID，不依赖标题、页码或当前另一窗格选中状态；同一书籍范围内只允许合法候选。已有关联不得静默覆盖。第一版可要求先明确解除旧关联再建立新关联；若提供重新关联，则要求确认并以单次事务完成。过滤条件导致目标隐藏时，应明确提示或调整过滤，使用户能实际看到被定位对象。

保持被动选择与主动定位的区别：单击笔记预览，不自动改变 PDF 位置；主动定位才跳转。点击 PDF 标注可以同步选择相关对象，但不强制反复切换标签或打断编辑器。独立笔记无定位按钮（或禁用），不产生虚假页码。用信号阻断或同步保护避免互相触发造成循环、跳页或草稿替换。

| 更多 | ellipsis | 两侧 |

补齐当前资源中缺失的必要 SVG；同一语义使用相同图标，不同操作不复用误导性图标。修复目前 `external-link` 同时用于移动和关联、`chevron-right` 同时用于上移下移的问题。保留 Tooltip、主题着色及正常字号；窄侧栏低频按钮收入更多菜单，不强制扩大最小宽度。

依据选中类型、关联状态及同级位置实时更新 enabled 状态。书籍根不能删除、移动或重命名；分组不能关联、编辑正文或定位；无关联笔记不能定位；同级首尾相应禁用上移、下移。删除及解绑遵守既定数据保护策略。

### 3.3 A03：目录式笔记树完善

显示真实的书籍根节点，以当前书名作为显示名（不新增持久化节点）。可在根或任意分组下新建笔记及子分组；选择普通笔记时新建同级。保留现有树结构和顺序，不引入复杂拖拽。

刷新前按节点 ID 保存选择、分组展开/折叠状态及滚动位置。更新后恢复有效状态；新建时展开必要父节点并选择新对象；删除时选择合理邻近对象。不再每次重建强制展开所有分组。继续使用 `QTreeWidget` 即可，无需为此更换完整 Model/View 实现。

“移动到”对话框显示根节点和可选分组的树，树项存储目标 ID，支持同名分组，不再通过显示字符串 `labels.indexOf(choice)` 推断对象。排除当前节点及其后代作为非法目标，并验证移动后整棵子树的最大深度。移动失败时保持模型及界面原状。

### 3.4 A04：草稿、正式模型与持久化

基准 `DocumentSession::saveNow()` 会调用 `commitPendingNote()`，导致其他阅读操作触发的自动保存可能提交正在编辑的草稿；`NoteEditDialog::saveInternal()` 在内存更新后即标记已保存，尚未确认磁盘写入结果。

统一约定：编辑窗口持有独立 `NoteDraft` 或等效编辑缓冲区；正式会话只包含已提交数据。普通会话保存、自动保存、PDF 标注变化及切换阅读标签不得隐式提交草稿。显式编辑器保存才进入提交路径。将提交和持久化的调用关系拆清楚，禁止 saveNow 反向调用编辑器保存造成递归或意外提交。

| 操作 | 行为 |
| --- | --- |
| 输入标题、正文或暂存附件 | 修改草稿，标记未保存 |
| 保存 / Ctrl+S（编辑器焦点） | 提交当前草稿并完成持久化，成功后保留窗口 |
| 确定 | 同上，成功后关闭 |
| 取消 | 放弃上次成功保存以来的未提交内容 |
| 关闭窗口 | 有未保存内容时提供保存、放弃、取消关闭 |
| 主窗口保存/自动保存 | 仅持久化正式数据，不提交草稿 |
| 持久化失败 | 不显示已保存，不关闭窗口，保留可重试草稿并提示原因 |

显式保存成功的判断以对应正式数据成功写入为准，而非只修改内存。保存失败不得留下错误的“已保存”状态、半完成关联或重复创建对象；优先在可验证的事务边界中预校验、暂存、原子写入后发布成功状态。若实现采用先更新内存再写入的方式，必须明确失败回滚策略（只回滚本次变更，保护其他已提交的阅读修改及撤销栈），或采用明确的待持久化状态并保证取消/重试语义一致。不得以丢弃草稿、跳过外部修改校验或覆盖旧文件来处理错误。

### 3.5 A05：非模态窗口的生命周期

- 编辑窗口绑定明确的书籍/会话 ID 与 Note ID，新建草稿持有预分配 ID；不得依据当前 PDF 选择项推断编辑目标。
- 重复打开同一笔记只激活已有窗口，不重新读取覆盖未保存草稿。尝试打开不同笔记时，如已有未保存草稿，先明确保存、放弃或继续原编辑。初版每应用只需一个活动编辑窗口（至少保证同一笔记不存在多个编辑副本），不实现多标签编辑系统。
- 切换书籍或正常阅读不会自动提交草稿；窗口仍属于原会话。关闭书籍或退出程序时先处理其编辑窗口；用户取消关闭时会话保持可用，保存失败不得释放草稿。信号连接和对象所有权须避免会话销毁后的悬空引用。
- 正文保存只更新本次编辑的字段，关联变更走专门接口，不从过期草稿覆盖最新 `annotationId` 或树位置。外部重命名、删除、撤销使当前目标变化时，应明确处理冲突；禁止静默复活已删除对象或覆盖更新内容。可采用阻止冲突操作并提示、或提交时比较编辑基线等简洁方案。
- 编辑窗口关闭清理统一走可靠的 finished/关闭路径（包括确定、取消、Esc、标题栏关闭和程序关闭），不可只依赖部分 `closeEvent` 中发出的自定义信号。主窗口 Esc 不应吞掉编辑器自身的正常键盘行为。

### 3.6 A06：定位笔记、失败回滚与撤销

当前 `PdfView` 创建 `NotePoint` 后即加入模型和撤销栈，再触发编辑窗口；取消后依赖部分关闭路径删除临时点。这与原先约定的一次性创建事务不一致。

新建定位笔记时，临时定位点、Note 和目标树位置一并暂存。可在 PDF 上显示临时预览，但不加入正式数据、持久化或撤销栈。用户首次保存时一次性建立 NotePoint、Note、关联和树节点；取消丢弃未提交对象。如果来源是已有标注，取消不改变该标注。由文字或区域选区产生的新标注同样明确待提交状态；不误删用户原先独立创建的标注。

完善 `DocumentSession::commitReadingEdit()` 及 `ReadingSnapshotCommand`：操作前校验，操作失败恢复原有标注、笔记、树及索引，不发送误导性成功通知、不形成无效撤销记录。重点检查 `NoteTree::moveNode()` 先修改父节点再检查深度的路径；对整棵子树校验，不只检查移动根的深度。删除标注及笔记当前分两次命令，应合并为单个用户事务。跨模型操作完成后只发布一致的最终状态，防止自动保存捕获中间状态。

| 操作 | 撤销/重做要求 |
| --- | --- |
| 创建定位笔记 | 一次命令恢复/移除标注、Note、关联及树节点 |
| 删除普通标注、保留笔记 | 一次命令恢复原标注及关联 |
| 同时删除标注和笔记 | 一次命令恢复两个对象及树位置 |
| 建立、解除或明确重新关联 | 一次命令恢复原关系及必要定位点 |
| 移动分组 | 一次命令恢复完整子树的父节点和顺序 |
| 无效操作 / 取消新建 | 不产生正式数据或撤销记录 |

继续遵守普通标注与笔记独立生命周期：删除普通标注默认保留笔记并解除关联；删除笔记默认保留普通标注；失去用途的 NotePoint 按既有特殊规则清理，保留笔记正文。带笔记的对象仍受连续橡皮擦保护。删除整个子树时明确确认影响范围，普通关联标注默认保留。附件不因撤销、删除正文或放弃草稿而误删其他已提交笔记引用的资源。

## 4. 里程碑 C：正式 Markdown 渲染模块（M01–M03）

### 4.1 M01：正式依赖集成

以 `demo/markdown/` 已验证实现及 `results.md` 为基础，正式采用 MD4C + JKQTMathText + QTextDocument/QTextBrowser。Demo 使用 MD4C 0.6.0、JKQtPlotter 5.0.0git20251013（按记录核查准确来源）；正式集成固定经过验证的具体版本或提交，不使用不受控的最新分支。

- MD4C 负责 Markdown 与数学片段识别；JKQTMathText 仅承担数学排版，避免引入无关绘图库。可通过 xmake 包管理或独立依赖构建获取，允许上游使用 CMake，PANO 本体保持 xmake。
- 依赖声明由 `pano-note` 或必要的统一依赖配置管理；使用同一 Qt SDK、架构、编译器 ABI、MSVC 运行库及构建模式。不得依赖开发者系统中偶然存在的 Arch 软件包名、固定机器路径或 Demo 临时依赖脚本。
- 默认正式应用从 C 起需要这些依赖；保持 Demo 开关独立，若两个目标使用同一依赖版本可复用包配置，但不共享正式与归档 Demo 的源码实现。
- Windows 检查 DLL 获取、链接和运行时部署；Linux 检查 SO/rpath 及系统 Qt 与独立 SDK 的一致性。文档给出可复现的依赖准备、配置、构建和运行步骤。
- PANO 继续 MIT。MD4C MIT；JKQTMathText LGPL-2.1-or-later，优先动态链接，记录版本、版权、许可证、依赖及相应源码获取方式。动态链接不是履行许可义务的充分条件，正式分发前仍需完整核查可替换库等要求。内部 PANO 静态库不改变第三方库的实际链接许可要求。

### 4.2 M02：统一渲染管线

保留现有 `MarkdownPreview` 等合理的对外接口或职责，内部由成熟库适配替代旧自研解析算法。侧栏只读预览、正式编辑器实时预览使用同一渲染实现，未来汇总阅读也复用。不要将 Demo 窗口和全部示例代码直接搬入正式程序。

Markdown 源文 → MD4C 解析（常用 GFM 扩展、数学片段识别、禁用原始 HTML）→ 普通富文本及公式资源 → QTextDocument → QTextBrowser。公式资源在内存生成，不进入书籍附件；Markdown 源文为权威数据，不存储渲染结果。

针对 Demo 局限：

- 处理 `$...$` / `$$...$$` 的正确边界，特别是独立公式中的单独 `=` 行被识别成 Setext 标题、代码块中 `$$` 被误统计等情况。优先使用解析库的事件/状态；必要时做小范围、识别代码和转义的预处理，不重新编写完整 Markdown 解析器。原始正文不可被预处理结果覆盖。
- 公式渲染失败应保留可读的原始 TeX 内容及非干扰性错误提示，不导致整个笔记空白或崩溃。明确不支持的环境，不追求完整 TeX 文档排版。允许简单、多行、矩阵、分段函数等专业公式的合理效果；未完全支持的语法应记录，不用旧解析器悄悄掩盖失败。
- 文档内链接默认不自动访问网络或执行外部程序；如提供普通外部链接操作，应由用户明确触发并限制允许的协议。现阶段不要求实现新的跨书籍内部链接协议。
- 所有书籍资源通过统一受限资源解析入口加载，默认只读合法 `assets/` 相对路径，拒绝绝对路径、盘符/UNC、路径穿越、符号链接逃逸、危险 URL 及未经授权的远程图片。校验规范化及真实路径位于允许目录内，考虑 HTML 实体/URL 编码后的路径；不能仅用 `contains("://")` 判断安全。限制图像解码及资源占用，损坏/缺失图片应显示占位和说明。外部本地图片通过明确导入动作复制到书籍附件，不允许渲染器直接读取任意文件。
- 新实现验证稳定后移除正式源码中已被完全替代的 Markdown/Math 解析逻辑，更新探针和依赖。保留归档 Demo 作为历史技术验证，不改写其原始功能。

### 4.3 M03：排版与性能

统一处理正文、数学公式、表格、代码块、图片和中英文混合的主题样式，保证浅深色主题、字号、DPI 变化后正确刷新。利用 JKQTMathText 返回的宽度、ascent/descent 等尺寸信息改善行内公式基线；可先验证 Qt 富文本对齐能力，确有必要再采用局部自定义对象。不为基线差异重新开发完整排版引擎。

根据实际预览 viewport 宽度计算布局：正文自动换行；图片等比缩放；过宽公式在可读性优先条件下缩放或支持横向查看；表格及代码块不得永久裁剪不可见。单独验证约 250–350 逻辑像素的侧栏，而不仅是宽窗口。监听 splitter 及实际 viewport 的变化，避免在连续缩放时产生过量重绘。

渲染使用适度防抖，建议起点约 300 ms；先测量实际完整渲染耗时（包含资源、Qt 文档布局和显示，不只计算公式）。如出现重复公式重绘开销，可使用有界缓存，键包含公式源码、渲染模式、字体字号、颜色、DPR 等实际影响因素，正确失效；不预先实施复杂缓存或后台线程方案。Qt GUI 和线程相关资源遵循其线程约束。

## 5. 里程碑 D：专业 Markdown 编辑器（E01–E04）

### 5.1 E01：窗口布局及编辑模式

在现有 `NoteEditDialog` 基础上完善独立非模态窗口（可改名 `NoteEditorWindow`，不要求仅为命名重构）。右侧笔记窗格仍为笔记树及只读 Markdown 预览，不重新放入正文编辑器。

```text
┌──────────────────────────────────────────────────────────┐
│ PANO — 编辑笔记                         最小化 最大化 关闭 │
├──────────────────────────────────────────────────────────┤
│ 标题 [                                              ]    │
│ 所属书籍 / 分组路径     关联状态：P18 / 无关联     定位原文 │
├──────────────────────────────────────────────────────────┤
│ 标题 粗体 斜体 列表 引用 代码 表格 公式 图片 链接   更多  │
│                               [仅编辑 | 分栏 | 仅预览]  │
├───────────────────────────┬──────────────────────────────┤
│ Markdown 源码             │ 实时只读预览                 │
│                           │                              │
│                           │                              │
├───────────────────────────┴──────────────────────────────┤
│ 未保存的修改 / 已保存 / 保存失败       取消  保存  确定    │
└──────────────────────────────────────────────────────────┘
```

使用可调整窗口、合理最小尺寸和 `QSplitter`；支持最大化。三种模式共享同一份草稿及编辑控件，不通过销毁重建丢失光标、选区、撤销历史或正文。默认分栏，可记忆本机窗口大小、分栏比例及编辑模式，不写入书籍数据协议。标题与正文分离，分组路径、原文关联信息只读显示；关联操作使用统一接口，不在草稿中隐式改关系。

保存、确定、取消及关闭完全遵守 A04/A05。窗口非模态且不强制置顶，用户可继续翻页、选择文字及截图。原文定位显式激活所属阅读器而不改变编辑目标；不同书籍的阅读操作不得错误插入到当前草稿。

### 5.2 E02：编辑工具与语法高亮

使用 `QPlainTextEdit` 或现有等效源码控件，提供轻量 `QSyntaxHighlighter`，不将高亮器作为 Markdown 渲染语法的权威解析器。覆盖标题、强调、引用、列表、链接、行内及围栏代码、数学片段等常见内容；正确处理基本的多行状态、代码块内的符号及浅深主题。

| 类别 | 第一版功能 |
| --- | --- |
| 文字 | 标题级别、加粗、斜体、删除线 |
| 段落 | 有序/无序列表、引用、分隔线 |
| 专业内容 | 行内/块公式模板、行内代码及代码块、简单表格 |
| 插入 | 本地图片、剪贴板图片、链接、PDF 文字与区域截图 |
| 编辑辅助 | 撤销重做、合理缩进、选区替换与快捷键 |

快捷操作应直接编辑 Markdown 源文，支持选中文本时包裹、无选区时插入合理模板并将光标放在适当位置；一次操作可由编辑器 Ctrl+Z 撤销，不触发整个阅读数据的撤销栈。保留原有换行和用户文本，不强制自动格式化全文。工具栏可使用菜单收纳标题级别、公式模板等低频功能；不做复杂富文本排版控件。

### 5.3 E03：实时预览及位置保持

用户编辑时仅渲染草稿，不提交正式数据。按防抖机制刷新预览，连续编辑时合并更新；仅编辑模式下可暂停不必要的预览渲染，切换回来补做一次。渲染前保存预览位置，优先恢复对应文本块或近似滚动锚点，不能每次输入都 `moveCursor(Start)` 或强制滚回顶部。切换主题、分栏宽度及字号时亦保持位置。初版不要求精确的双向源文/预览滚动同步，保持各自合理位置即可。

侧栏预览只显示正式保存的笔记（不读取未提交草稿）；显式保存成功后更新相应笔记树标题、关联标记和只读正文，不因刷新重置整棵树状态或改变 PDF 阅读位置。

### 5.4 E04：图片及原文摘录

支持从已有标注、PDF 文字选区、区域选区、定位工具和笔记树创建笔记，所有入口使用统一草稿编辑器。已有文字摘录默认可插入标准 Markdown 引用，区域截图生成图片链接，独立笔记/定位笔记正文可为空。来源页码为显示信息或用户可编辑的摘录文本，不增加新的持久化定位字段。

图片附件统一归入对应书籍 `assets/`；使用唯一、稳定的文件名和相对 Markdown 路径。支持文件选择导入和剪贴板图片；校验图片类型及大小，保留原始 PDF 只读。现有区域截图/文字提取能力应复用，不重写 PDF 渲染及坐标算法。截图生成使用现有正确的未旋转页面坐标转换规则。

附件与草稿生命周期：暂存尚未提交的附件，预览允许通过受限的草稿资源入口读取；正式提交时安全复制/移动至书籍附件目录并写入相对路径。失败保留可重试草稿，不写入缺失资源的正式引用；取消只清理本草稿独占的临时资源，不删除已有附件。若资源已先落盘，必须保证取消不会误删被其他数据或撤销记录引用的文件，并记录可回收的孤立资源，暂不实现全局垃圾回收。

本阶段至少保证创建笔记时能够使用上述来源，并允许通过编辑器插入本地/剪贴板图片。对于正在编辑的同一书籍，可复用现有选择/截图入口直接插入当前草稿（入口明确标明目标，不改变主要关联）；完整的“向已有笔记追加多个原文摘录”、来源链接组织及跨页摘录管理属于 Phase 3.3，不提前扩大关联模型。其他书籍的选择不得写入当前笔记。

## 6. 实施顺序及阶段交付

| 里程碑 | 实施范围 | 退出条件 |
| --- | --- | --- |
| A | B01–B03 工程组织与构建体系 | 正式程序、可选目标、模块依赖和现有探针正常；业务行为不变 |
| B | A01–A06 遗留问题修复 | 双向关联、工具栏、树管理、草稿、事务通过实际操作及针对性数据验证 |

先完成 A，再进行 B；B 稳定后再进入 C、D。建议 A 独立提交，B 形成独立修复提交；C/D 可按实际工作量分别提交。每个里程碑完成后进行最小必要验证，再继续后续工作。提交信息遵循 `refactor:`、`fix:`、`feat:`、`docs:` 等简洁约定。若正式依赖跨平台集成遇到阻碍，应保留已完成的 A/B 并记录阻碍，不通过恢复重复编译或引入自研解析扩展绕过问题。
