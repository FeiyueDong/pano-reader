# PANO Phase 2.2 — 阅读器稳定化与回归修复

> 开发性质：已有功能修复、交互稳定化与针对性回归验证  
> 项目：`pano-reader`  
> 分析基线：`107d5b3cd62d310af39de664258979542193a8c6`（`update ui`，2026-11-28）  
> 实施基线：开始开发时的最新提交及当前工作区，以实际代码为准。

## 1. 背景与目标

Phase 2.1 已完成阅读器顶部工具栏重组、左侧文档导航、右侧标注与笔记窗格，并完善了全屏按钮、对象橡皮擦、页面布局控制、翻页控件及搜索面板。当前的功能范围和总体界面组织基本合适，不需要再次进行大范围重构。

本阶段根据 Windows 实际使用反馈及静态代码检查，集中解决以下问题：

1. 非连续单页、双页布局下仍无法可靠地通过滚轮翻页。
2. 铅笔、荧光笔丢失 Shift 直线绘制能力，影响已有直线式笔迹编辑设计。
3. 全屏可以通过 F11 和按钮退出，但 Esc 无法可靠退出。
4. 标注工具切换时，上下文属性栏高度变化导致阅读区域移动或缩放。
5. 缩略图列表中远处页面持续空白，需点击对应页后才生成。

同时处理代码检查发现的关联缺陷：普通翻页与视口滚动的语义混淆、不透明度提交不完整、全屏与查找面板的状态恢复、搜索结果计数和操作提示不一致。

本阶段不新增阅读器功能。大型 PDF 打开时的主线程阻塞已经有初步测量依据，可在不降低数据安全的前提下尝试低风险优化，但不作为核心修复的前置条件。最终目标是让当前已有功能稳定可用，为 Phase 3 专业笔记系统开发建立可靠基础。

## 4. 里程碑 A：核心交互修复

### 4.1 R01 — 非连续布局滚轮翻页

**问题与代码依据**

`SettingsManager` 已将 `wheel_turns_page` 的缺省值调整为 `true`，但旧配置显式保存的 `false` 仍会生效。`PdfView::wheelEvent()`（基线约 L1344–1399）以 `!m_wheelCooldown.isValid()` 判断是否允许翻页，首次成功后调用 `start()`；`QElapsedTimer` 启动后不会自动失效，因而可能只成功翻页一次。当前也未真正落实方向变化时清除累积量，且普通鼠标和高精度触控板的增量单位混用。

**实施要求**

1. 保留现有滚轮翻页设置，默认开启；旧配置明确为 `false` 时仍按禁用处理。开发验证应先检查测试书库对应应用配置的实际值，并通过设置界面显式开启后测试。无需删除配置、重置整个应用或新增迁移协议。确认设置应用后所有已打开阅读会话以及新会话均使用正确值；若当前“应用”按钮不通知会话，补齐通知，不必重构设置系统。
2. 修复冷却逻辑，使冷却结束后可以再次翻页。以下为概念性写法，具体可按当前代码简化：

```cpp
const bool cooldownReady = !m_wheelCooldown.isValid()
    || m_wheelCooldown.elapsed() >= 250;
```

3. 不用同一个无单位阈值混合累计 `angleDelta()` 和 `pixelDelta()`。普通鼠标优先按滚轮刻度处理；高精度滚轮/触控板按实际增量积累、滚动方向及手势阶段处理。冷却初值建议 250 ms，仅用于抑制重复或惯性触发，不应吞掉正常间隔的连续翻页。方向改变、手势结束、离开边界、切换文档或布局时清理适当的累积及冷却状态；冷却期间不积攒会在下一次手势中突然触发的旧增量。
4. 若页面能够垂直滚动，先进行页内/组内滚动，抵达边界后继续同向滚动才翻页。整页或整组可见时无需额外等待滚动空间。注意滚动条最大值为 0 或因取整出现极小范围时的处理，避免视觉上适页却无法翻页。
5. 非连续双页使用真实 `spreadPages()` 的页组首尾确定相邻组，覆盖首页单独、末尾单页及目标位于组内另一页的情况。不得直接将当前页加减 1 代替翻组。
6. 向下翻页进入目标页/组顶部，向上返回目标页/组底部。首尾停止，不循环翻页。成功翻页才开始冷却；失败或已到边界不能锁死下一次反方向操作。连续模式保持原有滚动行为；Ctrl+滚轮缩放、Shift+滚轮横向滚动优先，不触发普通翻页。
7. 滚轮翻页复用统一导航和阅读状态更新，不写入主动跳转历史，不影响选中对象、标注内容、原 PDF 或撤销栈。

| 模式 | 无页内滚动空间 | 有页内滚动空间 |
|---|---|---|
| 单页 | 一次有效滚轮操作切换相邻页 | 先滚动，抵达边界后翻页 |
| 双页 | 切换相邻双页组 | 先组内滚动，抵达边界后翻组 |
| 连续单页/双页 | 正常连续滚动 | 正常连续滚动 |

验收不能只发送一次滚轮事件。至少连续前进 10 次、反向返回 10 次，并覆盖第二次成功翻页、冷却期结束、快速反向、关闭/重新开启设置等情况。触控板不可用时标记未验证，而非推定通过。

### 4.2 R02 — 恢复 Shift 直线绘制及修饰键响应

**问题与代码依据**

`PdfView::updateDraw()`（约 L2347–2405）将 `m_draft.path` 赋为 `m_drawRawPath`，Shift 时仅在自由路径末尾追加吸附点，而不是生成完整直线；`finishDraw()`（约 L2407–2443）又无条件将有效路径覆盖为原始鼠标路径。`keyPressEvent()`、`keyReleaseEvent()` 仅在 `DragMode::DrawShape` 下对 Shift 变化重算预览，没有覆盖 `DrawPath`。

**有效几何与原始路径分离**

- `m_drawRawPath` 只保存本次手势实际采样点，按现有合理的采样间距记录；即使 Shift 按下也保留鼠标轨迹，不能把吸附点写回原始采样路径。
- `m_draft.path` 是当前有效预览几何。Shift 未按下时使用原始自由路径；按下时使用固定起点与吸附终点构成的两点路径。
- 维持当前的方向吸附策略（水平、竖直及已支持的 45° 方向），不新增复杂约束或分段折线工具。吸附终点应在页面边界内；必要时沿约束方向截断，而不是逐坐标裁剪破坏角度。
- 释放鼠标时使用释放事件的最终坐标及修饰键状态重新计算有效预览，随后直接验证并提交有效几何。不要在 `finishDraw()` 再次用原始路径覆盖，不要把键盘释放与鼠标释放顺序混为一谈。

```cpp
// 概念示例：采样、预览和提交应由同一个手势状态控制。
if (shiftPressed) {
    m_draft.path = {m_dragStartPage, constrainedEnd};
} else {
    m_draft.path = m_drawRawPath;
}
// 根据有效路径更新边界并绘制；提交时保存该有效路径。
```

**修饰键及编辑要求**

- 优先使用鼠标/键盘事件传递或明确维护的 Shift 状态，避免仅依赖全局 `keyboardModifiers()` 的时序。按下、释放 Shift 且鼠标不动时也应刷新当前草稿；自动重复按键不得产生新的笔迹。
- 在绘制前按住 Shift、绘制中途按下 Shift、绘制中途释放 Shift、再次按下 Shift 四种情况均正确。松开 Shift 后恢复此前采集的完整自由路径；最终几何以鼠标释放时有效状态为准。
- 直线式铅笔/荧光笔保持原类型和样式，路径仅两个有效端点，延续原有端点编辑能力；自由路径仍支持包围盒移动和缩放。图形缩放保持线宽独立，不改变笔迹样式。禁止新增“直线荧光笔”标注类型或修改 JSON 协议。
- 直线、矩形、椭圆、对象端点调整、等比例缩放的 Shift 约束继续正常；确保正方形/正圆不发生回归。保持当前页面坐标体系与旋转变换。
- 有效路径边界、退化几何检查及命中检测沿用 `AnnotationGeometry` 等既有机制，确保零长度、水平/竖直、页面边缘笔迹正常处理。取消操作时清空原始路径和草稿，不写入模型；一次完成绘制只产生一次撤销操作。

验收时不能只观察绘制过程的直线预览，还必须检查鼠标释放后、撤销重做后和关闭重开后保存的笔迹形状及端点数。

### 4.3 R03 — 统一 Esc 事件处理与全屏退出

**问题与代码依据**

当前有三个 Esc 处理入口：`MainWindow::eventFilter()`（约 L1115–1129）、`ReaderWorkspace` 构造时注册的 `QShortcut`（约 L175–180）以及 `PdfView::keyPressEvent()`。工作区快捷键只处理临时状态/工具切换，并不请求退出全屏，可能在普通 `KeyPress` 到达全屏事件过滤器之前已消费事件。`ReaderWorkspace::closeTransientUi()` 与 `PdfView::handleEscape()` 也存在职责重叠。具体 Windows 快捷键分发需实际验证。

**统一行为**

| 当前状态 | Esc 行为 |
|---|---|
| 正在绘制、拖动、缩放或擦除 | 取消未提交操作，清除草稿/预览，返回默认选择；不退出全屏 |
| 专用工具（包括抓手），无正在操作 | 返回默认选择工具；不退出全屏 |
| 默认选择，存在文字/区域选区或已选对象 | 清除临时选择及浮动工具栏；不退出全屏 |
| 默认选择，存在正在使用的临时查找界面 | 按查找关闭规则处理，恢复正常/全屏阅读布局 |
| 默认选择，无任何待取消状态，处于全屏 | 退出全屏 |
| 默认选择，无待取消状态，普通窗口 | 不执行额外操作 |
| 模态对话框、弹出菜单、输入控件 | 优先遵循其原生 Esc 行为，不误退出全屏或丢失正文 |

其中，全屏专用工具下第一次 Esc 返回选择，第二次 Esc（无其他待取消状态）退出全屏，是本次必须满足的用户操作。不要以已保存搜索关键词、历史记录或隐藏的面板作为无限阻止退出的临时状态。

**实施要求**

- 建立唯一的阅读器级 Esc 分发入口，允许由 MainWindow 窗口级快捷键/受控事件处理调用，具体选型以 Qt 实际事件行为为准。不要同时注册多个独立 Esc 快捷键并依赖其优先级。`PdfView` 和 `ReaderWorkspace` 继续提供返回是否真正处理了当前交互的能力；`MainWindow` 保持唯一全屏状态控制者。
- 先取消未提交事务，再切换工具；不能先改变工具导致正在编辑对象的状态丢失或误提交。一次 Esc 只执行一层逻辑，长按 Esc 不得因自动重复意外连续退出。
- 确保焦点在画布、工具栏、右上角退出按钮以及正常可用的侧栏时都能正确处理；针对输入控件及模态窗口适当限定快捷键范围，避免全局事件过滤误处理其他窗口。F11、顶部全屏按钮、退出全屏按钮和菜单仍共用现有切换入口，保持已修复功能。
- 保存和恢复正常面板布局，并维持退出时实际阅读位置，不拉回进入全屏前的位置。全屏临时状态不得写入正常界面配置。搜索面板的特殊情况与 R09 统一处理。

### 4.4 R07 — 区分普通翻页与视口滚动

当前 `PdfView::navigatePageStep()` 在连续布局下执行约 90% 视口高度的滚动。应核查 `ReaderWorkspace::goToPreviousPage()`、`goToNextPage()` 等入口是否直接复用了这一语义，并明确区分实际翻页与 PageUp/PageDown。

| 入口 | 连续布局 | 非连续布局 |
|---|---|---|
| 上一页/下一页按钮 | 定位相邻页或双页组 | 切换相邻页或双页组 |
| PageUp/PageDown | 按约一个视口滚动 | 切换相邻页或双页组 |
| 普通滚轮 | 连续滚动 | 按 R01 页内滚动/翻页 |
| 页码输入 | 精确定位指定页 | 精确定位指定页所在组 |
| 历史前进/后退 | 恢复历史锚点 | 恢复历史锚点 |

建议复用共同的目标页组计算，独立明确视口滚动入口，不必引入新的公开数据结构。首尾按钮禁用条件按页/页组而非仅当前页码计算，连续双页避免在同组重复停留。按钮普通翻页不写入历史，页码输入和目录、搜索等显式定位保留历史语义。混合尺寸及旋转后应正确更新滚动范围、当前页和页码控件；输入框及笔记编辑器保留自身按键行为。

## 5. 里程碑 B：界面稳定及状态修复

### 5.1 R04 — 稳定上下文属性栏高度

`ReaderWorkspace::buildContextToolBar()`（约 L758–889）和 `updateContextToolBar()`（约 L1866–1958）根据工具与选中对象显示/隐藏 QLabel、颜色按钮、SpinBox、ComboBox、Slider 等控件。各控件 sizeHint 不同，现有属性栏没有稳定的纵向尺寸约束，切换内容时可能改变整个阅读区域高度，进一步触发适页/适宽重算、位置移动和渲染请求。

**目标**：在相同主题、字号、DPI、窗口和侧栏尺寸条件下，切换任意标注工具、选中/取消对象或更改属性值，属性栏占用高度及 PDF 视口尺寸不变。

```text
普通选择：  [选择对象后调整样式                    ]
荧光笔：    [颜色] [线宽] [不透明度] [混合]           同一行高度 H
矩形：      [颜色] [填充] [线宽] [线型] [透明度] ...
橡皮擦：    [提示] [半径]                            
---------------------------------------------------
PDF 视口：  顶部位置、宽度及高度保持一致
```

- 根据当前字体、主题、样式边距和所有实际属性控件的合理 sizeHint 计算统一行高；可使用固定高度容器、统一尺寸策略或等价方案。不要硬编码只适合当前 Windows 字号的高度，也不要将隐藏控件的 sizeHint 误算为零。
- 普通选择即使没有可编辑对象，也保留该行空间，以提示或空白替代控件。可用控件按功能显示，不要求所有属性永久可见。
- 字体、主题或 DPI 改变时重新计算统一高度；同一次外观变更应合并布局刷新。窄窗口沿用现有横向收纳/溢出机制，不允许上下文控件自动换成额外行，也不能裁掉需要操作的属性。主工具栏的首页单独显示选项变化同样不应造成意外高度波动。
- 全屏整体隐藏属性栏是明确的布局切换，仍可按现有锚点机制适配；退出后恢复正常行高。
- 不通过每次工具切换后强行恢复缩放数值掩盖问题，应消除不必要的视口尺寸变化。验收记录切换前后实际 `viewport()->size()`、缩放比例及页面位置，结合截图或实际观察确认。

### 5.2 R05 — 缩略图可见范围及按需请求

**问题与代码依据**

`ReaderWorkspace::requestNearbyThumbnails()`（约 L1226–1248）使用列表左上角 `(2,2)` 和左下角 `(2,height-2)` 的 `indexAt()` 推断可见页范围。这些点可能落在居中缩略图的边缘或行列间隙，导致退回阅读页前后少量页的范围。若远处检测点有效，当前做法还可能将阅读页与列表可见页之间的所有页面都加入请求范围。列表滑到远处后存在空白或无意义的请求队列。

**实施要求**

1. 主依据改为缩略图列表自身视口与条目实际矩形的相交关系。可使用 `QListWidget::visualItemRect()` 等已有 API 获取可见项；初期允许对数百页列表做轻量遍历并测量开销，不必改用虚拟模型。考虑顶部/底部部分可见、单列、多列、间距、旋转和垂直滚动条宽度。未完成列表布局时，待布局稳定后再调度，不将无效检测点当作无可见项。
2. 请求集合为实际可见页及少量邻近预取页，可附加少量当前阅读页附近请求，但两者距离很远时不能请求整个中间区间。优先可见项，再预取；限制每批请求数量及重复请求。即使 PDF 当前阅读页不变，缩略图列表滚动到第 400、800 页也应正常加载。
3. 在列表滚动、实际 viewport 尺寸变化、侧栏宽度变化、页面标签切换/重新显示、文档切换和旋转后可靠调度。可使用现有计时器合并快速事件，但不能因不断滚动或渲染回调持续重置计时器而长期饥饿；停止滚动后及时加载，并避免重入。面板隐藏时不继续扩大请求队列。
4. 保留自适应单列/多列布局、选中页提示及原比例显示。缩略图滚动本身不改变 PDF 阅读位置；点击某一项才主动定位。阅读区主动翻页时可同步滚动当前页缩略图，但不能由渲染完成事件触发跳转。
5. `QListWidget` 可继续使用。此轮优先保证正常可见项完整显示，不要求全面重写缩略图模型或全书缓存策略。

### 5.3 R06 — 缩略图缓存和失败状态闭环

**问题与代码依据**

- `PageRenderer::requestPage()` 缓存命中时返回 0，不再次发出 `pageReady`；而 `refreshThumbnails()` 会清除 `m_thumbGenerated`、`m_thumbRequests` 并重建占位项。同一个文档对象再次调用 `setDocument()` 不会清除底层缓存，旋转或重建列表后可能命中缓存却仍为空白。
- `PageRenderer::onPageRendered()` 收到空图像时会清理内部 pending 后直接返回，外部 `m_thumbRequests` 可能永久保留对应请求。`onThumbnailRendered()` 仅在请求存在且 ID 不一致时拒绝结果，缺少明确代际/生命周期判断。

**建议状态模型**

```text
未显示 -> 检查缓存 -> 命中：直接显示 -> Ready
                   -> 未命中：提交请求 -> Pending
Pending -> 成功：生成缩略图、清除 pending -> Ready
        -> 失败：清除 pending、有限重试或失败占位 -> Failed
        -> 过期/文档关闭：丢弃结果、清理对应状态
列表重建 -> 复用有效缓存/重新提交，不依赖旧 pageReady 信号
```

- 缓存检查与实际填充复用同一显示方法，正确处理请求返回 0 的缓存命中、无效请求等不同情况；不以 0 一律表示“已经显示”。先确认非空缓存后更新图像；成功显示才标记 generated。
- 将渲染失败及取消作为明确结果传递给调用方（可增加轻量内部信号或等价状态通知，不需引入新模块），清理相应请求状态。仅对仍有需要的可见页有限重试（建议最多 1–2 次，间隔重试）；持续失败时保留可辨识的失败占位及再次进入时的合理重试入口，不无限循环。对主阅读区同类 pending 遗留问题顺便核查，若存在等价缺陷一并修复。
- 文档关闭、切换、刷新或渲染代际变更时，按文档身份、页码、目标尺寸、请求 ID/代际核对回调。过期结果不得覆盖新文档或新尺寸缩略图。若缓存存放的是未旋转源图像，旋转只作用于显示阶段；同一文档旋转后可以复用合法原图，不能将已旋转结果再旋转一次。
- 保持真实 PDF 页面宽高比，考虑横向及旋转页；当前 `QSize(160,220)` 请求为固定尺寸，应核查底层是否拉伸，必要时根据页面比例计算目标栅格尺寸，而不是只在最终显示时调用 `KeepAspectRatio`。
- 明确共享占位图和生成图标的生命周期。R06 需要可靠状态闭环；更大规模的内存上限/模型优化归入 P02，不要求此次全部重构。

### 5.4 R08 — 属性修改即时提交与目标绑定

当前 `m_opacitySlider::valueChanged` 只更新百分比文字，而样式提交依赖 `sliderReleased`。通过键盘、滚轮或点击轨道调整时，可能不会发生 release 信号，形成显示值与实际样式不一致的问题。

- 不透明度的有效数值变化接入与线宽等控件相同的预览/防抖提交逻辑，覆盖鼠标拖动、点击轨道、键盘方向键及滚轮。连续调整可合并撤销命令，结束后确保最终值提交；不要让每个滑块步进都生成独立撤销操作或同步磁盘写入。
- 切换工具、选中对象、切换文档、保存及关闭时，按原有目标绑定机制处理待提交值：用户已确认的更改应提交到原目标，已取消的临时操作应恢复。不能因为延迟计时器尚未触发而错写新对象或新工具预设。
- 从对象/预设向控件同步数值时使用既有信号阻断或更新保护，不得反向触发编辑、撤销命令或保存。默认选择状态无对象时不修改无关预设。
- 检查颜色、填充、线宽、线型、混合方式的既有即时提交行为，保持本阶段仅修复不一致路径，不重新设计属性系统。

### 5.5 R09 — 全屏与查找面板状态恢复

`ReaderWorkspace::setFullscreenMode()`（约 L2685–2729）仍单独 `hide()` 已迁移至左侧标签中的 `m_searchBar`，退出时仅恢复侧栏，可能使活动查找页不可见。`openSearchPanel()` 又可通过 Ctrl+F 在全屏中主动显示左侧栏，两条路径需要统一。

本轮建议：允许全屏 Ctrl+F 临时显示查找面板（不新增独立窗口）。如果现有实现必须较大改造才能支持，允许采取“先正常退出全屏，再打开查找”的简化方案，但须明确记录实际选择，并保持快捷键行为一致。

- 正常全屏切换只隐藏父面板，不额外永久隐藏其查找子页；记录正常模式下的面板可见性、尺寸与当前导航标签。恢复时不清除有效搜索词、匹配结果、当前结果或阅读位置。
- 若采用全屏内查找，Ctrl+F 显示临时左栏并聚焦输入；关闭查找或 Esc 关闭活动查找后恢复全屏画布，后续空闲 Esc 退出全屏。不得修改正常模式的侧栏持久化设置。
- F11/退出按钮在临时查找中也应有效，退出后恢复正常面板状态，搜索会话状态按现有规则管理。搜索隐藏但保留结果时，不得因不可见的查找控件阻止 Esc 退出。
- 搜索防抖计时器、结果列表、查询字符串、临时高亮应共同清除或保留；关闭搜索后旧计时器/回调不能重新产生已清除的高亮。复用已有搜索模型，不新增搜索功能。

### 5.6 R10 — 搜索计数和提示一致性

`refreshSearchResults()` 已设置最多 4000 项结果的展示限制和 `shown/total` 提示，但 `QPdfSearchModel::statusChanged` 的 Finished 分支会再次覆盖计数。应使一个入口负责最终计数，搜索中、完成、无结果及结果截断提示准确。确保当前结果索引和上一项/下一项操作只在可导航的有效结果范围内，查询变化时不会操作旧结果。

本轮保留搜索结果上限，不新增分页、全书索引或复杂的逐步结果加载系统。若能低风险改善现有状态更新则可实施，但不作为额外功能。无文字层扫描件提示应表达“没有匹配文本，可能没有可搜索文字层”，不要把未匹配等同于必定没有文字层。

橡皮擦实际行为为跳过带有笔记的标注，而属性栏提示仍描述为“会先确认”。统一修改为“按住拖动连续擦除；附有笔记的标注将被跳过。”继续保留显式删除的确认机制，确保提示符合实际操作。核查本轮涉及的翻页、Shift、Esc 快捷键提示，更新不一致文字即可，不开展全面翻译。

## 6. 里程碑 C：可选性能优化

Phase 2.1 已有 Linux 测量记录：约 199 MiB、864 页的 `Primer C++(第5版).pdf` 源文件 SHA-256 校验耗时 1015 ms，窗口挂载约 2208 ms，打开至首屏缓存约 2230 ms。该结果说明哈希是一个明确的主线程阻塞环节，但计时点口径混有不同阶段，不应将所有剩余耗时直接归因于 PDF 引擎，也不能推定 Windows 下耗时完全相同。

本轮以用户可见缺陷修复为主。P01–P03 可按实际收益选择实施；未实施时沿用 Phase 2.1 诊断记录并说明后续处理条件。核心缩略图正确性（R05/R06）不是可选性能任务。

### 6.1 P01 — 大型 PDF 异步完整性校验（可选）

当前 `MainWindow::openBook()` 同步调用 `DocumentSession::load()`，后者同步执行 `LibraryManager::verifySource()`，读取完整 PDF 并计算 SHA-256。建议优先考虑将纯文件 I/O 和哈希计算移出 GUI 主线程，但正式加载标注及阅读会话仍以校验成功为前提。

```text
GUI 打开请求 -> 检查已有会话及重复打开请求
              -> 显示打开/校验状态，允许取消
后台任务      -> 读取 PDF，计算完整 SHA-256
GUI 收到结果  -> 核对任务代际、书库、书籍身份及源文件状态
              -> 校验成功：继续现有会话加载流程
              -> 校验失败/取消/过期：安全结束，不加载错误源文件
```

实施条件：

- 保持现有完整 SHA-256 验证要求，不将文件大小、mtime 或路径相同直接视为内容身份匹配。若源文件在校验期间发生变化，应拒绝该次结果或重新校验；不能让校验完成与实际加载之间的文件替换静默通过。沿用或适当加强现有身份/外部修改检查。
- 后台任务只持有所需的不可变数据（路径、期望哈希、任务标识等），不得在工作线程直接访问 GUI、非线程安全的 Qt PDF 对象或可变的书库会话。GUI 状态、书库元数据和阅读会话的修改在主线程执行。
- 结果返回时检查书库是否仍然有效、书籍是否仍存在、路径和期望身份是否仍匹配、请求是否取消/过期。切换书库、删除书籍、关闭主窗口等场景不得产生悬空对象、错开书籍或后台任务向已释放对象发送回调。支持取消和防止重复打开同一本书。
- 避免后台校验完成后 `DocumentSession::load()` 再同步计算同一文件的完整哈希；通过受控的已校验结果或等价入口承接后续加载，而不是提供可随意绕过验证的公共布尔参数。
- 后台读取按合理块大小处理，允许取消；界面给出明确的“正在校验/打开”状态，无需新建复杂任务管理系统。不得通过循环调用 `processEvents()` 伪装异步并引入重入风险。
- 复用 `PANO_OPEN_TIMING` / `pano-open-timing` 记录普通打开路径，测量哈希耗时、可交互等待时间、GUI 主线程阻塞和首屏显示时间。分别说明冷/热缓存条件，不能将总耗时未减少误判为异步化无效，也不能只测非 GUI 探针便宣称界面不卡顿。

如果不能以小规模、明确的生命周期设计完成，允许整体延期，不提交仅完成一半的异步流程，不削弱文件完整性保护。

### 6.2 P02 — 缩略图队列与资源占用（可选）

在 R05/R06 正确性修复后，根据实测考虑以下低风险优化：

- 统一共享占位 `QPixmap`/`QIcon`，避免为 864 个列表项重复分配相同占位图。
- 对可见页优先、邻近页预取；限制同时在途请求和过期预取队列。快速拖动滚动条至远处时优先处理新的可见范围，避免等待数百个不再需要的任务。
- 关注缩略图渲染与主阅读区渲染之间的资源竞争，不能因缩略图优先而影响正常阅读。以既有 Qt PDF 渲染能力为基础，不引入新的渲染后端。
- 核查列表长期浏览后已生成图标的内存增长；若确实需要缓存上限，确保淘汰条目可重新从缓存/渲染恢复，不能让 `m_thumbGenerated` 与实际图像脱节。

### 6.3 P03 — 减少重复布局计算（可选）

记录工具切换、窗口调整、侧栏拖动、切换书籍、恢复阅读状态期间布局重建次数和渲染请求次数。R04 已消除不必要的视口高度变化后，若仍存在明显重复计算，可对相同尺寸/参数增加早退或合并同一事件周期内的布局更新。

保持 `PageLayout` 的四种模式、双页封面规则、旋转坐标变换、适宽/适页缩放和阅读锚点语义不变。不得为减少调用次数省略必要的滚动范围更新或坐标刷新。没有明确收益时不进行重构。

## 8. 里程碑 D：验收场景与回归策略（R11）

## 9. 本阶段范围控制

以下内容不纳入本轮：完整笔记树、Markdown/TeX 渲染引擎替换、OCR、PDF 编辑/导出、跨书笔记、数据同步、全新 PDF 后端、GPU 渲染、大规模缓存模型重写、新标注类型、多选或复杂对象旋转功能。也不重新调整书库界面和已确定的阅读器三栏结构。

若发现直接影响数据安全或当前功能正确性的缺陷，可针对性修复并记录；其他新需求先记录，留待相关正式开发阶段。性能任务若存在复杂性或不确定性，应保留可复现证据及后续设计建议，不能拖延已确定的核心修复。
