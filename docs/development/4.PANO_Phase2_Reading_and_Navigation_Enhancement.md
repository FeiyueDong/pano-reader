# PANO Phase 2 — PDF 阅读与导航完善

> 开发性质：Phase 1.2 收尾修复 + 正式阅读器功能开发  
> 项目：`pano-reader`  
> 参考基线：Phase 1.2，提交 `b00d5030e1fab61a037f71da043f0c44ae09f4f4`（`fix bugs and update ui`）  
> 实施基线：开始开发时的当前工作区及最新提交，以实际代码为准。

## 1. 背景与目标

Phase 1、1.1、1.2 已建立正式工程、书库及书架管理、独立数据存储、多文档会话、阅读器三栏界面、标注对象编辑、工具预设、文字几何处理、智能选择及浮动工具栏等基础能力。用户实测表明，前几轮的主要缺陷已基本得到解决，缩略图、阅读位置恢复和标注定位能够正常使用。

Phase 1.2 仍有三个明确的交互问题：Shift 未能约束矩形和椭圆为正方形和正圆；默认选择工具不容易触发文字选择且缺少相应光标提示；Esc 未能可靠回到默认选择工具。此外，打开大型扫描书籍时存在约 1–2 s 的短暂卡顿，尤其是在连续布局、页面显示较小的情况下。该性能问题原因尚未确认。

本阶段不再单独安排 Phase 1.3，而是先修复上述问题，再完成正式 PDF 阅读器的基础能力。目标如下：

- 使默认选择及标注交互可靠、自然，收尾已有安全缺陷。
- 支持四种阅读布局和三种持续缩放模式，保持统一页面坐标和阅读锚点。
- 增加当前 PDF 全文搜索、用户书签、导航历史、全屏阅读等常用能力。
- 完成连续对象橡皮擦、几何标注复制粘贴、上下文右键菜单。
- 对大型扫描 PDF 的打开卡顿进行实际诊断，在本阶段尝试低风险优化；若仍有瓶颈，记录原因、证据及后续建议，不以大规模性能重构阻塞本阶段。

本阶段完成后，阅读与标注系统应达到相对稳定的日常使用状态，为 Phase 3 专业笔记系统提供基础。

## 2. 开发约束与工作方式

1. 继续采用现有 C++20、Qt Widgets、Qt PDF、xmake 技术路线。保持正式工程独立，不修改或依赖已归档的 `demo/`，不批量复用 Demo 源码。
2. 继续使用统一的页面 point 坐标及页面索引作为数据权威来源。布局、缩放、旋转、系统 DPI 变化均不修改已有标注几何数据。
3. 映射 PDF 和书库内拷贝 PDF 均为只读源文件。任何阅读、标注、书签、截图及测试操作不得修改源 PDF。导出图片等不得覆盖受保护源文件。
4. 保持 Phase 1.x 正式书库兼容性。新增字段须有明确缺省行为，新增文件须支持不存在的情况；核查旧版本读写行为后确定版本策略，不允许静默丢失新增数据。格式升级若涉及破坏性修改，应有显式迁移和备份。
5. 尽量复用现有模块和 `QAction`，避免重复创建操作入口或引入复杂框架。可以针对职责过重的 `PdfView`、`ReaderWorkspace` 提取必要的轻量模块，但不进行无关架构重写。
6. 按 PANO 项目长期开发约定，允许主动编译、启动程序、GUI 交互、截图和视觉检查。应实际查看截图或界面，而不是仅生成截图。优先补充已有探针的针对性断言，避免大量低价值自动化测试。
7. 开发前检查最新代码、项目 `AGENTS.md`、Phase 1.2 开发记录及数据格式规范。若下文列出的代码位置已变化，以当前等价实现为准，不机械复制旧行号或伪代码。
8. 使用用户指定的持续测试书库时遵守第 12 节数据保护要求。所有破坏性、故障注入和恢复测试在独立临时书库中完成。

## 4. 里程碑 A：已有交互与数据安全修复

### 4.1 R01 — Shift 几何约束

**问题**：Phase 1.2 的 `PdfView::updateDraw()` 在直线分支处理了 Shift，但矩形和椭圆分支仍直接使用起点、终点构造矩形，没有等宽高约束。

**要求**：

- 矩形按住 Shift 绘制正方形，椭圆按住 Shift 绘制正圆；不增加新的标注类型。
- 使用页面坐标计算约束矩形，保证 `abs(dx) == abs(dy)`。保留拖动象限，以起点为固定角；建议以较大绝对位移确定边长，再根据该方向可用页面范围统一裁减边长，避免先裁剪单轴破坏等宽高关系。
- 保留直线及直线式笔迹现有方向吸附行为，支持水平、竖直和 45° 方向吸附；不要改变普通自由绘制行为。
- 通过鼠标事件携带的修饰键及键盘按下、释放事件维护当前状态。拖动过程中按下或释放 Shift，即使鼠标没有移动，也应按最近鼠标位置更新预览。鼠标释放后的结果必须与最终预览一致。
- 正常缩放、旋转、不同页面布局及四个拖动方向均应成立；页边界附近不可破坏约束。
- 已有几何编辑中的 Shift 等比例缩放继续保留，几何尺寸变化不修改标注线宽。

建议将约束矩形及边界计算纳入现有 `AnnotationGeometry` 或等价纯几何模块，避免预览和提交各实现一套算法。

### 4.2 R05 — Shift 自由笔迹路径保留

当前 Shift 分支可能直接将 `m_draft.path` 替换为起点和终点，导致中途释放 Shift 后无法恢复此前的自由路径。

应分别维护原始采样路径及约束预览路径：

- 自由绘制期间持续记录原始鼠标轨迹，包括按住 Shift 的期间。
- 未按 Shift 时按原始路径预览；按住 Shift 时根据起点和最新鼠标位置计算直线预览。
- 释放 Shift 恢复原始路径预览；释放鼠标按最终状态提交一种有效几何。
- Esc 取消时清理两类临时路径；撤销一次即可移除本次绘制对象。
- 对水平、竖直、单点等退化路径保留已有几何保护，不引入除零或异常包围盒。

### 4.3 R02 — 文字命中判定

**现象**：默认选择状态下，很难判断或触发文字选取。现有 `textAtPagePoint()` 以约 0.8–1 pt 的极短水平选择范围尝试 `getSelection()`，将有效文字选区误用为文字命中条件。字符间、词间及纵向偏移很容易失败。

**方案**：将“能否从此处开始文字选择”与“拖动后实际选择哪些文字”分离。

1. 利用 Qt PDF 提供的文字索引、选区或文字几何能力，按访问页面建立轻量命中信息；优先复用已有 `TextSelectionGeometry`。具体 Qt API 以当前 SDK 实测为准，不假设每个多边形都能直接映射到唯一字符索引。
2. 根据字符、词语及连续文本行范围进行命中查询，允许合理的词间空白及轻微纵向偏移。初始容差建议 4–6 个逻辑屏幕像素，换算为页面 pt，并结合局部行高设置上限。容差属于可调实施参数，不应作为普适文字排版常量。
3. 不能将整页文字包围盒视作可选文字区域；避免跨栏、段落之间的大块空白、图片、公式附近空白被误判。对于竖排、旋转或复杂排版，无法可靠归并时使用保守的原始文字区域。
4. 命中时可记录适合的文字起点或最近文字位置，拖动后仍使用真实文字选择接口获得原文和几何。空点击不创建文字标注；不伪造扫描版的文字层。
5. 缓存按页面按需建立，限制内存及工作量。鼠标悬停不能重复提取整页文字，也不应为了预建缓存扫描全部文档。文档重新加载、源内容变更或关闭时清理相关缓存；缩放、布局和视图旋转仅变换坐标，不重新提取文字。
6. 保持已有高亮连续性、原始文字索引及原始几何持久化方案，不因命中优化改变已保存的标注内容。

### 4.4 R03 — 默认选择和光标采用同一命中逻辑

在现有智能选择基础上，建立统一命中查询（例如 `InteractionHit`，包含命中类型、页码、标注 ID、控制点、文字命中位置等）。悬停和按下必须共享判定，不重复维护两套不一致的规则。

| 命中情形 | 光标 | 左键行为 |
|---|---|---|
| 已选对象控制点 | 对应 resize 光标 | 调整端点或边界 |
| 可移动几何标注 | 移动光标或明确的对象指针 | 点击选择、拖动移动 |
| 文字标注与原文重叠 | I-beam（可选原文时） | 单击选择标注，拖动优先选取原文 |
| 可选择文字及合理邻近范围 | `Qt::IBeamCursor` | 开始文字选择 |
| PDF 内非文字区域 | `Qt::CrossCursor` | 框选区域 |
| 页面外部 | 普通箭头 | 取消选择 |
| 主动抓手工具 | 开放/闭合抓手 | 拖动阅读页面 |

保留独立框选入口、主动文字标注工具，以及此前约定的 Alt 强制文字选择、Ctrl 强制区域选择方式。若存在系统级快捷键拦截，以独立工具入口作为可靠替代，不应使功能只能通过修饰键使用。

- 已选控制点优先，文字与其他标注重叠时按前述规则处理；强制选择操作应有对应光标反馈。
- 鼠标达到拖动阈值并确定操作后，锁定本次交互类型，不能在途中重新切换到另一种选择。
- 启用必要的 viewport 鼠标跟踪；在工具切换、修饰键变更、鼠标离开及滚动后正确刷新光标，不残留 I-beam 或 resize 光标。
- 对扫描 PDF 默认在无标注区域自然进入矩形框选；文字版允许在字、词及普通词间距附近自然开始文字选择。

### 4.5 R04 — Esc 返回默认选择

Esc 的默认行为应明确且集中，不能仅清理临时对象而保持专用绘制工具。

| 当前状态 | Esc 行为 |
|---|---|
| 绘制、移动、缩放或连续擦除尚未提交 | 取消临时操作、恢复原数据，返回 `Tool::Select` |
| 已完成文字或区域选区 | 清除临时选区、关闭浮动工具栏，返回默认选择 |
| 使用专用标注工具但未绘制 | 切回默认选择工具 |
| 默认选择且有已选标注 | 取消选择 |
| 搜索栏正在使用 | 关闭搜索栏、清除搜索临时状态 |
| 全屏且无待取消的操作 | 退出全屏 |

普通阅读区内一次 Esc 应能完成取消临时操作并回到默认选择。工具栏选中态、属性栏、光标、浮动工具栏须同步。已提交对象不得被 Esc 删除；正在拖动的对象回到操作前状态。颜色对话框、设置、笔记编辑、菜单等局部控件优先处理自己的 Esc，防止误关闭或丢弃笔记。搜索及全屏与 Esc 的完整协调见第 8 节。

### 4.6 R06 — 永久删除安全收尾

现有 `.pending-delete/` 隔离机制已较 Phase 1.1 改善，不进行全面重写。重点核查 `LibraryManager` 中永久删除及启动恢复逻辑：

- 永久删除只允许已进入回收站的书籍，且无未保存或正在打开的会话。延续先保存和关闭会话的保护。
- 索引更新与删除状态记录均须检查写入结果。特别是 `committed` 记录写入失败时，不得继续不可逆递归清理。保留隔离数据及操作记录，允许重试或安全恢复。
- 启动恢复不得盲目信任记录中的 `quarantine`、原目录等路径。解析规范化路径后，检查其位于当前书库允许的目录内且是预期的书籍子目录，拒绝绝对路径越界、`..`、根目录、符号链接/目录联接点绕过、路径别名前缀混淆等情况。
- 禁止删除书库根目录、其他书籍目录及任何映射模式的外部 PDF。路径验证失败、记录损坏或状态与索引不一致时保留现场并提示，不猜测后递归删除。
- 清理操作应尽量幂等：崩溃后根据真实索引及已持久化记录判定恢复、重试或人工处理；不因重复恢复删除其他对象。
- 只有确认元数据事务已提交且目标合法后才物理清理。部分失败后保持可诊断记录。

此项故障及恶意路径测试必须在临时书库中进行，不得在用户指定的持续测试书库执行。

### 4.7 R07 — 浮动工具栏

保留现有文字与区域操作，不重新设计功能集合。定位优先级为选区下方、上方、右侧或左侧，最后才允许部分重叠；考虑 viewport 范围及工具栏实际尺寸。使用现有 Lucide 图标与简短文字/提示，提高辨识度。

浮动工具栏属于临时交互层，不占据页面布局空间。滚动、缩放、布局切换、切换文档、Esc、选区失效及关闭文档时更新位置或隐藏，不能留在错误页面。点击浮动工具栏或右键菜单不应先清除其所对应的选区；执行动作必须使用已捕获的文档、页码及选区，而不是当前偶然变化的选中对象。

## 5. 里程碑 B：阅读布局与坐标体系（F01）

### 5.1 四种页面布局

建议使用明确的布局枚举（命名可与现有工程风格保持一致）：

| 布局 | 显示行为 | 翻页行为 |
|---|---|---|
| `SinglePage` | 仅显示当前页，放大后可页内滚动 | 上一页/下一页 |
| `ContinuousSingle` | 所有页面单列连续排列 | 普通逐页导航及连续滚动 |
| `FacingPages` | 仅显示当前双页组，组内可滚动 | 上一组/下一组 |
| `ContinuousFacing` | 双页组纵向连续排列 | 按双页组导航及连续滚动 |

默认 `ContinuousSingle`。非连续布局下，到达页内/组内滚动边界后继续滚动可以翻页；设置适当的阈值或事件累计保护，禁止一次滚轮惯性跨越大量页面。允许在阅读设置中关闭滚轮边界翻页。显式页码输入、目录、缩略图、书签等仍指向具体 PDF 页而非双页组编号。

### 5.2 双页排列规则

以用户可见的 1 基页码说明：

```text
首页单独显示（默认）：
       [1]
    [2] [3]
    [4] [5]
       ...

首页参与双页排列：
    [1] [2]
    [3] [4]
    [5] [6]
       ...
```

- 默认从左到右阅读，首页单独显示选项仅对双页布局生效。单页布局应保留该选项值以供后续切回双页。
- 同组页面共同缩放，保持各自原始宽高比，顶部对齐，双页间保留固定逻辑像素间距；单独首页/末页可在阅读区居中。不创建虚假的 PDF 空白页面。
- 支持单页 PDF、奇偶页数、不同页面尺寸以及横向页面，考虑 PDF 原生旋转与用户视图旋转。暂不开发从右到左的书籍排列。
- 页面间距建议默认 16 个逻辑像素或延续现有合理默认值。页面组内间距可以采用统一主题/布局度量，不随 PDF point 坐标一起缩放。

### 5.3 当前页的定义

- 普通滚动时选择可见面积最大的页面；近似相同则优先保留当前页（建议以小比例滞回阈值抑制抖动）。若此前当前页已不可见，选择最合理的可见页。
- 点击实际页面、创建标注时以操作所在页为当前页，不主动滚动。
- 目录、搜索、书签、缩略图、页码跳转以明确目标页为当前页，防止双页布局的可见面积规则立即覆盖用户选择。
- 非连续布局切换当前页时同步更新当前页/组、滚动范围和导航控件；跨组前后翻页应到达适合方向的边界。
- 当前页更新只改变导航状态，不能成为每次重绘、缩放或标注选择时自动定位的理由。

### 5.4 PageLayout 职责

`PageLayout` 负责根据页面原始尺寸、旋转、缩放比例、阅读窗口大小及布局模式计算页面/组矩形、整体内容尺寸及可见页面集合。

```text
PDF 页面尺寸、旋转、布局模式、缩放比例
                   |
               PageLayout
                   |
       页面在内容区域的位置与尺寸
                   |
       统一 page <-> content <-> viewport 变换
          /             |              \\
      PDF 渲染       标注交互         导航与截图
```

布局差异不得散落在不同的标注工具中。所有工具继续基于现有统一坐标变换与页面命中。布局重算不修改 `annotations.json`，不清空撤销栈，不重载 PDF，不改变独立工具预设。不可见页/组不得参与当前页命中，但显式导航仍可访问它们。

连续布局可以计算全体页面的轻量位置元数据，但实际页面渲染只针对可见页和有限预加载区域。尽量利用已有布局数据避免每次鼠标移动或滚轮事件全量重算；不要因为新增双页模式而引入整本文档图像渲染。

## 6. 缩放模式、阅读锚点和导航入口（F02、F07）

### 6.1 三种缩放模式

在内部区分 `ZoomMode`（缩放策略）与 `zoomFactor`（实际比例）：

| 模式 | 计算规则 |
|---|---|
| `Fixed` | 用户指定比例，窗口变化时保持不变 |
| `FitWidth` | 根据可用阅读区宽度与当前参考页/双页组宽度计算 |
| `FitPage` | 同时考虑可用宽高，使用较小的适配比例 |

计算适配比例时扣除边距、页间距及实际滚动条占用空间。双页以整组为计算对象，单独封面及末页以实际页面为对象。避免适配比例和滚动条反复互相触发导致振荡。

对连续布局的混合尺寸页面，参考当前页/组计算整体缩放比例。在普通连续滚动期间保持比例稳定，不能随着当前页变化不断改变整本文档大小。显式导航、模式切换、阅读区大小变化或旋转时允许根据新的参考页重新计算。非连续布局可在显式翻页或组变化时重新计算适配比例。

### 6.2 缩放行为

- Ctrl+滚轮：以鼠标命中的原文位置为锚点；鼠标在页面外时回退到阅读区域中心或最近有效可见页。
- 底部缩放按钮及数值输入：以阅读区中心附近的有效原文位置为锚点。
- 手动输入比例、放大缩小按钮、Ctrl+滚轮均切换至 `Fixed`。
- 适宽、适页按钮进入持续模式，调整窗口、侧栏、全屏及旋转时重新计算。
- 提供常用比例 25%、50%、75%、100%、125%、150%、200%、300%、400%，支持手动输入。保留合理的比例上下限及合法数值校验，不接受 NaN、无穷或非正值；不应为实现预设而降低现有合理缩放范围。
- 控件应显示实际比例与当前模式，程序更新控件时阻止反馈信号循环；避免手动缩放因当前页信号又切回适宽模式。

### 6.3 阅读锚点

缩放、窗口变更、布局切换、旋转及全屏前记录当前视图对应的页面索引、原始页面 point 坐标及目标屏幕位置（必要时以 viewport 相对位置表达）。布局重算后通过同一坐标变换恢复，使该原文位置尽可能保持在原先的视图位置。因页面边界、滚动范围、非连续布局变化而无法精确恢复时合理夹取到最近有效位置。

阅读状态恢复应先建立页面几何和最终布局，再恢复锚点；不得先用临时很小的 viewport 尺寸计算最终适宽比例，再不断重复跳转。遇到侧栏及窗口初始化造成的多次 resize，合并必要的布局更新。

### 6.4 统一导航入口

在现有 `goToPage()`、`revealAnnotation()`、阅读位置恢复等逻辑基础上，形成统一导航接口。概念形式：

```cpp
navigateTo(pageIndex, pagePoint, alignment, navigationReason);
```

具体签名可调整，至少需要区分导航原因、是否记录历史、页内对齐及目标页/组切换。

- 目录、书签、缩略图、搜索、标注列表、页码输入共享该入口。
- 普通标注选择、绘制、属性更新不得调用主动定位接口。
- 恢复阅读状态、历史回放与布局锚点恢复不得再产生新历史记录。
- 导航后同步当前页、缩略图及必要的界面状态，但不必改变无关标注选择。

## 7. P01 — 大型扫描 PDF 打开性能诊断

### 7.1 问题和边界

用户反馈：打开较大的扫描书籍时，在连续布局且页面显示较小的情况下会短暂卡顿约 1–2 s。当前并无实测证据证明瓶颈一定是页面布局或渲染。本轮将其作为探索性性能任务，优先定位实际耗时，不先行假设解决方案。

关注以下候选原因：

| 候选阶段 | 可能的开销（需验证） |
|---|---|
| 文件访问及校验 | PDF 哈希计算、文件状态查询、同步盘或磁盘 I/O |
| PDF 加载 | Qt PDF/PDFium 文档初始化、页数及页面尺寸读取、扫描页解码 |
| 会话初始化 | JSON 读取、标注列表、阅读状态及目录模型初始化 |
| 页面布局 | 初始缩放较小导致大量可见页；全页尺寸查询或重复布局计算 |
| 正文渲染 | 可见页任务提交过多、旧请求堆积、同步高分辨率渲染、图像转换与合成 |
| 缩略图 | 一次性初始化大量列表项/占位图、与正文竞争渲染资源 |
| 文字命中和搜索 | 新增功能意外在打开时提取全书文字或索引 |
| GUI | 初始化过程阻塞事件循环，重复刷新控件和几何 |

注意区分首次导入（可能需要复制 PDF、计算哈希及生成封面）与已导入书籍的普通打开。用户描述的问题主要针对普通打开，不应仅用导入耗时解释。

### 7.2 诊断方式

使用第 12 节的小型文字论文和大型扫描书籍，对开发前后进行尽可能相同条件的对比。建议在修复前先复现并保存一次基线；若无法复现，也应记录环境及操作条件。

- 使用 `QElapsedTimer`、现有日志或轻量调试记录，分别测量：发起打开、路径解析及校验完成、PDF Ready、会话数据加载、页面尺寸/布局初始化完成、阅读工作区显示、首个真实页面图像显示、初始可见区域渲染基本完成。
- 区分异步请求提交耗时和结果完成耗时，记录实际 GUI 主线程停顿（如低频事件循环心跳或 GUI 交互观察），不能只用后台总耗时判断界面是否卡顿。
- 记录文档页数、文件大小、设备/操作系统、构建类型、布局与实际缩放、初始可见页数量、渲染请求数量及队列/缓存情况。避免日志包含不必要的私人文件内容。
- 至少比较同一程序内重复打开与重启后的首次打开；不能将重启简单等同于 OS 冷缓存，不要求人为清空系统文件缓存。条件允许每种情形重复 2–3 次，报告代表值或范围。
- 扫描书籍重点测试连续单页的较小固定比例（例如 25%/50% 或实际能够复现的比例），再比较默认比例及连续双页。论文作为轻量对照。
- 若发现性能问题与本阶段新布局或新增文字命中模块有关，优先修复新增的明显回归。

### 7.3 优化方向（按证据选择，不要求全部实施）

1. 优先显示当前阅读页及最接近视口中心的页面，再补齐其余可见页及邻近预加载。即使小比例下可见页较多，也限制同时待处理请求数；保留占位及有效的缓存复用，最终完成所有稳定可见页的渲染。
2. 在窗口几何尚未稳定时避免重复提交大量临时分辨率请求。合并布局更新、丢弃过期请求结果、避免相同文档/页码/分辨率重复渲染；不阻塞正常首屏显示。
3. 页面渲染尺寸与实际显示需求、DPI 对应；先低分辨率预览、后续补高清仅在确有收益时采用。避免小页面仍按高分辨率整页渲染。
4. 若瓶颈在缩略图初始化或渲染竞争，可调整为按缩略图视口可见范围请求、去重及有限缓存，缩略图面板未显示时减少工作。保持用户已确认正常的缩略图功能，不做无关重构。
5. 若瓶颈在文件哈希或 I/O，可研究在不降低源内容一致性保护的前提下复用有效校验结果或异步处理。不能为缩短打开时间直接取消必要校验，尤其是重新定位、源变化等关键场景。
6. 保持 Qt 对象线程归属及渲染 API 使用约束；不为性能贸然跨线程共享未经确认线程安全的 `QPdfDocument`。不要求引入 GPU、替换 PDF 引擎或实现复杂任务调度框架。

### 7.4 验收及允许延期条件

目标是减少首屏前 GUI 阻塞和不必要的渲染工作，让阅读区尽早响应；不以固定毫秒阈值作为跨设备强制验收，也不宣称未经测量的优化幅度。

若能够定位并低风险修复，给出修复前后的实测数据和对应代码说明。若未能定位、改善不明显，或修复需要较大范围重构，可将问题留待独立性能阶段，记录：复现条件、耗时分解、已排查因素、已尝试改动、是否回退、尚存瓶颈及后续建议。此情形不阻塞其他 Phase 2 功能验收。

## 8. 里程碑 C：阅读辅助功能

### 8.1 F03 — 当前 PDF 全文搜索

搜索范围仅限当前 PDF 中可提取的原文（包括 PDF 自带 OCR 文字层），不搜索用户笔记或整个书库，不引入 OCR、正则、模糊匹配等复杂能力。优先使用 Qt PDF 的 `QPdfSearchModel`，以当前 Qt SDK 的公开 API 及实际能力为准，不另写全文索引引擎。

**界面设计：**

```text
┌──────────────────────────────────────────────────────────────────┐
│ 原有一级标注工具栏                                               │
│ 原有二级属性栏（按需显示）                                       │
├──────────────────┬──────────────────────────────┬────────────────┤
│ 目录 页面 标注   │ [关键词________]  3/24 ↑ ↓ × │ 笔记  详情     │
│ 书签 搜索        │       临时搜索栏             │                │
│                  │                              │                │
│ 搜索结果 (24)    │         PDF 阅读区           │ 原文摘录       │
│ 第 38 页 · ...   │                              │                │
│ 第 42 页 · ...   │      普通匹配：浅黄色        │ Markdown 笔记  │
│ 第 47 页 · ...   │      当前匹配：橙色轮廓      │                │
│ ...              │                              │                │
├──────────────────┴──────────────────────────────┴────────────────┤
│                      原有阅读控制栏                              │
└──────────────────────────────────────────────────────────────────┘
```

布局示意用于明确职责，不要求逐像素复制。左侧标签较多时允许使用图标+tooltip、可滚动标签或其他节省横向空间的方式，保留五项导航内容，不因新增搜索及书签挤压 PDF 主区域。

**操作规则：**

- Ctrl+F 打开阅读区顶部临时搜索栏并聚焦输入框；已有文字选区时可将文字作为初始搜索词（非必要，不改变原选区数据）。
- 输入短暂防抖后搜索；Enter/F3 前进、Shift+Enter/Shift+F3 后退。到末尾可循环至首项，并提供简单提示。
- 结果列表展示页码、匹配文字及前后文；点击结果精准定位到对应页面及区域，采用统一导航入口。
- 搜索期间允许逐步更新结果，显示搜索中及当前已获得结果数。完成后才显示确定的总数或未找到结果。对于新查询，旧查询的回调不得污染新结果；若 Qt 当前版本不能可靠取消任务，应通过模型实例/查询代次等方式隔离状态。
- 普通结果浅黄色、当前结果橙色并配合轮廓等明确区别；根据主题确保对比度。搜索高亮为独立临时层，不参与标注命中、撤销重做、自动保存和截图中的正式标注合成。
- Esc 或关闭按钮清除当前搜索的临时高亮及搜索结果显示；需要时恢复之前的导航标签。切换书籍保留各自搜索状态，关闭会话时释放搜索资源；不持久化搜索历史与结果。
- 无文字层的扫描文档提示原文搜索不可用；混合文档只能搜索有文字层的页面。不能因部分页无文字而判定全书不可搜索，也不应为了提前判断是否扫描版而在普通打开时扫描全书。
- 当前版本的搜索结果坐标约定应通过实际样本确认，统一转换为现有页面 point 坐标，避免重复应用旋转或缩放。

### 8.2 F04 — 用户书签

书签属于主动保存的阅读位置，不是 PDF 自带目录，也不是需要绘制在 PDF 上的标注。采用独立、平级的列表，不引入多级书签树、标签和富文本说明。

创建入口：底部书签按钮、Ctrl+B（当前阅读锚点）及页面右键菜单（点击位置）。标题默认“第 N 页”，创建后可重命名，不强制弹出输入框；同一页面允许多个不同位置的书签。用户书签点击后精准定位页内坐标。

左侧导航增加“书签”标签页，提供创建、重命名、定位、删除、按创建顺序/页码排序。默认创建顺序，排序不修改存储顺序。书签不与书架收藏混淆，创建书签不会收藏该书。

每本书新增可选的 `bookmarks.json`，第一次需要写入时创建；旧书库缺少该文件视为空集合。建议协议：

```json
{
  "format": "pano-bookmarks",
  "schema_version": 1,
  "book_id": "book-uuid",
  "bookmarks": [
    {
      "id": "bookmark-uuid",
      "title": "地震反应谱",
      "page_index": 127,
      "position": {"x": 72.0, "y": 135.0},
      "created_at": "2026-11-27T15:00:00Z"
    }
  ]
}
```

书签页码仍为 0 基索引，界面显示 1 基页码；坐标与标注使用相同的原始页面坐标。校验唯一 ID、book ID、有限坐标、页码和版本。书签应有独立的修改状态，纳入自动保存、手动保存、切换关闭保存、原子写入及外部文件修改检测。书签变化不能无关重写整份标注文件。外部 PDF 缺失时保留书签，不擅自删除；超范围书签应提示定位不可用而不是静默改写数据。

### 8.3 F05 — 导航历史

每个文档会话维护独立的前进、后退记录，默认最多 100 个位置。只记录主动跳转，不记录普通阅读过程中每一次滚动：

| 操作 | 记录历史 |
|---|---|
| 目录、用户书签、标注列表定位 | 是 |
| 搜索结果、缩略图点击、手动输入页码 | 是 |
| 正常滚动、逐页/逐组按钮 | 否 |
| 缩放、旋转、布局切换、全屏 | 否 |
| 创建、选择、修改或删除标注 | 否 |
| 书籍打开及阅读状态恢复 | 否 |
| 历史前进和后退回放 | 否 |

主动导航前捕获当前真实阅读位置，导航成功后记录目标位置；连续重复同一目标可以去重。后退应能够返回主动跳转前的页内位置，而不只是页顶。后退后新建主动跳转清除前进分支。普通滚动不生成记录，但下一次主动导航时应捕获最新实际位置。历史记录保存页码和页面 point 锚点，按当前布局和缩放定位，不强制恢复历史中的视图样式。

使用 Alt+Left / Alt+Right 及底部历史按钮。按钮启用状态随历史同步；避免与文本编辑器光标操作冲突。关闭会话释放历史，不写入书库，不与书库“最近阅读”记录合并。

### 8.4 F06 — 阅读控制栏、面板与全屏

保持现有书库与阅读工作区分离：书库中不显示阅读控制和标注工具。阅读工作区的总体布局如下：

```text
全局菜单栏
书库固定标签 | 书籍 A × | 书籍 B ×
阅读工作区：一级标注工具栏
            二级属性栏（按当前工具/对象显示）
左侧导航                 中间 PDF 主区域             右侧笔记/详情
目录/页面/标注/书签/搜索  临时搜索栏、浮动工具栏       按原有机制工作
底部阅读控制栏
全局状态栏（保存状态及提示）
```

底部阅读控制栏建议分组为：

```text
[后退][前进][添加书签] | [上一页][页码 / 总页数][下一页]
| [布局▼] | [−][缩放比例▼][＋][适宽][适页]
| [旋转▼] | [左栏][右栏][全屏]
```

优先使用一行水平工具栏及现有 Lucide 图标，配合 tooltip；小窗口时合理折叠低频按钮，不挤压页面或截断所有关键操作。布局下拉包含四种模式及首页单独显示选项；不增加四个常驻布局按钮。状态栏避免重复显示所有控制参数。书籍状态随切换主动同步。

全屏通过 F11 或按钮切换，不创建新阅读窗口，不重新加载 PDF。默认隐藏菜单栏、文档标签、左右面板和标注工具栏；可隐藏底部控制与状态栏以扩大阅读区域，确保有明确的 F11/Esc 退出机制。保留阅读滚动、快捷缩放、默认选择等基本能力。进入前保存窗口状态和面板显示、宽度等本机 UI 快照，退出后恢复，并保持阅读锚点。全屏仅是临时界面状态，不覆盖普通模式的布局配置。

Esc 冲突处理：局部对话框/编辑器优先处理；阅读区有未完成操作或临时选区时先取消并回到默认选择；搜索处于活动状态时关闭搜索；无待处理操作且处于全屏时退出。F11 可明确切换全屏。不要因快捷键传播一次同时关闭搜索、退出全屏、关闭书籍或丢弃笔记。

### 8.5 阅读设置与数据扩展

在现有设置界面的“阅读”类别增补：默认页面布局、默认缩放模式（建议适合页面，新书生效）、默认固定比例（仅 Fixed 使用）、双页首页单独显示、非连续模式滚轮翻页、恢复阅读位置。页面间距设置可选，若未实现则使用现有合理默认值。标注设置中增加橡皮擦半径。

沿用现有设置应用、取消和实时预览规则。新书默认设置不覆盖已有书籍的专属阅读状态，不因打开设置而改变当前文档布局。

| 数据 | 存储位置 |
|---|---|
| 默认布局、缩放模式及比例、首页选项、滚轮翻页、页面间距 | 本机配置 |
| 擦除半径 | 本机工具预设 |
| 单本书实际布局、首页选项、缩放模式及比例、旋转、页内锚点 | 现有书库阅读状态文件 |
| 用户书签 | `books/<book-directory>/bookmarks.json` |
| 搜索结果、导航历史、临时选区 | 当前文档会话内存 |
| 窗口及侧栏宽度、全屏前界面状态 | 本机配置或临时内存（全屏快照） |

阅读状态在现有结构上扩展，不重新设计整份数据协议。缺少布局字段的旧书籍默认为连续单页；缺少缩放模式但存在有效历史比例时按 Fixed 恢复，以尽量保留之前的显示效果。没有历史状态的新书使用本机默认设置。原有页内锚点优先于仅页码的旧记录；比例、旋转等异常字段安全处理，不写坏已有数据。实际字段名及版本由开发者根据当前规范确定，并在 `docs/specification/` 中明确兼容行为。

## 9. 里程碑 D：标注交互收尾

### 9.1 A01 — 连续对象橡皮擦

在现有单击对象擦除基础上，实现按住左键连续擦除。仍按整个对象删除，不切割路径或文字片段。

- 擦除光标为与实际范围一致的圆形，半径以逻辑屏幕像素表示，建议默认 12 px、可设置 4–25 px（可根据实际体验调整）。换算到页面坐标进行命中，不随 PDF 缩放改变屏幕操作范围。
- 连续检测相邻鼠标采样点之间扫过的范围，避免快速移动漏删。按实际笔迹/描边/填充/文字区域进行合理命中，不能仅以对象包围盒作为最终擦除依据；未填充矩形中心不应被当作实心对象。
- 所有普通标注类型均可擦除，搜索高亮、临时选区、用户书签及控制点不是擦除对象。附带有效笔记内容的标注、笔记定位对象默认跳过，在状态栏简洁提示；用户可通过显式删除操作及现有笔记保护流程处理。
- 一次按下到释放为一次撤销命令；同一对象重复命中只删除一次。撤销恢复 ID、几何、样式及绘制顺序，重做结果一致。
- 拖动中可预览隐藏命中对象，Esc 取消时恢复；避免临时擦除过程被自动保存成不可恢复的中间状态。鼠标释放后才正式提交，异常失焦或文档切换按安全取消规则处理。
- 擦除轨迹不可跨页错误连接；经过页面间隙时按各页实际命中处理。

### 9.2 A02 — 几何标注复制与粘贴

第一版支持直线、矩形、椭圆、铅笔和荧光笔等与原文文字索引无关的几何对象，允许跨页及跨已打开书籍复制。不支持文字高亮、下划线、删除线及笔记对象跨位置复制。

- Ctrl+C：存在有效文字选区时优先复制原文；否则复制已选且支持的几何标注。区域选区的图片复制沿用现有浮动工具栏/上下文操作；若已有一致的 Ctrl+C 行为可保留并记录优先级。
- Ctrl+V：优先粘贴至鼠标所在的有效页面位置；没有有效鼠标位置时使用当前阅读区中心或当前页合理位置。右键粘贴使用该次右键的页面位置。
- Ctrl+D：在原对象附近生成独立副本，保持合理偏移。
- 保存形状、线宽、颜色、线型、填充、透明度、混合方式等完整样式；重新生成标注 ID 及创建/修改时间，更新目标页码和绘制顺序，默认不复制附属笔记、截图资源和旧页码关联。
- 以原始页面 point 坐标处理几何平移，不因不同显示比例或旋转改变物理尺寸。超出目标页面时优先平移适配，不自动缩放；对象尺寸大于目标页面、无法合法放置时提示并停止或提供明确处理方式，不能静默截断。
- 剪贴板优先使用带格式标识和版本的自定义 MIME（如 `application/x-pano-annotation+json`）。读取时校验数据大小、版本、支持类型、有限坐标及样式范围，不信任外部剪贴板中的任意 JSON；禁止借此加载外部文件或执行内容。
- 每次粘贴或创建副本为一次独立撤销操作；创建后可选中新对象，不强制触发额外页面滚动。笔记编辑器、搜索输入框及其他普通文本控件有焦点时仍执行其原生复制粘贴快捷键。

### 9.3 A03 — 上下文右键菜单

右键菜单作为工具栏、浮动工具栏及快捷键的补充，按命中对象提供操作：

| 右键对象 | 菜单项目 |
|---|---|
| 普通 PDF 页面 | 添加书签、添加定位笔记、框选、粘贴（可用时） |
| 已选文字 | 复制、高亮、下划线、删除线、添加笔记 |
| 已选区域 | 复制图片、保存图片、矩形标注、区域高亮、添加笔记 |
| 几何标注 | 编辑笔记、复制、创建副本、属性、删除 |
| 文字标注 | 编辑笔记、复制原文、属性、删除 |

已有有效选区内右键不应导致选区被清空。未选择标注时可以根据右键命中选中该对象，但不能因选择而自动定位；菜单关闭前保留其目标书籍、页码和对象 ID，避免延迟执行到其他对象。菜单操作复用 `QAction` 或现有业务接口，不维护另一套样式、截图、笔记或删除流程。不可用的操作合理禁用或隐藏，删除保持既有笔记保护。

## 10. 公共技术与数据约束

1. PDF 渲染、文字及图形标注、搜索高亮、选择区域、截图、控制点及导航必须共享现有 page/content/viewport 坐标变换。不同布局和旋转下先确认真实页面，再做局部变换。
2. 现有原始标注几何及合并后的显示几何分离原则不变。文字命中缓存、搜索结果、用户书签、导航历史均不应误写入 `annotations.json`。搜索临时高亮不应影响普通区域截图的正式内容。
3. 扩展当前会话及保存机制，区分标注/笔记、书签和阅读状态的 dirty 标记。保持延迟自动保存、Ctrl+S、切换与关闭保存；保存失败时保留修改，阻止导致数据丢失的关闭或删除。切换书库仍需保存并关闭会话、正确释放锁。
4. 每本书的导航历史、搜索状态、当前页、缩放模式及临时交互状态相互独立。工具预设继续使用本机统一配置，已有对象样式不随预设变化。
5. 新文件/字段记录在正式规范中；继续采用 UTF-8 JSON、稳定 ID、明确 `format` 和 `schema_version`。对新旧版本读写进行核查，不为兼容而重复保存权威几何或状态。
6. 按需获取正文图像、缩略图和文字数据。缓存预算保持有限，避免连续双页、搜索及文字命中各自无限扩大内存占用。新异步请求注意文档会话生命周期，关闭标签后不得访问已释放对象或绘制旧文档结果。
7. 所有快捷键关注焦点和上下文，优先保证文本编辑器、搜索栏和局部弹窗正常工作；不要设置多个互相竞争的全局快捷键。菜单、工具栏、快捷键共享操作逻辑。

## 11. 本阶段范围控制

本阶段不开展以下完整功能：专业笔记树、成熟 Markdown/公式库集成、OCR、带标注 PDF 导出、Markdown/完整书库导出、跨设备同步、对象多选/旋转、复杂路径节点编辑、PDF 内外部链接全面支持、右到左双页排版、阅读颜色滤镜及 GPU 渲染重构。

缩略图当前已由用户确认正常；只有诊断确实发现其调度、重复请求或缓存是实际瓶颈时才针对性调整。大型扫描文档卡顿允许在有记录的前提下延期，其他已确定的阅读布局、导航和交互任务不随意延期。不要为本阶段功能引入尚不需要的插件系统、额外数据库或复杂服务层。

## 14. 交付与开发记录

本阶段交付内容：正式工程源码及构建配置；必要的现有探针更新；阅读状态与书签数据规范；必要的用户操作说明及快捷键说明；项目 `AGENTS.md` 中的长期测试路径约定；Phase 2 开发结果记录。

## 15. 阶段完成判定

本阶段应当使 PANO 在不修改 PDF 原文的前提下，提供稳定的标注选择与几何编辑体验、四种阅读布局、持续缩放、准确的阅读定位、全文搜索、个人书签、导航历史及常用标注操作。用户能够直接使用持续测试书库继续阅读，并查看本轮新增的测试成果。

若大型扫描 PDF 启动卡顿仍然存在，可以保留为独立性能优化任务，不因此扩大本阶段范围。完成核心功能并解决明确的交互与数据安全缺陷后，进入 Phase 3 专业笔记系统开发，重点讨论笔记树、成熟 Markdown 库、数学公式、图片和摘录管理，不再频繁改动阅读器基础布局和坐标体系。
