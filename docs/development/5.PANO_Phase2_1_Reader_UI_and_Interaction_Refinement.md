# PANO Phase 2.1 — 阅读器界面优化与交互稳定化

> 开发性质：Phase 2 收尾修复、阅读器界面组织优化及性能诊断  
> 项目：`pano-reader`  
> 分析基线：`783d336df405aac87bf1637f68962ee36bb7ec29`（`phase 2: reading and navigation enhancement`，2026-11-28）  
> 实施基线：开发开始时的当前工作区及最新提交，以实际代码为准。

## 1. 背景与开发目标

Phase 2 已建立四种页面布局、持续缩放模式、统一导航、全文搜索、用户书签、阅读历史、全屏阅读、连续对象橡皮擦、几何标注复制粘贴及上下文右键菜单。Windows 实际使用表明，阅读布局及主要功能已经基本符合预期，但部分实际交互仍存在缺陷，界面的功能分布也需要进一步整理。

本阶段不再扩大 PDF 阅读器的功能范围，而是在现有能力基础上完成以下工作：

- 修复全屏入口与退出、橡皮擦、非连续布局滚轮翻页及页面切换等交互缺陷。
- 完善导航历史、搜索状态和非连续布局滚动范围等本轮代码检查发现的问题。
- 将阅读工具集中至顶部；左侧组织原始文档导航，右侧组织标注与笔记；底部主要显示状态信息。
- 使缩略图布局随侧栏宽度自适应，并改进按需生成机制。
- 补充大型扫描 PDF 的完整应用层打开耗时分析，按证据实施低风险优化；复杂性能改造可独立延期。
- 使用指定测试 PDF 和持续测试书库完成实际交互及视觉验收，为 Phase 3 专业笔记系统开发建立稳定基础。

本阶段完成后应基本冻结阅读器的主要功能范围和界面职责，不要求一次性解决所有性能问题，也不引入完整笔记树等下一阶段功能。

## 2. 开发约束与参考资料

1. 保持 C++20、Qt Widgets、Qt PDF、xmake 技术路线及统一页面 pt 坐标体系。不得因 UI 迁移改变既有标注位置、页面索引、文字几何、样式或原文锚点。
2. 正式工程独立开发，不修改归档 `demo/`，不引入 Ribbon 框架或进行无关架构重写。优先使用已有 `QAction`、`QToolBar`、`QToolButton`、`QSplitter` 及 Lucide 图标资源。
3. 映射 PDF 和书库拷贝 PDF 均视为只读源文件。维持源文件身份校验、书库锁、外部修改检测、原子保存及删除保护。不允许为提高性能而静默取消完整性校验。
4. 保留已有标注、笔记、书签、书架、阅读状态及工具预设。新增本机界面设置应具有合理默认值；现有书库格式原则上不变。若确需扩展格式，说明版本与缺省处理，并同步数据规范。
5. 按 PANO 长期约定，允许主动编译、运行、真实 GUI 操作、截图和视觉检查。优先修改现有探针的针对性断言，不以新增大量测试或截图数量代替真实交互验收。
6. 开发前核查 `AGENTS.md`、Phase 2 需求和结果记录、当前代码及 `docs/specification/phase1-data-formats.md`。本文中列出的函数和位置基于分析基线；代码发生变化时应核查等价实现，不机械套用旧代码。
7. 使用第 8 节规定的持续测试书库进行正常功能测试，破坏性测试使用独立临时书库。

## 4. 里程碑 A：基础功能与交互修复

### 4.1 R01 — 全屏按钮及退出机制

**已知问题与代码依据**

- `ReaderWorkspace::buildBottomBar()` 对应全屏动作会发出 `fullscreenRequested()`，但 `MainWindow::connectSession()` 没有连接到实际全屏切换入口。
- `MainWindow` 的 F11 动作依附于菜单，进入全屏后菜单隐藏，F11 退出在 Windows 实测失效。现有事件过滤器仅处理 Esc；具体快捷键分发行为仍需实际平台确认。
- `phase2_probe.cpp` 直接调用 `toggleFullscreen()`，未测试按钮与真实快捷键，因此通过并不代表完整入口可用。

**实施要求**

- 由 `MainWindow` 作为全屏状态唯一控制者；当前阅读工作区的全屏请求连接到统一入口。非当前文档不得错误触发切换。
- F11 使用不依赖隐藏菜单、工具栏可见性的窗口级快捷键机制。可将唯一 `QAction` 显式加入主窗口或使用等价 `QShortcut`。避免重复注册相同快捷键导致歧义或一次按键切换两次。
- 全屏动作、菜单、按钮、F11 和退出入口共享同一状态，不单独维护相互矛盾的 checked 值。书库页禁用阅读器全屏操作或明确不触发。
- 进入全屏前记录窗口几何、最大化状态、面板可见性/宽度、工具栏状态；退出后恢复。临时隐藏面板不得覆盖正常模式的持久化配置。
- 每次进入和退出前获取当前阅读锚点，在新视口尺寸、布局与缩放更新稳定后恢复该锚点；退出时不强制跳回进入全屏前的页码，因为用户可能已经在全屏中阅读其他内容。
- 全屏中 F11 应始终能够退出；Esc 先取消未提交绘制/对象编辑/擦除、清除临时选区或关闭相应临时 UI，无待取消状态时退出全屏。取消操作和回到默认选择应复用 `PdfView::handleEscape()` 等统一逻辑，不能通过先清除工具造成未提交操作被意外保存。
- 全屏中提供明确的退出按钮（U06），不应只依赖快捷键。对话框、笔记编辑器等具有自身 Esc 行为的控件应正常处理其事件。

**验收重点**：通过实际按钮进入，再分别通过 F11、Esc 和退出按钮退出；通过菜单/F11 进入后再次 F11 退出；检查正常窗口与最大化窗口恢复、侧栏配置及阅读位置。不得只调用内部函数验证。

### 4.2 R02 — 对象橡皮擦

**已知问题与代码依据**

`PdfView` 使用 `Qt::BlankCursor` 隐藏鼠标并在 `paintEvent()` 中绘制圆环。`mouseMoveEvent()` 更新 `m_lastMouseViewPos`，但普通悬停或擦除拖动并未稳定请求重绘，导致光圈直到点击或其他刷新才移动。`eraseSegment()` 通过半径计算采样间距，却使用普通 `annotationAt()` 的固定命中容差，并且每个采样点只返回一个标注。已命中对象直至释放鼠标才删除，拖动期间无即时反馈。

**光标与视觉反馈**

- 优先采用圆形自定义 `QCursor`（`QPixmap`、正确热点及 DPI），随系统鼠标自然移动。改变橡皮半径、屏幕 DPI 或相关主题后更新；切换工具、离开阅读视口时恢复相应系统光标。若平台自定义光标效果不佳，可使用独立轻量覆盖层或新旧光圈局部重绘作为替代，不得因此每次移动都强制重新渲染 PDF。
- 橡皮半径延续现有逻辑屏幕像素单位（现有 4–25 px 范围及工具预设）。光圈大小与实际擦除半径一致，不随 PDF 缩放改变屏幕显示尺寸。
- 拖动期间即时预览擦除结果：暂时隐藏已经命中的、允许删除的对象；不得修改 PDF 原图，不因预览而写入标注模型或文件。提交后清除临时预览。

**擦除几何与事务**

- 保留对象级删除，不实现自由笔迹局部切割。检测鼠标相邻采样位置间由圆形半径扫过的区域（线段胶囊形区域），而非仅中心点。可先以几何包围盒筛选，再用实际图形/描边路径判断交集；空心矩形和椭圆内部不应被误当作实心区域。
- 使用已有页面坐标转换；跨页拖动分别处理实际经过的可见页面，不把页间空白作为任一页面坐标。对同一位置重叠的多个可擦除对象均进行检测，并按 ID 去重；不能因最上层对象已被收集或受保护而阻塞下层对象。
- 单击也是有效的圆形擦除；一次按下、拖动、释放组成一次 `RemoveAnnotationsCommand`。没有命中时不生成撤销命令，所有结束路径均清理状态。
- 带有笔记的标注继续默认跳过（包括有内容的定位笔记），状态栏合并提示，避免每个采样点重复发出消息；仍可通过选择后显式删除并确认。
- Esc、工具切换、文档切换或鼠标捕获丢失时取消未提交事务并恢复预览。正常释放后一次撤销恢复全部对象及原有顺序，重做一致。
- 擦除不得触发页面跳转、修改被保护对象或产生重复保存操作。

建议将实际命中路径扩展纳入 `AnnotationRenderer`/`AnnotationGeometry` 等已有几何模块，保留普通选择命中容差与橡皮半径的区别。实现方案可按现有模块边界调整。

### 4.3 R03 — 非连续布局滚轮翻页

**已知问题**：`AppSettings::wheelTurnsPage` 及配置缺省值为 `false`。`PdfView::wheelEvent()` 已有边界翻页分支，但未限制为非连续布局，且直接使用 `currentPage ± 1`、目标总是页顶，没有针对双页组、触控板或边界阈值处理。

| 布局 | 滚轮纵向行为 | 独立上一页/下一页按钮 |
|---|---|---|
| 单页 | 先页内滚动；到边界后继续滚动翻页 | 切换一页 |
| 双页 | 先组内滚动；到边界后继续滚动翻组 | 切换一组 |
| 连续单页 | 正常连续滚动 | 定位相邻页 |
| 连续双页 | 正常连续滚动 | 定位相邻双页组 |

- 新配置默认开启非连续布局滚轮翻页；保留阅读设置中的开关。已有明确保存的 `false` 不静默覆盖，若旧版本自动保存了 `false` 而无法判断用户意图，开发记录说明如何在设置中启用；可在现有配置规范允许时使用明确的迁移策略，但不重置其他设置。设置应用后应立即作用于已打开的会话，无需重启或重新打开书籍。
- 当前页/组完全可见、没有纵向滚动空间时，普通离散滚轮向下进入下一页/组，向上进入上一页/组。存在页内滚动空间时先正常滚动，达到边界后下一次有效滚动或累计达到合理阈值才翻页。避免一次滚轮或触控板惯性事件连续跨越多个页面。
- 正向翻页定位目标顶部，反向滚轮翻页定位目标底部（若整页可见则自然居中/显示整页）。到达文档首尾时不循环翻页。
- 使用 `PageLayout::spreadPages()` 或等价分组接口计算目标组；不得以当前页加减一代替双页组翻页。例如首页单独时，组顺序为 `[1] → [2,3] → [4,5] ...`（示例为 UI 一基页码）。尾部不配对页按真实页处理。
- 支持 `angleDelta()` 与 `pixelDelta()`，兼顾高精度滚轮和触控板；边界累计状态在方向改变、布局切换、主动导航、文档切换时清理。Ctrl+滚轮缩放、Shift+滚轮横向滚动保持优先级，不误触翻页。
- `PageUp`/`PageDown` 提供明确阅读导航；非连续模式按页/组切换，连续模式按常规视口滚动。笔记编辑及输入控件保持本身键盘行为。
- 普通滚轮与翻页按钮不写入主动导航历史；页码输入、目录、搜索等显式定位仍按历史规则处理。

### 4.4 R04 — 独立翻页按钮与页码输入

目前 `QSpinBox` 向上增加页码、向下减少页码，符合数值控件语义，但与 PDF 阅读中上下方向的翻页直觉冲突；当前左右箭头又属于导航历史，而非普通翻页。

- 隐藏页码输入框内部的增减按钮（可保留 `QSpinBox::NoButtons`），保留数字校验、总页数、回车确认及当前页同步。输入页码始终为一基显示，数据模型继续使用零基索引。无效页码不触发跳转。
- 在页码输入框两侧提供独立上一页/下一页图标按钮，采用左/右箭头或明确的上一页/下一页图标，并配置准确 tooltip；首尾禁用不可用方向。
- 普通翻页使用 R03 的页/组语义；页码输入仍可定位至双页组中的具体一页。历史按钮独立分组并标为“导航后退/前进”。
- 同一翻页动作供工具栏、键盘和滚轮复用，最终通过统一导航接口执行；不复制页索引运算。最终按钮位置见 U01。

### 4.5 R05 — 阅读历史出发位置与分支

**已知问题**：`ReaderWorkspace::onNavigated()` 只记录目标 `(pageIndex, pagePoint)`，首次主动跳转时可能没有出发位置；现有探针先执行两次跳转，没有覆盖该场景。滚轮当前使用 `NavigationReason::PageInput` 也可能误入历史。

- 在主动导航改变当前页或滚动位置之前捕获真实视口锚点；导航成功后捕获目标锚点，保证首次跳转即可后退。建议复用统一 `navigateTo()`，扩展导航事件携带出发/目标位置，或增加相应导航事务；避免各按钮自行实现历史。
- 历史为每个文档会话独立的有限位置序列及当前索引，沿用约 100 条的上限。重复位置去重，无实际跳转不增加历史。
- 正常阅读滚动、普通翻页、缩放、旋转、布局切换、阅读状态恢复及编辑操作不新增条目；下一次显式跳转时以当下真实阅读位置作为出发位置，而不是上一条历史的陈旧坐标。
- 历史回放不重复入栈。后退后发生新的显式导航时截断旧前进分支。若导航前后锚点因滚动发生改变，按实际出发位置更新当前节点或等价地保存跳转边，保持返回路径直观。
- 保留 Alt+Left / Alt+Right 及对应按钮；按钮可用性和历史索引同步。历史只在会话内存在，不增加书库持久化字段。
- 明确导航原因：页码输入/目录/缩略图/书签/搜索/标注列表定位是主动跳转；普通翻页与程序性恢复不是。不要把任何对象选择信号当作导航请求。

### 4.6 R06 — 非连续布局滚动范围与定位稳定性

**已知问题**：`PdfView::navigateTo()` 更改 `PageLayout` 当前页后，在固定缩放模式下未明确更新滚动条范围；不同尺寸页面、双页组或旋转条件下可能继续使用上一布局的范围。

- 非连续模式切换目标页/组后，先完成布局与目标缩放计算，再更新滚动条 range/pageStep，最后依据目标原文位置进行滚动定位。
- 适宽/适页模式在应重新计算的时机保持现有语义；固定缩放不被普通导航改变。避免滚动条信号在中间状态反向更新当前页或触发多次导航。
- 目标页顶部、底部、中心及页内坐标定位应明确区分，不以 `(0,0)` 是否为空作为唯一对齐依据（原点本身是有效位置）。双页组以组边界计算滚动空间，并能精准定位组内具体页面。
- 统一检查 `navigateTo()`、`revealPageRegion()`、布局切换、旋转、视口 resize、阅读状态恢复等路径是否共享必要的状态更新；不重新设计页面坐标系统。
- 保留连续布局中正常滚动及当前页可见面积判定；选择、创建、编辑标注不引发意外导航。

## 5. 里程碑 B：阅读器界面组织优化

### 5.1 总体布局与职责

采用前次讨论的方案 B：分组式紧凑工具栏。保留传统菜单栏、文档标签、多文档工作区及三栏主体，不引入 Ribbon，不照搬参考软件的多层标签工具栏。示意如下（不代表固定像素尺寸）：

### 5.2 U01 — 顶部工具栏重组

**总体设计**：将现有底部阅读控制栏的实际操作迁移到顶部，与标注工具协调组织。复用 `ReaderWorkspace::buildPrimaryToolBar()`、`buildContextToolBar()` 及原底部栏中的已有动作，不再保留一份重复的底部控制栏。不要把书库管理工具混入阅读工具栏。

主工具栏建议按以下从左至右的顺序组织，各组使用分隔线区分：

| 分组 | 内容与表现 |
|---|---|
| 常用操作 | 保存、撤销、重做、删除当前标注 |
| 阅读导航 | 历史后退、前进；上一页、页码输入/总页数、下一页；历史与翻页在组内视觉区分 |
| 缩放 | 缩小、可编辑百分比、放大、适合宽度、适合页面 |
| 页面布局 | 单页、双页、连续阅读开关、首页单独（仅双页适用）、旋转 |
| 选择与标注 | 默认选择、抓手、独立区域选择；文字高亮/下划线/删除线；直线/矩形/椭圆；铅笔/荧光笔/橡皮；定位笔记及已有区域截图入口 |
| 辅助与视图 | 查找、添加书签、左/右面板开关、全屏 |

- 同类工具用分隔线或轻量按钮组组织。优先采用图标、必要的短文本及 tooltip；不要每个工具都使用大块文字按钮。已有图标库不能表达语义时补充同风格图标，不混用系统 emoji 或难以辨识的字符图标。
- 默认选择、抓手及主动绘制工具保持互斥；适宽/适页与布局按钮明确表现当前状态。撤销、重做、翻页、历史前进/后退等可用状态由实际会话同步。
- 保留上下文属性栏，不将所有样式控件塞进主工具栏。根据工具和选中对象显示适用的颜色、线宽、线型、填充、透明度、混合方式及橡皮半径。选择模式未选对象时可保持简短提示或收起无用属性，但不要让阅读区在频繁选中对象时产生明显上下抖动。
- 允许宽窗口下单行显示主工具栏；窄窗口时通过 Qt 工具栏扩展菜单、复合控件收纳或有组织的换行处理溢出。应实际验证嵌入式 `QWidgetAction` 的溢出表现，不能仅缩小字体和图标到不可读，也不能隐藏核心操作而无替代入口。菜单仍提供完整操作。
- 页码、缩放等自定义控件的固定宽度需兼顾大页数、百分比、字体设置和高 DPI；工具栏控件的字号及图标尺寸跟随现有外观机制。
- 不重新实现快捷键或重复连接动作。核查 `MainWindow` 内旧工具栏构建代码、ReaderWorkspace 动作和菜单动作是否重叠；可移除已确认不再使用的旧控件/连接，但不作无关清理。
- 底部主要保留保存状态、错误/操作提示、当前页及总页数、布局、缩放等简洁信息。缓存大小等调试信息如有需要放入诊断输出，不长期占用主要状态空间。

### 5.3 U02 — 页面布局控制方式

将当前四选一下拉框改为两个正交的操作维度：单页/双页（互斥）与连续阅读（独立开关）。内部仍使用现有 `PageLayoutMode`，不修改阅读状态协议。

| 单页/双页 | 连续阅读 | 现有内部模式 |
|---|---|---|
| 单页 | 关闭 | `SinglePage` |
| 单页 | 开启 | `ContinuousSingle` |
| 双页 | 关闭 | `FacingPages` |
| 双页 | 开启 | `ContinuousFacing` |

- 默认布局、每本书上次布局恢复继续有效；读取实际布局反向同步 UI，不因控件初始化触发重复布局切换。
- 双页模式下提供首页单独显示入口，可采用相邻小按钮或双页按钮的下拉选项；单页模式禁用或隐藏入口，但记住该设置。切换连续状态时不改变首页单独设置。
- 每次布局切换只执行一次有效布局更新，并保持当前原文锚点。适宽/适页状态按实际视口重新计算。
- 旋转延续现有视图旋转能力，不修改 PDF 文件和标注几何。所有布局控制与视图菜单共用相同状态。

### 5.4 U03 — 左侧导航栏与自适应缩略图

左侧导航最终为四个标签：**目录、页面、书签、查找**。将现有标注列表迁至右侧。目录及书签功能保留，标签文字过宽时可使用紧凑图标和 tooltip，避免四个标签的最小宽度阻止侧栏缩小。

**侧栏宽度**：建议初始展开宽度 220–260 个逻辑像素、最小展开宽度约 160 个逻辑像素（随字体、DPI、实际控件调整），替换目前 `m_leftTabs->setMinimumWidth(340)` 的刚性限制。检查所有子页面及其布局的 `minimumSizeHint`，确保真正可以拖至单列状态。左右面板均可完全折叠，并有可恢复入口；原有用户设置优先保留，不一律重置。

**缩略图布局**：

- 延续现有 120×158 左右的缩略图目标尺寸和可自动换行的列表模式，根据实际 viewport 可用宽度（扣除滚动条、边距、间距）计算可容纳列数。宽度不足两列时必须切换为单列；单列居中，多列均匀排列。不通过拉伸 PDF 图片充满固定网格。
- 横向、纵向、混合尺寸页面均保持比例，页码及当前页选中状态清晰；支持用户拖动侧栏时动态重排，不重新生成整份文档的缩略图，不丢失选中项或无故滚动到首页。
- 避免全量创建独立占位图像：可共享一个占位资源，或采用惰性列表模型/委托。第一版无需强制迁移整个列表架构，前提是大书籍的初始化和滚动性能合理。
- 缩略图调度依据列表自身的可见页及少量邻近页，而非只依据主阅读区当前页。用户单独滚动缩略图至远处时，实际可见缩略图应及时生成。隐藏页面标签/隐藏面板时不继续大量请求缩略图。
- 区分未请求、请求中、已生成、失效状态，按文档、页码、尺寸及显示旋转条件匹配请求。复用已有 `PageRenderer` 的缓存及 pending 去重，不能以非空占位 icon 当作真实已渲染图像，也不能因完成后移除 pending 而持续重复提交。
- 保持主阅读区当前页与缩略图选中项同步；用户主动浏览远处缩略图时不强制反复抢回当前阅读页，点击缩略图才执行定位。主阅读区实际页码变化时按既有策略同步。
- 旋转或主题改变时按实际需要更新缩略图，不无条件清空所有已生成图像。若保留原始未旋转缓存，可以在显示层重新变换。

涉及 `ReaderWorkspace::buildLeftDock()`、`refreshThumbnails()`、`requestNearbyThumbnails()`、`onThumbnailRendered()` 及 `onPageChanged()` 等入口。U03 解决可用性和按需行为，P02 测量优化效果。

### 5.5 U04 — 查找面板迁移与搜索交互完善

现有 `buildSearchBar()` 将搜索输入与最大高度 130 px 的结果列表一起放在阅读区上方。迁移后，完整搜索功能成为左侧“查找”标签页，顶部工具栏保留打开查找的入口。取消原先占用阅读区垂直空间的搜索结果条，不建立第二套搜索模型。

```text
┌────────────────────────────┐
│ 目录  页面  书签  [查找]     │
├────────────────────────────┤
│ [ 搜索当前 PDF         × ] │
│ 12 / 38 处        ↑  ↓  ×  │
├────────────────────────────┤
│ 第 2 页                     │
│ … peak detection …          │
│ 第 2 页                     │
│ … automatic peak …         │
│ 第 5 页                     │
│ … peak detection …          │
│                            │
│ （结果列表填充剩余高度）      │
└────────────────────────────┘
```

**操作及状态**

- Ctrl+F、菜单和查找工具栏按钮均展开左侧栏并切换至查找页，聚焦并选中输入框文字。重复 Ctrl+F 仍聚焦，不关闭或清空当前查询。
- 保留约 250 ms 防抖输入搜索；明确显示空查询、搜索中（可带当前已发现数量）、搜索完成、无结果等状态。未完成时不得将暂时零结果显示为最终无结果。
- Enter/F3 下一项，Shift+Enter/Shift+F3 上一项；点击结果或使用快捷键时准确定位原文，列表选中项与序号保持一致。首次查找完成默认选择第一项，避免首次 Enter 意外跳过第一项（若已自动定位第一项，则 Enter 正常进入第二项）。输入框以外的快捷键不得干扰笔记编辑和其他文本控件。
- 搜索结果列表显示页码、匹配关键词及前后文，可换行或截断并提供完整 tooltip。避免当前实现仅连接前后文而导致匹配关键词本身缺失；根据实际 Qt PDF 数据构造摘要。
- 切换目录、页面、书签标签或隐藏侧栏时，保留当前搜索会话及临时高亮；显式清除/关闭查找或相应 Esc 行为才清除结果和高亮。明确关闭后回到上一导航标签（无可用记录时回到目录或页面）。关闭时停止防抖计时器、清理查询并隔离迟到结果，重新打开不出现旧查询与新结果混杂。
- 各文档使用独立 `QPdfSearchModel` 与查询状态；切换标签不重置其他文档搜索，也不将查询持久化到书库。
- 无文字层扫描件仍仅支持已有文字层搜索；无匹配时正常提示，不引入 OCR，不将无结果等同于文件必然无文字层。

**结果绘制及性能**

- 保持搜索高亮独立临时层，不纳入标注 JSON、撤销栈、对象命中或区域截图。普通匹配与当前匹配使用明确不同的显示方式；当前匹配可能包含多个矩形，全部应标识为当前结果。
- 当前 `refreshSearchResults()` 调用 `setSearchHighlights(highlights, -1, QRectF())`，而 `activateSearchResult()` 未更新当前结果高亮。修复此状态流；追加结果时不得将用户正在查看的结果重置为第一项或普通高亮。
- 当前结果列表最多构造 4000 项但显示模型全量计数。优先使用模型或增量更新支持全部匹配；若仍保留数量上限，应明确显示已展示数和总数，导航范围及高亮范围保持一致，不静默截断。
- 避免 `countChanged` 每次触发全量清空重建列表及所有高亮，优先增量更新或合理合并刷新。切换查询时及时清理上一代结果，严格检查文档与查询状态。点击、双击或 activated 信号不得重复记录同一次导航。

### 5.6 U05 — 右侧标注列表与笔记联动

右侧设置三个标签：**标注、笔记、详情**，首次打开文档默认展示标注页。标注列表迁移后保留现有 `AnnotationModel`、`NotePanel`、属性控件和数据保存逻辑，不创建另一份标注数据源。

```text
┌──────────────────────────────┐
│ [标注]  笔记  详情             │
├──────────────────────────────┤
│ 全部类型 ▾   排序 ▾   仅有笔记  │
│ 共 6 项标注                    │
├──────────────────────────────┤
│ [类型图标] 文本高亮       P2   │
│   The problem with most …     │
│ [类型图标] 矩形           P2   │
│ [类型图标] 荧光笔         P3   │
│ [笔记图标] 算法的适用条件 P3   │
│   对于准周期信号的适用范围…    │
│                              │
├───────── 可调整分隔线 ────────┤
│ 选中标注                      │
│ 矩形 · 第 2 页                │
│ 尚未添加笔记                  │
│ [添加笔记] [查看详情] [删除]    │
└──────────────────────────────┘
```

**列表及预览**

- 保留已有类型筛选、“仅有笔记”筛选、颜色提示及当前选中状态。类型图标采用 Lucide 或现有同风格图标，结合样式颜色区分类型；不只依靠颜色或单一圆点识别对象。
- 默认按创建顺序（先创建在前），支持页码顺序、最近修改顺序。页码相同时以创建顺序/稳定 ID 作稳定排序。排序仅作用于视图，不改变 `annotations.json` 的组织顺序、对象叠放关系或产生数据修改。
- 文字标注显示简短原文摘录；有笔记时优先显示笔记标题及适当摘要；图形和自由笔迹显示类型及页码，不强制为每个图形生成截图。列表项提供准确的页码、类型及更多操作入口。
- “附着笔记”类型筛选应准确表达实际的定位笔记类型；不要与“仅有笔记”混淆，后者适用于任何标注类型，只要确实包含笔记内容。
- 标注页下方提供轻量选中对象预览/操作区域，可采用垂直 `QSplitter` 或等价布局。显示基本类型、页码、原文或笔记摘要，并提供定位、添加/编辑笔记、查看详情及删除入口；无选中对象时提示选择，不显示过多空字段。完整属性在现有上下文属性栏和详情页，完整 Markdown 编辑仍在笔记页，不重复实现编辑器。空间不足时允许收起预览。
- 列表右键菜单或更多操作复用已有对象操作，特别是删除保护、笔记编辑及复制操作。删除带笔记对象继续遵循确认与保护规则。

**联动行为**

| 操作 | PDF 阅读区 | 右侧面板 |
|---|---|---|
| 点击 PDF 中的标注 | 保持原阅读位置 | 同步选中 ID，更新预览/详情 |
| 用户点击列表项 | 精确定位标注所在位置 | 选中并显示预览 |
| 双击列表项 | 定位一次 | 进入现有笔记查看/编辑入口 |
| 创建新标注 | 不发生跳转 | 更新列表并同步选中 |
| 修改位置、形状或样式 | 保持当前位置 | 更新对应项及详情 |
| 删除标注 | 保持当前位置 | 清除该项及失效选择 |
| 滚动阅读 | 更新当前页 | 不无故改变对象选择 |
| 筛选隐藏当前选中项 | 不改变阅读区选择 | 明确当前项未显示，避免假选中 |

- 使用标注 ID 作为 UI 联动键，不能使用列表行号索引模型。程序性同步选中与用户主动定位分离，保留前几轮消除异常跳转的成果。列表刷新及排序不得触发导航。
- 创建普通标注不自动切换到笔记页；明确点击添加/编辑笔记、定位笔记工具或双击等用户操作才切换。用户已在笔记编辑时，切换对象/文档之前先按现有机制提交或处理未保存内容；不要因列表刷新覆盖编辑中的笔记。
- 保留现有右侧笔记与详情页面，并使其与当前选择联动。切换面板标签不修改标注数据。不要提前开发笔记树、分组节点、跨书知识关系或新的 Markdown 存储形式。

### 5.7 U06 — 全屏界面及面板控制

- 正常阅读模式下，顶部辅助与视图组提供左侧栏、右侧栏开关；图标明确显示展开/折叠状态，折叠后仍可恢复。保留用户调整的非零宽度，不将隐藏时的零宽度覆盖原配置。
- 全屏默认仅显示阅读画布，右上角提供独立的退出全屏按钮，建议使用轻量覆盖层、始终可点击且不改变 PageLayout。若采用自动隐藏，必须具有稳定的鼠标唤出热区，并验证真实使用可发现；首选始终可见的小型退出入口。底部不强制保留完整工具栏，可按需要提供轻量翻页浮层，但不是本阶段硬性新增功能。
- 全屏临时隐藏搜索、浮动操作及左右面板时，保留应恢复的正常界面状态。退出时按 R01 恢复，不意外重置查询或选中对象；未提交编辑按统一取消/保存规则处理。
- 正常界面中的菜单、文档标签、上下文属性栏、状态栏等可见性与用户设置一致；退出全屏后图标、checked 值和实际窗口状态一致。

## 6. 里程碑 C：性能诊断与低风险优化

### 6.1 P01 — 完整应用层打开性能诊断

用户在打开较大的扫描书籍时观察到约 1–2 s 短暂卡顿，较小缩放比例、连续布局下尤其明显。本轮 Windows 测试仍存在性能问题。Phase 2 的 `pano-pdf-timing` 在 Linux 上得到以下结果：

| 样本 | 文件大小（字节） | 页数 | PDF load | 页面几何 | 首页渲染 |
|---|---:|---:|---:|---:|---:|
| `examples/sample-paper.pdf` | 126396 | 3 | 1 ms | 0 ms | 9 ms |
| `algorithms-05-00588.pdf` | 3878142 | 16 | 2 ms | 3 ms | 31 ms |
| `Primer C++(第5版).pdf` | 207962233 | 864 | 5 ms | 104 ms | 47 ms |

以上仅为已有开发记录中独立 Qt PDF 探针的测试值，不代表 Windows 应用完整打开耗时，不能排除 PDF 引擎在并发渲染、缩略图竞争或主线程等待条件下的影响。

**当前最值得优先验证的路径**：`MainWindow::openBook()` 同步执行 `DocumentSession::load()` 后才挂载阅读标签。`load()` 每次调用 `LibraryManager::verifySource()`，后者重新读取整个 PDF 计算 SHA-256。约 200 MB 源文件的完整哈希是在普通打开路径上实际存在的工作，并非仅在首次导入时执行。另有全量页尺寸读取、反复布局初始化、全量缩略图占位创建等可能开销。现阶段尚无实测证据证明哪一项是主要瓶颈。

**测量要求**

使用现有日志设施或轻量 `QElapsedTimer` 埋点，以一次打开操作为单位记录至少以下节点。若多个环节异步或交叠，区分累计耗时与各环节独立耗时，不简单相加。

| 阶段 | 应记录的内容 |
|---|---|
| 请求开始 | 打开来源、文档页数/大小（可在获得时补记）、运行环境 |
| 路径及源文件校验 | 文件读取、SHA-256、校验结果及耗时 |
| 文档加载 | PDF load 及页面尺寸获取耗时 |
| 会话数据 | 标注/书签/阅读状态加载及解析耗时 |
| 布局与缩放 | 布局计算次数、耗时，阅读状态恢复前后的缩放及视口 |
| 导航 UI 初始化 | 目录、缩略图占位、搜索模型及侧栏构建耗时 |
| 标签显示 | 工作区加入标签并实际呈现/处理事件的时间 |
| 首屏渲染 | 第一张真实页面完成并绘制的时间、初始可见页渲染基本完成的时间 |
| 渲染队列 | 主页面及缩略图请求数量、重复/过期请求数量、缓存情况 |
| 界面响应 | 主线程最长可观察阻塞/事件循环延迟，不将异步渲染总时长等同于卡顿 |

- 区分首次导入（可包含文件拷贝、哈希、封面生成）、已导入书籍普通打开、关闭标签后重新打开，以及已打开标签切换。不要把仅切换已有会话与重新加载 PDF 的耗时混在一起。
- 使用两份指定 PDF 对照，重点在大型扫描书籍上测量连续布局的小缩放比例与常规适页/适宽场景；同时记录侧栏是否展开、缩略图页是否激活、文件所在磁盘、OS/Qt 版本。可在同一环境重复约 3 次以观察首次与热缓存差别，不要求进行复杂统计或清空操作系统缓存。
- 优先在修改前记录基线，修改后在相同条件下复测。若有 Windows 环境，优先测量用户出现卡顿的平台；若只有 Linux，不把 Linux 测量当作 Windows 缺陷已消除。
- 实际 GUI 打开必须包含从用户操作到首屏显示的过程，而不是只运行非 GUI 的 `pano-pdf-timing`。埋点可作为调试开关或诊断日志保留，不在正常界面长期显示大量技术细节。

### 6.2 P02 — 按证据进行低风险优化

优先考虑以下措施，不要求无条件全部执行：

1. **文件校验响应性**：若完整哈希为主要开销，优先将纯文件读取与哈希计算移出 GUI 线程，提供可理解的“正在校验/打开书籍”反馈，避免重复发起同一书籍打开。不得从工作线程访问 GUI 或未经确认线程安全的 PDF 对象。取消、关闭、切换书库时处理任务生命周期，校验失败或源文件变化不得绑定旧标注。完整校验通过之前不进入可编辑会话。若暂时保留同步校验，应记录原因及耗时。文件大小/修改时间等仅可作为变化检测或诊断线索，不作为严格 SHA-256 内容身份的等价证明；本阶段不默认引入降低校验强度的快路径。
2. **缩略图初始化**：落实 U03 的共享占位和可见范围调度，隐藏标签时不批量发起请求。仅在确有性能收益时进一步采用惰性模型/委托。注意当前缓存已具有一定去重能力，不重复维护两套缓存。
3. **布局初始化**：检查 `PdfView::openFile()` 与阅读状态恢复之间的多次 `setPages`、`setViewportSize`、`setZoom`、`fitPage` 等调用，合并可以安全合并的中间布局刷新；视口未获得最终尺寸时不要大量提交无效尺寸渲染请求。保持首次显示及旧状态恢复准确。
4. **渲染请求**：优先当前可见主页面，适量预取邻近页面，缩略图作为较低优先级任务。检查 `PageRenderer` 的缓存 key、pending 去重和过期结果过滤；快速缩放、滚动、布局切换、关闭文档时不要让过期结果影响当前显示。Qt PDF 若无法取消已提交渲染，可限制提交量和忽略过期结果，不假设底层具有任意取消能力。
5. **绘制开销**：若测量表明遍历全部页或标注、频繁重绘等是热点，再考虑可见页索引或更细粒度的刷新；不先行增加复杂空间索引、GPU 渲染、多级磁盘缓存或重写 PDF 后端。

**性能任务完成边界**：至少报告完整打开路径中的主要耗时及可观察阻塞。如果低风险措施能改善，则给出前后对比；若尚未解决，应说明剩余瓶颈、已尝试方案、实际限制及下一阶段可独立研究的内容。不得以单独 PDF 加载探针通过、使用更小文件或更换默认布局替代问题修复。性能仍存在不阻塞其他 Phase 2.1 功能收尾，但必须明确标记为遗留问题。

   - V01–V32 各验收场景的通过、部分通过、未验证或失败状态，明确区分自动化、离屏和真实桌面测试；
   - 至少展示顶部综合工具栏及三栏布局、缩略图窄宽变化、左侧查找、右侧标注与全屏退出的代表性视觉结果；截图数量以能够说明问题为准；
   - 大型 PDF 的普通打开与首屏耗时、关键阶段测量、优化前后对比或保留问题；
   - 持续测试书库的实际使用情况、已新增测试内容、保护措施及遗留限制。
4. 提交信息简洁明确，采用项目既有提交规则，如 `fix: stabilize reader interactions and refine layout`。不提交本地书库、用户 PDF 或临时性能文件。不要为交付额外创建大量开发过程记录。

## 12. 阶段完成判定

- R01–R06 的用户可见缺陷得到修复，核心入口能够通过实际按钮、键盘或鼠标执行，不仅依赖内部函数探针通过。
- U01–U06 的界面职责调整完成：顶部集中操作、左侧组织原文导航、右侧组织阅读成果、底部主要显示状态。缩略图单列/多列自适应、查找面板、标注默认窗格及全屏退出均可正常使用。
- 四种布局、缩放、原文锚点、既有标注及笔记、书签、剪贴板和右键操作不发生明显回归，持续测试书库数据安全。
- P01 取得完整 GUI 打开流程的诊断结果或明确记录测量阻塞；P02 依据测量实施适当优化。大型 PDF 卡顿未完全消除时允许延期，但必须留下可复现条件、测量数据和后续建议，不虚报已修复。
- 完成可用平台上的构建、针对性回归及实际视觉检查；无法执行的测试明确列出，不以未验证状态冒充通过。

完成本阶段后，除严重缺陷和必要性能工作外，原则上不再继续扩充 PDF 阅读器功能，下一阶段转入 Phase 3 — 专业笔记系统。是否在 Phase 3 前插入独立性能优化阶段，由本轮实际诊断结果决定。
